# 基线方案

更新日期：2026-10-24。对象是[问题定义 v4](problem-definition.md) 的查询问题：轨迹 $T=(X,\tau,E,\beta)$，查询 $Q=(\mathbf q_{1..m};\tau_{1..m};W;R;\delta_\Delta;k)$，返回每轨迹最佳可行 episode 的全局 top-k。

本文只规定**比较什么、怎么保证公平、报告什么**；不写某个基线的实现细节。

## 1. 比较原则

1. **同一问题**：所有基线必须返回连续段区间 $[u,v]$、满足 §4 全部硬约束、轨迹不重复、$|\widehat R|\le k$。放松任一约束的变体只能标为“上界参考”，不得与同问题方法同表比较。
2. **同一距离**：相同的 $\beta$、相同的段向量、相同的 $\lambda$ 与 $D/m$。禁止某基线用欧氏点距离、另一基线用 DTW。
3. **同一查询集与 oracle**：固定随机种子；同一批查询、同一 $k$、同一 oracle。
4. **同一调参预算**：每个近似基线允许同等人数的参数组合；报告“达到 Recall@10 ≥ 0.95 的最小延迟”与完整 Pareto 前沿，而不是只挑最好点。
5. **成本口径**：至少报告候选轨迹数、DTW 次数、段向量距离计算次数、构建时间与索引字节；只报 QPS 不足以说明方法差异。

## 2. 共同评测契约

| 项 | 规定 |
|---|---|
| 数据 | Massive-STEPS 用户级轨迹（6 城）；主实验 Istanbul 或 6 城合并，NY 作小规模调试 |
| 查询 | 从真实签到序列采样的语义 episode，$m\in[3,6]$；时间窗 1 天/1 周/1 月/1 季；$R\in\{\text{无},50\text{km},5\text{km}\}$ |
| 查询数 | 主表 500；扩展 1,000；同分布分层（按时间窗与城市） |
| $k$ | 10 |
| $\delta_\Delta$ | $\max(30\text{min},25\%)$ |
| 段划分 | 主实验：每次签到一段（$s$ = 签到数）；对照：停留/移动分段 |
| 距离 | $\lambda=0$ 为主，$\lambda>0$ 作敏感性 |
| 精确结果 | oracle：枚举全部可行 $[u,v]$，逐轨迹取最小 $D_{\mathrm{norm}}$，再全局 top-k |
| 召回 | 轨迹级 $\mathrm{Recall@}k=\lvert\widehat R\cap R^*\rvert/\lvert R^*\rvert$，$\lvert R^*\rvert<k$ 时分母用 $\lvert R^*\rvert$ |
| 约束违规 | 返回结果中不满足硬约束的条数，必须为 0；非 0 直接判该运行无效 |
| 延迟 | 单线程、热缓存、每查询 3 次取中位数；报告 p50/p95 |
| 报告 | 每基线一行：qps、Recall@10、p95、候选轨迹数、DTW 次数、索引字节、构建时间 |

## 3. 精确基线（同问题）

### E0 — Oracle（离线，只用于标签）

枚举每条轨迹的所有 $[u,v]$，过滤硬约束，算 $D_{\mathrm{norm}}$，取每轨迹最优，再全局 top-k。复杂度 $O(Nms^3d)$，只在小数据或采样轨迹子集上跑；用于生成 $R^*$ 与 episode 最佳区间。

### E1 — 硬过滤 + 全扫描

先按 $W$、$R$、$\delta_\Delta$ 过滤轨迹与段区间，再对剩余候选逐区间算 DTW。

- 作用：证明“索引是否必要”的下界；也是所有近似方法的候选上限参照。
- 关键数字：过滤后候选轨迹数、候选区间数、DTW 次数随窗口宽度的变化。
- 预期：1 天窗很快；1 年窗接近全扫描。

### E2 — 硬过滤 + 段级下界剪枝

对段向量建轻量 sketch（段均值/范数范围/首段末段），导出 DTW 下界，跳过不可能进入 top-k 的区间。

- 作用：同问题的最强**精确**基线。若近似方法打不过它，说明近似没有价值。
- 需证明下界正确性（不漏解），并在小规模上与 E0 对拍。
- 报告：剪枝率、下界紧致度、验证次数。

## 4. 近似基线（同问题）

所有近似方法只放宽**候选生成**，验证阶段必须是精确的（精确算 $D_{\mathrm{norm}}$ 并检查硬约束）。

### A1 — 点级 ANN + episode 验证（当前基线）

把段向量建 HNSW；查询向量逐个检索，按轨迹聚合候选，再在候选轨迹内枚举可行区间算 DTW。

- 来源：本项目 2026-10-22 的 `city+quarter HNSW + verify`。
- 已知结果（6 城、1 年窗、50 km）：93.25 qps、Recall@10 0.9522、p95 24.5 ms。
- 公平性注意：它是点级召回，不利用序列结构；作为“朴素强基线”，不是同问题最优解。

### A2 — 整轨迹表示 ANN + 验证

把每条轨迹压成一个向量（段向量均值或 GRU/Transformer 编码），ANN 取 top-$n$ 轨迹，再逐轨迹求最佳可行 episode。

- 作用：检验“整轨迹表示是否够用”。若够用，说明 episode 结构不必要。
- 预期：时长差异与多活动混合会让均值表示失真；需要报告召回随 $n$ 的曲线。

### A3 — TRSSQ 式学习过滤（RSSE 适配）

按 TRSSQ（ICDE 2024）的 filter-validate：学习模型对（查询, 轨迹）打分取 top-$M$，再在候选内做精确代表片段搜索。

- 适配点：原方法在原始点上做，本问题在段上做；输入换成段向量序列。
- 风险：RSSE 无公开代码，需重训；训练集/查询分布必须与评测隔离。
- 作用：检验“学习型候选过滤”相对手工 ANN 的收益。
- 若重训成本过高，退化为 A3′：用查询-轨迹相似度代理（如最佳单段距离）排序取 top-$M$，明确标注为“学习过滤的代理”。

### A4 — GTRSS 式图索引

按 GTRSS（arXiv 2025）构造轨迹级双层图：节点为轨迹，边权为“两轨迹代表片段的相关性”，查询时图上导航取候选。

- 适配点：边权需换成段向量距离；原方法无时间/空间硬约束，本问题需在图上加过滤。
- 风险：无公开代码；建图成本高；只作为“图索引是否优于点级 ANN”的对照。
- 若实现不完整，只报告候选召回与建图成本，不报端到端延迟。

### A5 — 分区 + ANN

按城市/季度（或网格/H3）分区，查询只在相关分区内检索。

- 来源：当前最好的工程配置。
- 作用：检验“结构信号来自分区还是来自序列”。
- 与 A1 的组合关系要写清：A5 是 A1 的预过滤，不是独立算法。

### A6 — 标签倒排 + 验证

按段的主类别建倒排，取与查询类别重叠的轨迹，再验证。

- 作用：检验“精确标签匹配是否已足够”。
- 已知：2026-10-22 报告 Recall 0.852、延迟降 39%，是“过滤太硬”的失败模式样本。

## 5. 上界/邻近参考（不得与同问题方法同表）

| 编号 | 方法 | 放松了什么 | 用途 |
|---|---|---|---|
| U1 | ETQ-embedding | 不要求连续段、无时间可行性 | 语义 top-k 的上界：说明连续性约束的代价 |
| U2 | TISIS*-LCSS | 整轨迹、阈值集合、非 top-k | 语义序列匹配的上界 |
| U3 | TRSSQ 原版（点级） | 无时间/空间/时长约束 | 代表片段检索的上界 |
| U4 | Quantum Range Query 式 range reporting | 不做相似度排序 | 只说明时空范围访问的下界成本 |

这些结果只能写在“差距分析”一节，并明确标注放松了哪些约束。

## 6. 消融与敏感性

| 维度 | 取值 | 目的 |
|---|---|---|
| 时间窗 | 1d / 1w / 1m / 1q | 选择性对候选规模的影响 |
| 空间范围 | 无 / 50km / 5km | 空间分区的收益 |
| 时长容差 | 0 / ±25% / ±50% | 硬约束强度 |
| $m$ | 3 / 4 / 6 | 查询长度对 DTW 与召回的影响 |
| 划分 | 签到段（$s$=签到数）/ 停留-移动段 | 分段粒度的影响 |
| $\lambda$ | 0 / 0.1 / 0.5 | 时间轮廓项的收益 |
| 候选预算 | top-$n$ ∈ {50,100,300,600,1250} | 召回-延迟前沿 |

## 7. 诊断指标（回答“为什么输/赢”）

- **候选覆盖**：oracle 的 top-k 轨迹中，有多少进入候选集（candidate recall）。低于 1 时，延迟差异无意义。
- **候选规模 vs 选择性**：时间窗/空间范围过滤后剩余轨迹数与区间数。
- **DTW 调用数**与**每轨迹枚举区间数**：区分“候选少”与“剪枝强”。
- **尾部查询**：Recall 最低的 5% 查询，记录其 $m$、窗口宽度、城市与候选数。
- **约束违规**：任何非 0 都视为实现错误，不是精度问题。
- **构建成本**：建索引时间、索引字节、是否需要 GPU 训练。

## 8. 实施顺序

1. **E0 + E1**：先把 oracle 与全扫描跑通，确认约束与 $D/m$ 实现一致；在小数据上与暴力实现逐条对拍。
2. **A1 + A5**：复用现有代码，得到当前基线数字。
3. **E2**：实现段级下界剪枝，并与 E0 对拍（必须不漏解）。
4. **A2 + A6**：整轨迹表示与标签倒排，确认“粗表示是否够用”。
5. **A3/A4**：学习过滤与图索引，按可用代码决定做到端到端还是只报候选召回。
6. **U1–U4**：差距分析，标明放松项。

每步完成后更新本文的“实测状态”一节；未跑的不写数字。

## 10. 风险与边界

1. **TRSSQ/GTRSS 无公开代码**：A3/A4 是适配而非原系统复现；论文中必须写“adapted”，不能声称复现作者结果。
2. **学习过滤的训练泄漏**：A3 的训练查询必须与评测查询按用户/时间隔离。
3. **oracle 成本**：全库枚举不可行时，只在采样子集上算 oracle，并在论文中说明子集构造。
4. **段划分影响**：不同 $s$ 会让所有方法一起变化；主表固定一种划分，敏感性表另列。
5. **近似只放宽候选**：任何“放宽硬约束换速度”的做法都必须单独标注，不能混入同问题结果。
6. **不能据此宣称 SOTA**：本文只定义比较方案；没有运行结果前不写任何胜负结论。
