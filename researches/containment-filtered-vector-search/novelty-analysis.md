# 前缀属性约束向量检索的创新性复核

日期：2026-10-19（Asia/Shanghai）。以[当前规范定义](problem-definition.md)为准，覆盖单路径、静态数据、向量top-k与硬前缀合法性。依据已读原文、作者代码及本轮有限同义检索；尚未完成全领域引用闭包，没有新算法性能结果。

## 结论

**查询问题本身不能作为新增贡献。** Directory-Aware的recursive DSQ在固定单路径命名空间下与本问题合格集合一致；前缀展开能转成单标签过滤；静态DFS还能转成一维区间过滤。

**已有结构性质是研究依据，不是已成立的算法创新。** Trie、子树bitmap、前缀嵌套、LCP判定、共享结构和局部自适应均有直接前序或基本推导约束。当前没有充分证据把F1–F10写成十项独立创新。

**保留一个主候选：固定总字节下的前缀共享导航结构。** 它需要在相同scope与召回条件下，证明前缀受限查询族能支持比“TrieHI+先进过滤ANN”和“DFS+范围ANN”更有效的邻接/入口组织。实现、收益和新颖性均未验证；先测强基线瓶颈，再决定是否设计新索引。

## 为什么层状结构仍可能有价值

通用过滤接受任意谓词集合，一般区间索引接受任意区间；我们的静态合法范围只来自一个已知Trie，是彼此嵌套或互斥的受限区间族。这提供跨前缀共享成员、入口与边的机会。

但一般范围方法本来就使用segment-tree/elemental-graph共享，Curator也共享几何分区。因此“受限查询族更简单”只是可利用的条件，不能直接推出更低空间或更快搜索。需要明确减少了哪些已有开销，并验证没有损失宽前缀的几何多样性、深前缀的导航或构建公平性。

还必须拆开“属性范围结构”与“几何搜索结构”：一个前缀可由一个语义节点表示，不代表一个向量入口就能覆盖其多模态几何分布；范围集合能压缩，也不保证找到最近对象更快。

## 主候选 RQ-P：前缀共享导航在固定预算下是否有额外收益

**问题。** 对已知前缀Trie的静态单路径数据，是否能以共享的邻接/入口组织，在固定总字节和相同最终Recall@k下，减少现有scope+过滤图及DFS范围图的边扫描、距离计算和端到端延迟？

**不足与差异。** TrieHI主要优化scope层，PathSeer主要优化通用谓词邻居顺序，iRangeGraph处理一般数值区间。本候选仅尝试利用受限层状查询族组织真正不同的物理导航信息；这些方法的不同定位不能当成已证明的性能缺陷。

**候选机制范围。** 可在一个共享数据对象图上，按边适用的前缀深度保留邻居，再在不同前缀查询中复用物理边；为需要跨几何分支的前缀提供有限入口/桥。F2/F3/F7/F8/F9归并为这一个设计方向，当前还没有固定完整构图和预算分配算法。只存一条边的LCP深度但保持所有扫描不变，不应声称已实现导航改进。

设边 $u\to v$ 的公共前缀深度 $h_{uv}=|\operatorname{LCP}(s_u,s_v)|$。在源u已合格时，目的合格等价于 $|p|\le h_{uv}$。源u不合格时必须直接判断 $p\preceq s_v$；AX→ABC、查询AB的反例说明无条件套LCP会错。该性质是正确性约束，不是新颖性证据。额外深度/分块/入口引用字节须计入B，不能把它们当免费。

**可检验假设。** 在路径深度不均、查询覆盖多种前缀范围且合法邻居随范围明显变化的数据上，合法范围相关的共享邻接组织能减少无效扫描；净收益超过附加元数据、预处理与入口成本。若普通过滤图或DFS范围图已表现相同，该假设被否定。

**预期贡献的证据门槛。** 至少给出一个清晰、可实现的邻接/入口构建规则，说明其与Filtered-DiskANN/Packing/UNG/LSSG/iRangeGraph的差别；证明谓词判定及共享表示正确；若声称复杂度改善，给明确假设与界；再做同字节/同召回的独立实验。目前这些证据尚未齐备，因此不能写成已成立贡献。

## 支撑组件而非并列新意

- F1/F6/F10归入表示优化：LCP/采样终止路径计数可能压缩计算或扩散表示，但应先在完全相同候选、样本和规则下核对等价。它们可以是工程贡献候选，不自动成为独立检索算法。
- F5是语义/几何局部交集的另一实现方向，必须和Curator延迟视图及TrieHI bitmap同接口比较；本轮不同时推进两套全新导航体系。
- F4是选择性物化的受限代理模型，需要树覆盖/物化视图文献继续排查。若选择此方向，应单独立项，不与共享图贡献混为一个最优性声明。

## 强基线与公平组合

| 对照 | 应排除的弱化方式 |
|---|---|
| TrieHI/PE-Offline + 相同过滤执行器 | 不把TrieHI实现成只能全局top-L后过滤；不忽略读取/转换scope和bitmap准备 |
| 相同scope + ACORN/PathSeer/过滤HNSW | 固定版本；原论文与产品实现分开；PathSeer重做对应谓词成本的profile |
| 完整前缀singleton + 标签方法/ELI | 使用最深完整前缀查询，避免冗余祖先AND故意改变导航；ELI覆盖路由另保留所需祖先信息 |
| 静态DFS + iRangeGraph等范围方法 | 包含内部节点对象和编码成本，不能只比较范围扫描；静态序号不冒充动态MOVE零成本 |
| Curator共享几何视图 | 尊重其已有延迟构建能力，统计外部ID生成与视图成本 |
| 精确过滤扫描 | 小scope允许所有方案公平回退，不把扫描回退只留给本方案 |

组件适配实验统一hnswlib以隔离差异；ACORN/PathSeer/iRangeGraph原作者后端若另跑，应单列版本和后端，不声称切换库后的性能差是前缀机制收益。PathSeer原生融合索引不能由普通HNSW简单替代后冒称复现。初步强基线筛选后保留最相关对照，但排除任何基线应记录理由。

## 最小实验与停止条件

**阶段A：先验证是否存在值得解决的瓶颈。** 使用固定10K–50K向量与明确标为合成的单路径树，构造等深/变深、平衡/倾斜、向量相关/独立/交叉的数据。以相同向量查询跨多种前缀深度取scope，保留空/不足k；WIKI-Dir只在下载许可核查后用于真实数据外部验证。避免把人为构造的最坏情形当普遍业务分布。

固定ANN先测scope，再固定scope测过滤导航。至少报告向量、图、bitmap、Trie、入口等全部字节，构建/离线profile，scope/入口/搜索/排序分段时间，visited、边扫描、过滤次数、距离数、QPS/平均/P95、逐查询Recall@k和Fill、过滤违规。对齐距离归一化、k、精度、线程、查询集合、种子、调参预算和冷热缓存。

**阶段B：只加入一个组件。** 先等价的表示替换，再加入邻接/入口布局，最后才重新调度预算。对每步分别做消融与相同总内存对照；假如为新元数据腾空间而减少图边，应把该影响保留。不能把profile测试集泄漏或额外入口数量当作新结构收益。

**不继续立项的条件。** 若预先bitmap后过滤已经足够便宜、端到端时间主要由共同距离内核决定、现有范围图已覆盖受限前缀族、或同字节下新方法只在人工极端场景有利，就应终止/收缩导航方向。若仅有等价表示压缩的可重复收益，可按有限工程优化表述，而不是宣称新问题或全新搜索范式。

## 本轮检索与证据限制

先查总论文/关系索引与十篇笔记，再检索vector similarity join/vector join、similarity self-join/high-dimensional similarity join/inner-product similarity join与prefix/hierarchy变体，随后查prefix-filtered ANN、hierarchical filters、directory-scoped vector search、laminar filters、subtree ANN和iRangeGraph。本轮重新命中Directory-Aware与iRangeGraph原始arXiv/作者仓库，未取得足以建立另一项原生前缀新算法的新增全文。未将无关字符串“prefix”、数据库内部索引列前缀或AI生成综述内容当作直接证据。

该结果不是“没有相关工作”的证明。还缺树/层状过滤图、受限区间族、层级租户索引、物化视图/入口选择的完整前后向引用，以及UniFilter/UNG原文。新颖性尚未充分排查；本轮无算法性能实验。

## 可用于当前研究提案的表述

> 本研究面向单路径前缀约束下的近似向量top-k检索。该查询可由目录范围索引、单标签展开或区间过滤实现。我们拟研究前缀可行集合的层状结构是否支持更紧凑、有效的共享导航表示，并在相同内存与检索质量下，与原生目录范围解析、现代过滤图及范围专用图进行比较。

上述是研究目标，不是已经提出算法或获得加速的论文摘要。原始问题定义可以保留，但后续投稿的新意必须落到经过证据支持的方法或理论增量。
