# 第二篇 Packing 与前缀感知边预算

论文：[Tag-Filtered Approximate Nearest Neighbor Search](https://miaoqiao.github.io/paper/ICDE25.pdf)，Jiarui Luo、Miao Qiao、Chaoji Zuo、Dong Deng，ICDE 2025，3642–3654，DOI [10.1109/ICDE65448.2025.00272](https://doi.org/10.1109/ICDE65448.2025.00272)。本轮沿用已保存的作者 13 页稿，核对 §I、§III–V 与 Algorithm 2/3/6/7；核查日期 2026-10-19。原文 PDF 已在本地，网页正文工具因文件尺寸限制无法重新解析，不影响本地原文核对。

与[第一篇 Filtered-DiskANN](01-filtered-diskann.md)衔接：标签感知剪枝仍会受有限出度限制。此篇进一步问，各标签应该得到多少导航边，才能兼顾中低频标签的搜索效果与索引空间？Packing 是论文的第三个方案，不是独立论文名。

## 原方案的瓶颈是什么

假设对象 a 同时具有常见标签 A 和中频标签 B。其几何近邻大部分仅属于 A，全局最近的有限个邻居可能全部不属于 B；于是查询 B 时，a 的可用出边很少甚至为零。Filtered/Stitched Vamana 的标签感知剪枝不能在固定出度下自动为每个标签留下足够导航边。

为所有标签各建完整独立图虽然能避免部分竞争，却会增加成员与索引重复。TFANNS 论文将边当作有限资源，试图在搜索效果和内存之间取得折中，尤其照顾中低频标签，而不是简单增加所有节点最大度。

## Local Global 与 Packing 的区别


| 方案           | 预算作用范围         | 机制与动机                                                                                                           |
| ---------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Local（§III） | 单个对象的最大出度 M | 根据该对象各标签的频率分配边预算；避免所有槽位都被常见标签占用                                                       |
|                |                      |                                                                                                                      |
| Global（§IV） | 各标签对应的索引结构 | 按标签分配资源，缓解单节点标签数过多的问题；额外涉及频率变化和重建                                                   |
| Packing（§V） | 一组对象组成的 pack  | 块内共享预算，让标签少、需求少的对象让出部分度资源；将高频标签归为 mask tag 计算资源分配，减少预算被高频标签反复消耗 |

这里的 pack 是若干数据对象组成的块，不是前缀树节点，也不是将向量做量化或把路径合并。Packing 允许节点资源不同于固定逐点配额；比较时应对齐总边量/实际字节，不能只比较相同的名义 M。

### 为什么使用对数频率

记标签频率为 $f(t)=|\mathcal D_t|$，小于阈值 $\theta$ 的标签可以采用扫描。Local 对参与索引的标签使用约为

$$
m_a(t)\propto\log f(t)

$$

的出度分配（Algorithm 2 含取整和节点总预算）。直接按 $f(t)$ 分配会使大标签吞掉绝大多数预算；对数压缩差距，让中低频标签相对获得更多资源。**这不表示越稀有绝对分配越多，也不证明取整后每个标签必有一条边。** §VI 的对数、平方根、线性分配对比是实验依据，而非普适最优性定理。

Packing 将这一分配扩展至一个块内的总资源（Algorithm 6），并以高频 mask tag 减少高频标签影响。它已经有资源共享思想，不能把“共享图边预算”本身作为本项目的新意。

## 原文包含查询怎样执行

Algorithm 3 对查询标签集合 $L_q$ 选择最稀有标签 t。因为 $L_q\subseteq L_i$ 蕴含 $t\in L_i$，满足全部条件的对象必在 $\mathcal D_t$ 中。算法据交集基数估计选择扫描或图搜索，在覆盖集合中导航，并以全部查询标签检查结果。

这条路线是“选一个覆盖索引，再验证完整谓词”，不是分别检索各标签 top-k 再合并。单标签导航图也不保证交集内部可到达所有近邻。正文估计段落的个别不等式方向有笔误，实际应满足 $|\mathcal D_{L_q}|\le|\mathcal D_t|$，实现仍需核对。

前缀场景可直接用完整前缀作为 singleton 标签执行，或者把对象所有前缀标成标签、用查询前缀链作为 AND 输入；后一种输入包含冗余祖先条件，所有基线都应先规范化到最深前缀，不能把消除冗余本身包装为收益。

## 前缀结构增加了什么信息

单序列对象 a 的前缀沿同一条路径排列，记长度 l 的前缀为 $p_l$。它们满足

$$
\mathcal D_{p_1}\supseteq\mathcal D_{p_2}\supseteq\cdots,
\qquad
f(p_1)\ge f(p_2)\ge\cdots.

$$

一般标签可以任意交叠；同一对象的前缀范围却是一条包含链。深前缀内的边同时满足其全部祖先前缀，因此不同层次的标签需求并不是彼此独立的资源需求。朴素逐前缀独立配额可能忽略这种共享，但这不证明原 Packing 实现必然物理存储重复边；其去重和 mask 机制需要通过代码与消融核实。

### 一个例子

a 的序列为 $(A,B,C)$，有三个候选邻居：


| 邻居  | 属性序列  | 这条边可用于的非空查询前缀 |
| ------- | ----------- | ---------------------------- |
| $b_1$ | $(A,B,C)$ | $(A)$、$(A,B)$、$(A,B,C)$  |
| $b_2$ | $(A,B,D)$ | $(A)$、$(A,B)$             |
| $b_3$ | $(A,E)$   | $(A)$                      |

存储这三条不同物理边，三个层次的有效出度分别为 3、2、1。三个数之和为 6，不能当作实际需要六条物理边。同理，一条深前缀边已可被祖先查询复用，就不必仅为满足祖先计数再复制它。

但 $b_1$ 不能在导航上完全替代 $b_3$：宽前缀 $(A)$ 的查询向量可能更接近 E 分支。**同时满足过滤条件，只说明边可用，不说明它在向量几何上提供相同价值。**

## 候选改进 从独立配额改为累计有效出度

以下为本项目推导，不是原论文方案；新颖性尚未充分排查。

设最终物理邻居集合为 $N(a)$，定义边的有效前缀深度

$$
h(a,b)=|\operatorname{LCP}(s_a,s_b)|.

$$

当当前对象 a 已满足长度 l 的前缀查询时，邻居 b 合格当且仅当 $h(a,b)\ge l$。故该层次的有效邻居数为

$$
d_a(l)=\sum_{b\in N(a)}\mathbf1[h(a,b)\ge l].

$$

显然 $d_a(l+1)\le d_a(l)$。可把资源目标表达为

$$
|N(a)|\le M,
\qquad d_a(l)\ge r_a(l),\quad l\in\mathcal L_a,

$$

其中 $\mathcal L_a$ 为纳入索引设计的前缀深度，$r_a(l)$ 为其目标有效度。新增一条深边时，应同时更新它覆盖的全部祖先层次，按尚未满足的需求计算增量，而不是在每层分别记一次物理成本。Packing 的块预算版本可以将固定逐点上限改成块内物理边总量约束，但必须统一比较口径。

上述式子只是设计约束，不保证可行：候选集合有限、某些前缀对象很少或目标 r 过高时可能无法满足；更不保证连通或 recall。并且若只按有效度计数选边，可能全部选择深层几何近邻，使祖先查询失去跨分支导航。因此，需要与原 RNG 风格的几何多样性结合，并保留宽前缀的跨子分支候选；暂不在缺少数据时固定每层配额。

这项候选改进与第一篇的区别是：第一篇的 LCP/Trie 改造可以保持图不变，主要省标签处理；这一篇尝试改变边的选择，从而可能改变召回、空间和时延的折中。两者应分开消融。

## 最小实验与可证伪假设

假设 F2：在单路径前缀数据上，显式考虑跨深度复用的边分配，相对于已做完整前缀编码及去重的原 Packing，在相同实际索引字节和最终 Recall@k 下改善部分跨层级查询的时延；不预设所有前缀均有收益。

最小实验先固定 5K–20K 向量、距离、k、构图候选与入口，构造树深、分支度和前缀频率可控的单路径数据；分别包含向量与类别独立、同分支向量聚集两种场景。基线依次为 FilteredVamana/StitchedVamana、完整前缀 singleton 的原 Packing、仅加入物理边去重、再加入累计需求与几何多样性的原型。若原实现已有相同共享，须如实承认并调整假设。

小数据用完整前缀过滤扫描生成 exact top-k。除 QPS–Recall@k、P95、总常驻/峰值字节、构建时间，记录每对象各深度有效度、边有效深度分布、不同物理边与索引槽位数量、层级共享元数据、距离计算、宽查询跨分支访问。扫描查询前缀深度和实际 pass ratio；固定数据树时改变查询分布，避免把罕见深前缀与难查询直接等同。

反例与风险：浅树、叶子查询占主导、原方案已自然共享大部分边，候选机制可能没有收益；过度偏向深边会损害宽前缀，过度保留跨分支边又会挤占深前缀。小前缀集合直接扫描可能更好。全量新增标签元数据可能抵消共享收益。多路径对象不再满足沿一条路径的单LCP模型，不能直接外推。

原文理论边界：§IV Lemma 1 的 $O(nM_0)$ 是 Global 方案的图边空间分析，不是该原型或整个 Packing 的无条件保证；原文未提供任意数据下端到端 Recall@k 下界。本轮没有实现算法或运行性能实验，F2 不是已验证结论。

## 这一篇留下的问题

Filtered-DiskANN 让我们关注“剪掉一条边会不会破坏过滤导航”；Packing 进一步让我们关注“不同过滤范围应分到多少边”。前缀结构提供的新信息是边对各祖先过滤范围的嵌套复用关系。下一篇可看 UNG 如何把属性集合包含关系直接组织成导航结构，再判断前缀 Trie 是否能简化其标签组与跨组连接。
