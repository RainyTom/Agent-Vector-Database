# 第五篇 Curator 与前缀范围的共享几何搜索

论文：[Curator: Efficient Vector Search with Low-Selectivity Filters](https://arxiv.org/pdf/2601.01291v3)，Yicheng Jin、Yongji Wu、Wenjun Hu、Bruce M. Maggs、Jun Yang、Xiao Zhang、Danyang Zhuo。PACMMOD 4(1)，2026／SIGMOD 2026，[正式 DOI](https://doi.org/10.1145/3786635)。本轮分析 arXiv v3（2026-01-10），核查日期 2026-10-19。B 类 filtered ANN，可迁移借鉴，非 vector join。

上一篇 ELI 问哪些过滤范围值得物化。Curator 进一步说明：即使不同范围需要自己的搜索视图，也可以共享同一套几何分区。本轮先解释原机制，再讨论前缀特性可作用的环节。

## 原问题 为什么少量合格对象会使搜索困难

当合格对象占比很低时，全局近邻图中由合格对象诱导的子图可能很稀疏；只沿合格对象走容易失去导航路径，允许经过不合格对象又可能浪费大量访问。每个标签单独建立 HNSW/IVF 能适应其分布，但会增加构建和存储成本。

Curator 用共享分区树容纳各标签视图，避免依赖稀疏合格子图的连通性。作者 low selectivity 指低合格占比；本项目统一称 pass ratio。它主要补足图方法在低 pass ratio 下的不足，不应概括为所有查询上一律替代图索引。[§1、§3，PDF pp.1–5](https://arxiv.org/pdf/2601.01291v3)。

## 原方案一 共享几何树 各标签调整搜索粒度

基础索引是对全部向量建立的 hierarchical k-means tree。树节点代表几何聚类，存储中心；它由向量分布生成，不是业务属性路径构成的 Trie。

各标签索引嵌入该基础树，并按合格对象分布选择不同深度的分区。若某个区域内的合格对象很少，可以在较浅层用一个 buffer 保存其 ID；合格对象密集的区域继续细分。所有向量共享，标签专用 buffer 保存有序 ID。基础树节点还通过 Bloom filter 标记哪些标签索引经过该节点，用于跳过无关分支。Bloom 的假阳性可能增加访问，但不会把不合格对象自动加入结果。[§3.1–3.2，PDF pp.4–5](https://arxiv.org/pdf/2601.01291v3)。

例如某标签只有 30 个对象，而 buffer 容量为 64，可以在根部形成一个叶 buffer；不必强迫这 30 个对象沿完整几何树分散到许多底层节点。大量对象共享一个标签时，则需要更细分区。

搜索沿此标签视图执行 beam search 和 best-first search，使用几何节点评分与启发式停止规则。精确过滤和近似搜索要分开：只扫描合格 buffer 不等于有限搜索预算下保证找到全部真实 top-k。[§4.1，PDF pp.5–6](https://arxiv.org/pdf/2601.01291v3)。

## 原方案二 复杂谓词构造轻量临时视图

对于 AND、OR、NOT 或数值范围，Curator 将合格对象子集看作一个 virtual label。它不为每次查询重新运行 k-means，而是复用基础几何树构造临时视图。

关键条件是：向量 ID 按基础树的位置编码，同一几何子树内的对象在 ID 顺序中连续。给定**按此 ID 排序的合格对象列表**后，Algorithm 2 通过各几何子节点的 ID 范围二分划分列表；当当前范围的合格对象数不超过 $B_{\max}$ 时停止细分。临时节点只需关联基础节点、合格列表片段及子节点指针。[§4.2、Algorithm 2，PDF pp.6–7](https://arxiv.org/pdf/2601.01291v3)。

原文将有序合格列表作为输入，通常由外部关系数据库、posting list 或 bitmap 生成。故临时构建快，不意味着任意谓词的端到端处理都同样便宜。原文也明确提出仅在预计要搜索的子树内进行谓词求值和临时构建的延迟优化，并允许缓存或持久化热门 virtual-label 视图。这些都是已有能力，不是本项目新提出的机制；延迟优化在原实现和实验中的具体采用程度仍待核查。

§6.2 Fig.9 的实际复合谓词评测为两标签 AND/OR。Curator (Idx) 预建谓词索引，Curator 在线构建；不能据二者曲线差异推断外部合格 ID 生成已完整计时。可表达一般谓词与已测试大规模前缀工作负载是两件事。

## 前缀过滤的直接基线

对单路径对象 $s_i$，展开其全部完整前缀标识；查询前缀 $p$ 用一个标识进行单标签搜索。这已经使 Curator 能准确表达前缀过滤。另一基线先根据原生前缀索引取得合格对象，再按 Curator ID 排序，调用原临时视图构建与搜索。

因此，“共享几何树”“每个前缀一个视图”“稀疏分区上浮”“只构建访问区域”均不足以单独构成改进主张。应把比较集中于前缀范围的表示、生成与共享成本，同时保持合格对象语义相同。

## 前缀结构带来的真正问题 两种连续性不一致

记属性 Trie 为 $T_s$，几何聚类树为 $T_g$。单路径数据按属性 Trie 的 DFS 顺序排列后，一个前缀的全部对象可连续；但这通常不是 Curator 几何树的 ID 顺序。

考虑四个对象：

| 对象 | 属性分支 | 几何分区 |
|---|---|---|
| 1 | A | X |
| 2 | A | Y |
| 3 | B | X |
| 4 | B | Y |

属性范围为 $A=\{1,2\}$、$B=\{3,4\}$；几何分区为 $X=\{1,3\}$、$Y=\{2,4\}$。不存在一种四对象线性顺序，让四个集合都各自占据一个连续区间：四个不同的二元素集合均要求相邻，而四位置顺序只有三个相邻位置对。本轮枚举全部 24 种顺序也得到零个可行顺序。这是本项目反例推导，不是 Curator 作者定理，也不是性能实验。

因此，不能直接用属性 DFS ID 替换 Curator ID，同时继续假定所有几何子树仍连续。完整前缀共享并不会自动解决两棵树的交叉关系。

## 候选改进 F5 用前缀范围支持局部几何视图

以下为本项目综合推导，新颖性尚未充分排查。

静态单路径数据中，为每个对象保留几何顺序位置 $g_i$ 与属性顺序位置 $t_i$。属性顺序可通过 DFS 枚举 Trie 子树中的对象获得，同一终止节点的多个对象连续，内部节点终止的对象也需计入。几何节点 $u$ 与前缀节点 $p$ 分别对应半开区间 $I_g(u)$、$I_s(p)$。则

$$
\mathcal C(u,p)=\{o_i:g_i\in I_g(u),\ t_i\in I_s(p)\},
\qquad N(u,p)=|\mathcal C(u,p)|.
$$

即两棵树的交集可写成二维正交范围的计数与报告问题。这个归约精确描述成员关系，不自动给出低成本的数据结构；二维范围索引是需要比较的已有工具，不能声称该归约本身为新算法。

一个待验证的方案是用共享范围表示，在搜索访问几何节点时查询其前缀合格数：$N(u,p)=0$ 则跳过；数量较少时报告这些对象并形成局部 buffer；数量较多时继续沿几何树细分。这沿用 Curator 的粒度调整与延迟视图思想，候选差异仅在**跨前缀共享的成员表示和局部计数/报告接口**，是否净收益必须实测。

该方案希望在只访问少量几何区域时，避免预先展开整个 $\mathcal D_p$ 的有序 ID 列表。它必须与原文已提出的延迟求值版本比较，不能只击败 eager 全构建版本。

必须分别考虑以下成本：

- 计数只能决定是否跳过或细分；要计算对象距离仍需报告 ID 并读取向量，不能仅靠计数生成结果。
- 显式保存所有 $(u,p)$ 的交集可能使元数据膨胀，不应把两棵树的笛卡尔积视为免费；范围结构、缓存与 buffer 全部计入内存。
- 原生属性区间与几何 ID 的双顺序映射也占空间；更新引起的重排与维护另计。本轮首先限定静态数据。
- 几何中心/启发式与访问次序仍影响 ANN recall。若新实现改变 buffer 粒度或停止轨迹，必须重新验证召回，不能从过滤等价推出搜索结果等价。

前缀计数还满足分解关系。对属性节点 p，令 $E_p$ 是恰好在 p 终止的对象集合，则

$$
N(u,p)=|\mathcal D_u^g\cap E_p|
+\sum_{c\in\operatorname{Ch}(p)}N(u,c).
$$

这是单路径互斥子树的精确加和，可用于共享统计或校验缓存；直接逐子节点求和也可能昂贵，不等于常数时间查询。多路径对象会重复出现，不能直接沿用此加和公式。

## 最小实验与失败条件

**假设 F5：** 在相同总内存和最终 Recall@k 下，若查询只访问少量几何分区，跨前缀共享的局部成员表示能降低合格 ID 准备、临时视图和搜索的端到端成本。其净收益随属性与向量分区相关性、路径深度、pass ratio、查询复用率变化。

先使用固定 10K–50K 向量与静态单路径 Trie，设置属性和向量聚类对齐、独立、交叉分散三种分配；固定距离、k、查询和硬件。先核成员与计数正确，再比较以下方案：

| 基线或组件 | 用途 |
|---|---|
| 完整前缀展开 + Curator 单标签索引 | 原机制即可执行的直接强基线 |
| 属性前缀取成员、转换为有序几何 ID + Curator 临时视图 | 分离编码与视图成本 |
| 原文延迟求值/构建思路的可复核实现 | 排除仅由延迟化带来的收益；与作者实现差异显式记录 |
| 候选共享范围表示 + 局部视图 | 测前缀结构带来的额外收益 |
| 精确过滤扫描 | 给出 top-k 真值与低合格数时的实际基线 |

沿用 Curator 原生分区搜索以隔离成员表示差异，不能通过换 ANN 库解释收益；若另加图式对照，统一使用 hnswlib 并分别报告后端。消融依次固定搜索参数/顺序、加入局部成员表示、再加入缓存；不让单个方案独占预热。

报告全部范围结构、标签成员与缓存字节，构建成本，合格 ID 生成/排序时间，临时视图时间，节点访问数、中心/对象距离计算数，平均/P95 延迟和逐查询 Recall@k。端到端计时从输入 $(\mathbf q,p,k)$ 开始；零结果与不足 k 查询按主定义另报，不能筛去。缓存分别测冷/热场景，更新不纳入静态结果。

可能失败：前缀 bitmap 已压缩得足够好；低合格数扫描占优；搜索几乎遍历全部几何区域；范围查询/随机访问比线性有序列表昂贵；属性与几何高度交叉导致局部报告频繁；浅树/热门固定前缀无需复杂共享。若有这些结果，应收缩方案适用区间，而不是改写为普遍优于 Curator。

与上一篇 F4 的关系：Curator 的固定基础树可以作为共同成本另计，某些独立 per-label 增量成本仍可能可加；仅凭“共享树”不能断言 F4 必然失效。若进一步采用跨前缀共享成员表示或联合缓存，成本可能依赖共同物化选择，需要重新建模，不能直接套用独立索引成本的 DP。
