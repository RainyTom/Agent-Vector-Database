## 3. 先回答：合格起点是否只会到合格点？

设owner(u)=a，Desc(a)包含a。当前桥/MST多为双向，还有向父/根代表的跳转，**不能保证**邻接目的端合格。

反例：R有子属性A、B，a直属A，b直属B。构图在R处加入a↔b。查询A时a合格，b不合格；递归和非递归都可能如此。

### 3.1 对全部递归OR查询保持资格的边

对所有允许的递归查询，边u→v若要满足“u合格必推出v合格”，充要条件是：

\[
owner(v)\in Desc(owner(u)).
\]

充分性：任一包含owner(u)的后代闭包，也包含owner(v)。必要性：直接取查询属性owner(u)，目标必须在其闭包内。多个属性OR是闭包并集，不改变这个条件。

因此，同owner边和向后代边可用此证书；向祖先/兄弟的边不能无条件免检查。**把所有边改为单向下行又可能失去从一个子分支到另一分支的路径，不能据此宣称搜索完整。**

### 3.2 对全部非递归OR查询保持资格的边

充要条件是`owner(u)==owner(v)`。取只查owner(u)的非递归查询即可证明必要性。跨属性桥不能依赖递归证书免检查。

可以在构建时识别同owner/下行边，减少已知安全边的重复判断；如保存边证书位或按owner分段，必须计入字节与读取成本。当前实现尚未应用这项优化。

## 4. 分层设计

### 4.1 强控制：原生层保留与同层拼接

1. 每个非空直属属性仍用其独立hnswlib构建M64/efC200局部HNSW。
2. 对每个真实item导出原生最高层L(u)，以及各层的**有向**邻接；不再只调用`get_linklist0`。不免费对称化，反向边也要拿到接收端槽位。
3. 第ℓ层只包含L(u)≥ℓ的item。只从实际存在于这一层的item选该层属性代表；空代表表不伪造节点。
4. 按逆拓扑序组合各层代表。候选同层桥来自当前方案的组间几何连接，但必须经过§7的共同槽位重选。
5. 查询从合格入口所在的最高可用层开始，层内对所有owner共享一个前沿，逐层降到level-0。强控制固定上层`ef_upper=1`、底层为共同ef；不得对各owner调用`searchKnn`后合并。各层均先资格、后查询距离。
6. 距离缓存按item区分；邻接展开状态按`(level,item)`区分。高层已算距离不意味着底层邻接已扩展。

层次归因对照预先生成同一份合格入口候选表：原底层代表加上选定的原生高层入口；flat控制在level-0使用同一批真实ID，分层臂才走高层邻接。降到level-0时仍并入这批原始合格seed，不能因上层ef=1就悄悄丢掉其他OR分量的初始化。入口评分缓存复用且全部计数。这样可把入口变好与高层路径变好分开；有限beam本身仍没有分量覆盖保证。

小属性可能没有高层点；只能从较低层进入，不能暗中强制提升后仍叫“原生层保留”。仅保留层次但不加同层桥，高层可能仍有多个owner分量，这是要测的控制，不是保证有效的算法。

由原生随机层规则，M64时P[L≥ℓ]=64^(-ℓ)。168937个点的level≥1和≥2数量期望约2640和41，**不是本轮实测层统计**。不能因为总体有高层，就认为每个属性有高层。

### 4.2 候选：固定层配额的DAG代表提升

不直接令“DAG深度=HNSW层号”。DAG多父没有唯一树路径；高度也不是几何尺度。

- 候选是各属性原有真实portal，按item去重；不造质心，不改向量。
- 为每个候选记录去重的属性覆盖责任：它代表哪些DAG组合上下文、能连接哪些非空输入组。
- 固定每层节点出现配额及邻接字节，比较random、recursive-size、DAG覆盖/高度三种分配。大子树规模按去重item数计算，不把共享后代重复收费。
- 提升必须补齐0…ℓ嵌套出现并重建对应层邻接；只改level数字但没有可导航邻居不算分层完成。
- 同配额实验若提升一个portal，应撤销其他非强制高层出现或从同一字节预算支付；不能额外买高层容量后声称DAG选择更好。
- 对被多个祖先反复提名的portal设置层内槽位约束；先前端点负载已满则换代表或报告本次构建无法满足，不静默生成超级hub。

研究假设：**DAG覆盖责任在相同高层配额下，比随机或只按子树大小分配更能修复合格搜索分量。**风险是当前随机owner绑定缺少几何相关性，提升可能只制造远距离跳转和高层热点。尚未验证性能或新颖性。

## 5. 属性倒排入口与“唯一入口”

维护两张有版本的入口倒排：

```text
EntryDirect[a][level]    仅含直属a的真实item
EntryRecursive[a][level] 仅含Desc(a)中的真实item
```

每个桶保存有序去重的有限候选。递归空直属属性可从后代得到代表；非递归空直属属性直接空答。OR入口跨属性去重，不重复计算同一item距离。

必须区分三种策略：

|策略|真实起点数|费用与正确性边界|
|---|---:|---|
|静态单真实seed|1|无需为其他候选评分，但可能只覆盖一个合格分量|
|候选全评分后选1个|1|所有候选的合格查询距离都要计数；仍没有跨分量保证|
|一个虚拟查询源点→多个合格seed→共享前沿|多个|源点无向量、不评分；只有一次图检索，不是多图top-k归并，但不能称单真实seed|

建议以第三种作为保守主策略，第一/二种做入口消融。若用户要求严格一个真实起点，则必须接受它是额外近似因素，测入口可达覆盖和尾部Recall。两个不相交属性的OR，仅各自局部连通，不足以从一个真实seed覆盖两者。

## 6. 跳转预算b

### 6.1 推荐主语义：连续不合格中间点数

b限定两个合格节点之间可连续跨过多少个不合格item；抵达合格节点、以后扩展它时重新给预算b。它不是全查询共享的展开次数，也不是整条查询路径不重置的总额。

- b=0：只在合格诱导图上搜索。
- b=1：允许A合格→X不合格→B合格。
- b=2：再允许A→X→Y→B，两名不合格中间点。

这里“预算用完”表示不能再进入下一个不合格点；剩余0时仍可读当前不合格点的邻接以接回合格出口。若把“0立即停止读邻接”作为另一个定义，b=1便不能完成A→X→B，不能混用参数数值。

不合格点不计算query距离，也不进入按自身query距离排序的ANN前沿；它们只进附属元数据工作队列。所有合格出口仍送入唯一共享ANN前沿。

```text
ExpandQualified(u, level):
    对各邻居v:
        若Eligible(v): OfferQualified(v, level)
        否则若b>0: ExploreBad(v, level, b-1)

ExploreBad(x, level, remaining):
    若remaining <= best_remaining[level,x]: return
    更新best_remaining[level,x]
    对各邻居v:
        若Eligible(v): OfferQualified(v, level)
        否则若remaining>0: ExploreBad(v, level, remaining-1)
```

`best_remaining`初值必须低于0；距离是否已算、邻接是否以该预算展开是两个状态。若局部候选截断还依赖来源锚点/顺序，状态键要加入相应上下文，不能直接沿用上述简化支配关系。

### 6.2 两种不同预算不得混报

若采用“从真实起点累计、不重置”的语义，则合格节点也必须携带剩余预算；同一item以更大剩余值再次到达时，虽可复用距离，仍可能需要再展开。全查询共享工作额则是第三种调度机制，会依赖分支顺序。

本轮有限FIFO反例：短路径先以剩余0抵达X，较长但少经过不合格点的路径后以剩余1抵达X；普通visited漏掉出口，预算支配状态能找到。见[已运行证据](data/dag-budget-semantics.json)。该探针采用累计b=2、不重置，不能冒充推荐连续预算的性能实验。

### 6.3 与ACORN-1的区别

ACORN-1枚举N(u)及所有一跳节点的邻接，连合格中间点也展开，然后过滤、按M截断。连续b=1只描述穿过一名不合格中间点的恢复，不主动绕过未进入前沿的合格中间点；两者不等价。

b只限制路径上的拒绝点数，不限制全查询元数据工作；朴素分支量可随度数和b快速增加。增加b也不保证有限ef/早停下Recall单调。必须记录邻接读取、拒绝点展开、预算改善重展开与合格距离，不能只记L2次数。

## 7. 边替换：固定槽位、资格见证与容量强删分账

### 7.1 物理预算

以原生M64为参照，明确每层邻接容量`R0=128`、`Rℓ=64 (ℓ>0)`，不是笼统说“每点64条边”。原始边、MST、portal、分散桥、jump共同竞争槽位；双向桥需要两端各有槽。该上限是可比控制，不是所有子树都能保连的定理。

本轮真实两item探针：有效邻居1→0，level-0邻接分配仍为516B/容量点，完整记录步长仍1036B，高层邻接260B/层出现；底层分配地址未变。见[数据](data/dag-memory-probe.json)。仅修改`setListCount`不会回收邻接容量。

当前程序还保留`m.local`并另存导出边，CSR臂又有额外邻接/owner数组；当前QPS曲线**没有统一服务驻留字节预算**。不能据同M就声称等内存胜出。

最终预算应包含：一份FP32向量、全部层邻接容量与offset/层号、属性DAG/闭包、direct/recursive入口倒排、必要的边证书、查询scratch。构建临时局部HNSW在导出全层后释放，构建峰值另报。是否inline owner应单独收费，不能拿8B/边表示与4B/边表示当相同内存。

### 7.2 原始FilteredRobustPrune

在候选v之前已经保留w时，原论文Alg.3按以下条件删除u→v：

\[
\alpha_E d(w,v)\le d(u,v),\qquad F(u)\cap F(v)\subseteq F(w).
\]

原文使用Euclidean metric。本项目D=||x-y||²时等价几何条件为`alpha_E²·D(w,v) <= D(u,v)`，不能直接沿用同一alpha数值。算法达到R后直接break，剩余候选属于容量舍弃，不一定具有该见证。

### 7.3 任意正OR需要更强的局部资格条件

定义F(u)为使u合格的原子谓词集合。若希望用w作u→v的替代点，对全部正OR查询要求：

\[
\forall Q:(P_Q(u)\land P_Q(v))\Rightarrow P_Q(w).
\]

充要条件是：

\[
F(u)\subseteq F(w)\quad\lor\quad F(v)\subseteq F(w).
\]

若两端各有一个w不携带的原子标签，选这两个标签的OR即可反证。树R→A/B/C上u属A、v属B、w属C：共同祖先R满足原交集条件，但查询A OR B拒绝w。

单owner下，direct模式等价于w与至少一端同owner；recursive模式等价于w的owner是至少一端owner的后代。若同一物理图必须支持两模式，不得只用recursive条件声称同时安全；可使用包含Direct(a)/Recursive(a)两类原子的F，或逐模式分别核验。

**它只证明替代点资格，不证明w→v仍存在或有限beam召回。**要把某次删边称为有实际替代路径，应验证同层两段边都最终保留；后续剪枝也不能再破坏证书。不能把该条件包装成全图连通定理。

### 7.4 可实施重选顺序

1. 原始邻接与新桥候选统一去重；自环删除，反向边不免费。
2. 先选择有限必要桥与局部骨架P(u)，逐点检查`|P(u)|<=Rℓ`。无法满足时报告构建约束冲突，不静默扩容或声称全部骨架保留。
3. 已保留边占槽；其他候选按距离、多样化及OR资格见证筛选，新增桥替换相应原始边。
4. 分别记录`predicate_witness_drop`与`cap_forced_drop`。后者没有同等替代依据。
5. 对最终各模式、各属性范围核入口可达覆盖；记录因端点槽位不足未能准入的桥。只有选中且实际保留的骨架可声称被保护。
6. 导出紧凑全层服务表示，实际统计容量/字节，不再常驻一套不用的局部图。当前代码尚未执行此切换。

### 7.5 一般多父DAG的不可兼得边界

n个item各属叶属性t_i；为每对i<j建一个父属性a_ij，后代恰为t_i、t_j。因此每个a_ij查询的合格集合恰有两个item。

即使每属性自由选一个真实入口，要在b=0时到达另一点，每对也至少需要一个方向边，故总边数≥n(n-1)/2，最大出度≥(n-1)/2。R0=128时，n=258便需要至少33153条边，超过258×128=33024槽。

所以，**任意多父DAG＋每点固定硬度上限＋全部子树单真实入口可达**不能无条件同时保证。需明确选择：受限DAG/已验证可行骨架、块/总字节预算、多真实seed、或允许b>0。不能暗中改变承诺。

逐点“新增几条桥就必须删同样多实际旧边”也有边界：单item属性原始出度为0，却可能必须加桥。应比较明确的容量/字节预算，而不是假设每点原始有效度都有可替换余量。

- [有限语义脚本](experiments/dag_budget_semantics.py)：1099个固定拓扑序DAG（1…5属性）、26705个边资格条件检查、132329个OR替代点检查；另有预算状态和度预算反例。有限枚举不是对无限情形的证明，通用论证见§3/§7。
- [真实hnswlib内存探针](experiments/dag_memory_probe.cpp)：两item，M64/efC200，逻辑删邻居后容量未回收；不是RSS或ANN性能实验。
- M64当前平面图的两格固定(k,efSearch)批量QPS见[两格对比报告](dag-two-cases-report.md)，不与本文新策略混报。

最小实验按因素分阶段，不立即组合全部旋钮：

|阶段|对照|其他固定项|
|---|---|---|
|A：层次作用|flat；原生层无同层桥；原生层＋同层桥|相同入口、b=0、相同向量/owner/ef和明确全层字节|
|B：结构化提升|random；size-only；DAG覆盖/高度|相同逐层节点配额、边容量、入口和b|
|C：入口|静态单seed；全评分选1；虚拟源多seed|同一图、同一ef；入口距离全计|
|D：穿越|连续b=0/1/2；ACORN-1策略另列|同一图和入口；不混累计/全局预算|
|E：剪枝|普通RNG；singleton-cover；OR-witness/保桥|同一候选池、R、全层字节与平方距离alpha换算|

每阶段沿用当前两格固定协议：`k=10,efSearch=32`与`k=100,efSearch=128`，组内不调ef/k/构图；NodeANN每图在同一格内扫n=1…k而非强制n=k。每组以本方案该格实测Recall为R*，只比较达R*的同格QPS，报告全部点、超额、最小值与未达标状态；不跨ef连线，不把不同格混成一条曲线。

除质量/吞吐，还测逐层实际节点数、边/容量分布、入口评分、合格L2次数、不合格L2=0、属性判断、拒绝邻接展开、预算重展开、缺额/空查询、最大预算可达覆盖、服务驻留与构建峰值。新算法在实际运行前不得写收益数字。
