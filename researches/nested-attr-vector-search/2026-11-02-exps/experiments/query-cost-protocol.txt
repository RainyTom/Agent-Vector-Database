Fixed measurement workload
- Same SIFT128 first168937 base rows, first24 queries, CCS DAG, owner shuffle/seed and OR scope pairing as retained run26.
- Fixed operating points: merged ef512, global_filtered ef32, nodeann ef32. No optimization or budget changes.
- Empty queries recorded as rows with0 distances, excluded from aggregate latency/recall (23 nonempty).

Exact counter semantics
- distance_calls: actual RawL2Space kernel invocations, including native upper-layer/entry repeats. Not unique items, visited nodes or expansions.
- distance_qualified/rejected: attribution by item owner eligibility. Diagnostic attribution lookups do not count as algorithmic predicate calls.
- unique_distance_items: distinct item IDs whose distances were evaluated during one query, across all local graphs/levels.
- item_checks/rejects: merged checks each offered neighbor/seed BEFORE visited; native global callback checks result eligibility AFTER distance/candidate admission. These counts are not semantically identical stages.
- owner_checks/rejects: NodeANN scans owner qualification mask to choose graphs. No per-item callback inside qualified local graph.
- scope_us: closure-union and minimal-root resolution; separate from item/owner checks.
- Build, portal construction, ground truth and final recall verification distances excluded from query counters/timings.

Pass schedule
1. Prepare GT and eligible counts, outside all timers.
2. All ordinary timings first, native distance pointer unwrapped; per query warm1 then median3. No per-operation timestamps.
3. All exact-count passes, with native distance pointer temporarily wrapped then restored by RAII.
4. All per-operation timing passes, repeated3; retain the sample with median profiling-wall time, preserving coherent counters/components.
5. Validate exact returned IDs and operation counts agree between normal/count/profile passes. Compare hits and merged counts against saved run26.

Time interpretation
- Raw bracket times include Clock::now bracket overhead, but exclude diagnostic classification/counter increments.
- Calibrate empty bracket using identical compiler fences: median of5 means of20000 timestamp pairs.
- component_est_us = (sum_component_bracket_ns - component_call_count * timer_pair_ns) /1000.
- Do not clamp negative estimates: they indicate the component is below this calibration's resolution.
- These are online profiling-pass component estimates, NOT exact unperturbed query attribution. Clock probes, metadata reads, altered cache/branch context and calibration noise remain.
- Report count/profile wall time and slowdown relative to ordinary timings. Never sum estimates against ordinary latency, or call the remainder normal graph overhead.
- Predicate brackets measure mask lookup, not all branching/control costs; distance brackets measure RawL2Space kernel, not graph/heap/visited operations.
- No hardware-layout, SIMD, prefetch or compression changes; raw kernel and pinned hnswlib unchanged.
