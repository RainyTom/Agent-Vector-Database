# 物化作用域图：层级属性过滤向量检索的基准实现（2026-10-20）

状态：autoresearch 实验记录，固定基准上的工程结果与消融，不主张新颖性。本文档是本轮实际完成的工作（每节点物化图 + 紧凑存储 + 预取），不是[D0–D5 六个方案](../directions.md)中的任何一个；那六项仍保持停止/暂停决定。问题语义见[精化定义](../index.md)定义 7–10，评测协议见[基准协议](../benchmark-protocol.md)。

## 结论

在 SIFT100k、85 节点层级、1000 条混合作用域查询、Recall@10 ≥ 0.95、过滤零违规的同一口径下，查询吞吐从基线 **3,104 qps** 提升到 **94,698 qps**（≈30.5×），Recall@10 **0.9570**（高于门槛 0.7pp），p95 20.9 µs。最终索引 **83 MB**、构建 30.8 s；基线为 64 MB、16 s。宿主机抖动约 ±5%，同一代码多次运行的吞吐区间为 90–95k。

## 问题与范围

对象带多个层级标签；查询是 antichain 节点集合，可行集为各节点子树内直接标签对象的并集，按对象 ID 去重；过滤必须精确，近似只允许最近邻遗漏。基线暴露的核心矛盾：

- 全局图 + 后过滤的低选择率作用域会退化：hnswlib 的过滤搜索把“允许对象数”计入 `ef`，6% 选择率下需要接近整图遍历。
- 直接枚举可行集做精确扫描受内存带宽限制（float 下 25k 范围约 0.7 ms）。
- 层级包含关系允许把范围整合前移到构建期——这正是本工作采用的方向。

## 方法

### 1. 每节点物化精确可行集

对每个对象的每个直接标签沿父链加入所有祖先的成员表，排序去重。节点 $u$ 的索引恰好覆盖 $\mathcal D_u$，查询期没有谓词、位图或候选过滤。antichain 查询对 $|U|$ 个索引各取 top-k，按 $(distance,id)$ 合并去重。局部精确 ⇒ 合并精确，误差只来自 ANN。

### 2. uint8 精确距离

SIFT 描述子是 $[0,255]$ 内的整数（train/test 全为整数，最大值 212）。uint8 存储、int32 累加平方 L2：每维上界 $128\cdot255^2\approx8.3\text{M}<2^{24}$，float 转换精确，排序与 float32 完全一致。距离核用 AVX2 16 路 `vpmaddwd`。

### 3. PC1 内部 ID 布局

对中心化数据做 12 次幂迭代得到第一主成分，全库投影一次；每个节点按投影排序后插入。图的邻居在地址上更接近，交错 A/B 约 5%。

### 4. 作用域分组执行

同一节点的所有查询连续执行，再按查询合并部分结果。结果与顺序无关，只是把分散的图访问变成批式局部访问；float 下提升约 35%。

### 5. 紧凑内联块

hnswlib 的 level-0 元素为 `[2M 个 uint32 邻居][uint8 向量][size_t 标签]`（M=24 时 336 B）。自定义格式把向量放在块首，随后是 uint16 计数、uint16 邻居列表和 32 位外部 ID，共 226 B。向量前置让距离所需的缓存行与块首重合，邻接只在节点被弹出时读取。

### 6. 最近 M 条邻居

实测平均出度 21.2、仅 0.45% 达到 2M=48。导出时按到自身向量的距离排序，只保留最近 M=24 条：块 226→178 B，索引 108→83 MB，每次弹出扫描的邻居也更少。

### 7. 软件预取

冷图随机访问是主要成本：

- 处理某节点时，为其全部邻居块预取向量所在的两条缓存行，再计算距离；
- 候选堆顶即将弹出时，预取其邻接所在的两条缓存行。

预取行数经交错测量：邻接前置布局 0/1/2/3/4 行为 71.0/76.0/81.5/82.2/81.9k；向量前置布局 1/2/3/4 行为 85.3/85.7/83.3/79.6k。取 2 行。

### 参数

M=24、efConstruction=200、查询 ef=21；所有对象按标签继承得到 400k 成员关系（约 4× 向量重复）。

## 结果

- 主指标：`qps_at_r95` = 94,698（Recall@10 ≥ 0.95 且零违规时的查询吞吐）。
- 次指标：Recall@10 0.9570、p95 20.9 µs、构建 30.8 s、索引 83.3 MB、违规 0。
- 召回/吞吐曲线（截断图，交错测量）：ef=20/21/22 → 94.3k/93.5k/90.1k qps，召回 0.9533/0.9570/0.9604。
- 冷启动复现：删除整个 `work/` 后重跑，fixtures、oracle、索引全部重建，召回逐位一致。

## 消融与负结果

| 尝试 | 结果 | 结论 |
|---|---|---|
| 共享向量 + 紧凑邻接（51 MB） | 召回相同，慢 5–10% | 向量与邻接分离产生第二条随机流 |
| 变量长度邻接（82 MB） | 慢 2.4% | 偏移间接寻址抵消字节节省 |
| 小作用域精确扫描（float/u8） | 叶子 17 µs vs 图 12 µs | 扫描受带宽限制 |
| PC2/Morton、256 格聚类、逐节点 PCA、查询排序 | 中性或更差 | 一维 PC1 已足够 |
| 按节点大小分配 M / ef | 中性 | 召回缺口分散，代价斜率相近 |
| 两查询交错 beam | 结果逐位一致，84.3k vs 84.5k | 预取已隐藏延迟；两套状态抵消收益 |
| 距离/插入拆分两趟 | 慢 2–3% | 额外缓冲抵消 ILP |
| 2 路邻居循环展开 | 中性偏慢 | 分支与堆更新限制 |
| 透明大页（MADV_HUGEPAGE + COLLAPSE） | 噪声内 | 不采用 |
| 多 seed beam | 召回 +0.07pp，无速度收益 | 不采用 |
| M=32 构图再截断到 24 | ef=22 时 0.9567 | hnswlib 的多样性启发式优于纯最近邻 |
| 截断到 20 条 | 即使 ef=24 也只有 0.9544 | 24 是门槛下的下限 |

实现过程中发现并修复的正确性问题：两查询交错时若共享 visited 数组，两个搜索会互相覆盖 generation 标记，结果被静默破坏（召回 0.875 但返回 ID 仍“合法”）。并发搜索必须使用各自私有的 visited 数组。最终实现为单查询顺序执行，不使用该路径。

## 正确性与边界

- harness 用精确 oracle 复核每个返回 ID：可行性、去重、数量；`violations = 0`。
- 构建只读 base/tree/labels/meta，不读查询、workload 或 oracle；分组只改变执行顺序，不改变答案。
- 召回 0.9570 为确定性结果（单线程、固定种子、固定查询集），无逐查询保证，也不代表其他分布。
- 首版仅静态 100k、单机单线程、合成层级（属性与几何相关）；构建成本随 $\sum_i|\mathrm{Anc}^{+}(L_i)|$ 增长。

## 局限与未探索

- 未使用查询级多线程：会使索引结构比较与核心数混淆；如作为系统工程贡献，应同时报告单线程与多线程结果。
- 未实现共享多分辨率图或 NSG/Vamana 等不同图族；M=32 截断实验提示朴素最近邻图优化会损失多样性。
- 未在 1M 规模验证；索引/构建成本随成员关系线性增长，大规模下内存与构建可能成为约束。
- 未研究更新、删除、并发查询与缓存复用；本工作只覆盖静态只读基准。
