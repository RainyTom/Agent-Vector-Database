# 层级属性过滤向量检索：基准协议（2026-10-20）

本文定义 autoresearch 的实验入口与评分规则。它不主张新颖性，也不重启已停止的 D0–D5 方案；它是后续任何实现的共同测量面。问题语义沿用[精化定义](index.md)中的紧凑层级查询（定义 7–10）：查询节点集合为 antichain，可行集合为各节点子树内直接标签对象的并集，按对象 ID 去重；过滤必须精确，仅允许最近邻遗漏。

## 数据集与属性

| 项 | 值 |
|---|---|
| 向量 | SIFT1M 前 100,000 条，128 维 float32 |
| 距离 | 平方 L2，`(distance, id)` 字典序 |
| 层级 | 完全 4 叉树，深度 3：85 节点，64 叶 |
| 标签 | 每个对象 1 个主叶标签（最近 64 个种子中心的类别，属性与几何相关），12% 额外叶标签，4% 额外深度 2 标签；最多 3 个直接标签 |
| 查询 | 1,000 条测试向量；8% 根、20% 深度 1、38% 深度 2、16% 叶、18% 双/三节点 antichain |
| 结果 | k = 10；每个查询可行集合 ≥ 64 个对象 |
| 种子 | 20261020；单线程 HNSW 构建 |

生成器、oracle 与评测代码在 `production/nested-attr-vector-search/src/`，fixtures 与索引在 `work/`（不入库）。fixtures 版本号变化才重新生成；改生成器时必须同步提升 `FIXTURE_VERSION`。

## 指标

主指标 `qps_at_r95`：当且仅当平均 Recall@10 ≥ 0.95 且过滤违规为 0 时，取查询循环吞吐（1 / 每查询平均秒数）；否则为 0。

次指标：`recall_at_10`、`qps_raw`、`p95_ms`、`build_s`、`index_mb`、`violations`。

计时由候选程序在单进程内跑 3 遍取最小值，加载与构建不计入查询时间；构建时间单独计。候选输出 id 由 harness 用精确 oracle 复核，可行性、去重与数量违规单独计数。

## 基线

混合策略（`src/baseline.cpp`）：
- 每个节点维护对象 bitmap，祖先节点由子节点按逆 BFS 合并。
- 查询先 OR 出可行 bitmap；`popcount ≤ 16000` 时枚举可行 id 做精确扫描，否则使用全局 HNSW（M=16, efConstruction=200）加 ID 过滤，`ef ≈ 1.5k/selectivity`，结果不足 k 时倍增。
- 当前参考值：`qps_at_r95 ≈ 3,070–3,145`，Recall@10 ≈ 0.9987，p95 ≈ 0.75 ms，构建 ≈ 15.5 s，索引 ≈ 64 MB。

这个基线刻意保留两条路径：小范围精确扫描、大范围过滤图搜索。任何新方法必须同时胜过这两者在相同召回门槛下的表现，而不是只换掉较弱的一侧。

## 约束

1. 构建阶段只能读 base、tree、labels 与 meta；不得读查询、workload 或 oracle。
2. 查询阶段不得读取 `gt.bin` 或预计算答案；返回 ID 必须属于可行集合且无重复。
3. 不得修改 `datasets/`、`deps/`、fixtures 生成器以放宽工作量；`qps` 只在 harness 计时口径下有效。
4. 索引内存与构建成本单独报告；用无限内存换吞吐不算免费。
5. 至少在 sift100k 上报告；更大数据集作为补充，不替代主表。

## 复现

```bash
bash autoresearch.sh
```

依次完成：编译 → 导出向量（首次）→ 生成 fixtures（首次）→ 构建索引 → 3 次查询 → oracle 复核 → 输出 `METRIC` 行。
