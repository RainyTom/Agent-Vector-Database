# 从条件证书扩展到层级多属性混合过滤的机制组合

日期：2026-10-30；用户最新纠偏后。本文替代“所有下一步先过E0，再研究联合几何证据”的全局安排。E0/E1保留为几何证书族的诊断，不作为其他索引/过滤机制的前置条件。未执行本文新增实验，也未宣布任何候选已具新颖性。

## 1. 纠正研究标准：允许复用，不按组件名称判重

Trie、压缩位图、倒排、B-tree、图、几何分区、哈希、投影、查询优化和学习模型均可作为组件。使用已有组件并准确归属，不等于抄袭；论文核心机制已被做过，即使引用充分，也可能缺少独立新意。这是两个不同判断。不存在“换多少百分比就不算抄袭”的阈值；借用代码还需遵守许可证。

创新可发生在以下层次，并不要求每个基础原语全新：
- **表示与共享：** 同样的层级/多属性/向量信息，如何避免重复索引同时保留可用搜索关系；
- **构建与组织：** 如何选择或组织分区、边、局部视图、数据布局，使联合谓词仍可高效搜索；
- **查询算法：** 哪些候选先生成，过滤在哪一阶段执行，如何保持结果资格与可达性；
- **近似与质量控制：** 在原始距离目标不变时，如何减少候选/距离工作，并对漏召回及漂移给出可检验机制；
- **结构与更新协同：** 更新要求如何改变索引的组织与成本边界，而不只是调整压实周期。

不要求所有研究都产生更紧的L2下界。某个方法可以完全不改善box，却通过更好的搜索视图、候选路径或局部组织显著减少无效工作。也不要求ANN候选选择精确无漏；本项目要求硬属性资格精确，ANN保持既定同质量合同，二者不能混为一谈。

### 两级门，而不是“先证明全新才允许试验”

**探索门：** 有明确瓶颈、具体结构/操作差异、最近前序定位、可证伪预测、合理资源上限，就允许最小原型探索；新颖性风险未完全排查可明确标注，不要求先获得完整理论或全面文献闭包。

**贡献门：** 论文主张必须说明相对最近前序的实质增量，拿出机制消融、同质量、资源匹配和维护证据。发现完全等价就收缩主张；实验无效就记录该具体实现失败；未做不能记为失败。

## 3. 六个机制族：扩大设计空间，而非同时实现六套完整系统

下表全部是研究者候选，不是已确认的新算法。它们是可组合的机制轴，第一轮单独消融，避免把所有部件叠起来后无法归因。

| ID / 机制族 | 可直接复用的组件 | 值得研究的结构问题 | 首个小型判别与反例 |
|---|---|---|---|
| F1 联合资格与索引接口 | 目录Trie、倒排、Roaring/稠密bitmap、range索引 | 层级范围及多属性交集如何以搜索器可直接消费的粒度表示，避免反复展开全scope或重复逐候选解释谓词 | 固定搜索访问序列，对比全量F、逐点谓词、按实际访问批次的联合资格表示；记录准备/消费/更新总账。若普通bitmap已占很少时间，不以此作独立主线 |
| F2 共享查询视图与子索引 | Trie、共享树、局部HNSW、范围图、选择性物化 | 一份向量/几何骨架如何支持多个层级与交叉属性视图；共享什么、复制什么，查询如何进入合适视图 | 对少量固定查询比较单一索引、独立局部视图、共享视图的质量/访问/字节及更新扇出。独立局部视图是昂贵机会对照，不可免费称在线方案 |
| F3 过滤感知图导航 | HNSW、扩邻/二跳、入口索引、标签相关边、邻接bitmap | 精确结果资格与允许借道的导航角色如何分离；层级和联合谓词下怎样恢复有用候选而不过度扩邻 | 相同基础图/边预算比较结果集过滤、候选恢复及有限合法入口策略；测有效候选率、边读取、非法中介访问和漏召回。不能只测合法诱导图连通性 |
| F4 属性—几何双空间分区与组织 | 属性树/Trie、几何聚类、分块倒排、分区内图、连续布局 | 语义层级不能自由重排，几何分区又未必属性集中；能否在两者间组织可共享微分区/局部导航，而不复制全部向量 | 固定同一属性、向量和预算，比较属性优先、几何优先及一个明确的混合组织；测命中分区、污染率、局部搜索及对象移动量。不是改K同时重造属性 |
| F5 代理表示与近似候选生成 | 稀疏码、哈希、投影、分桶/倒排、已有允许的近似距离组件 | 能否把原本昂贵的过滤后候选发现转成便宜操作，同时保持原距离精排和高召回；不限定必须是安全下界 | 分开测候选召回、最终召回、资格精确性、代理存储/取得与更新成本；不同范数、零碰撞、新谓词是反例。IGP等现有实现约束仍在，不能默许任意PQ |
| F6 条件几何证书 | box/gap、pivot、范数、联合支持、经典range数据结构 | 过滤是否产生便宜可取得的新增排除证据 | 沿用上一报告E0/E1；只有本族需要同阈值oracle归因。轴界失败不传递给F1–F5 |

学习型路由/执行计划可以作为上述机制的选择器，但不单凭“加模型预测ef”立项；需区别VADER/SIEVE/Quake等，计训练、推理、更新漂移与质量风险。物理布局属于F4的可选研究轴，不预先判定所有布局工作都是工程；仅改对齐/压缩参数而无实质机制与证据时才收窄主张。

## 4. 三个可以展开的具体草案，而非只列索引名

### 草案一：层级—属性资格表示与搜索候选接口协同（F1＋F3）

目录Trie提供稳定scope语义，属性倒排/位图保持共同对象ID，图邻接或搜索批次按局部ID块消费资格。研究重点不是“Trie＋bitmap”，而是如何避免每次构造整个大scope的交集、又不把谓词解释散到每条重复访问的边上。

需给出实际状态：块级支持/精确位图如何表示，哪些层级及属性状态可共享，结果点与导航中介分别如何处理，属性改变后什么状态必须同步失效。只有各原子谓词边际存在不能判交集存在；保守假阳性可以增加工作，不能误删合法候选。

最近前序：Curator按访问区域求值与虚拟标签、ACORN/PathSeer候选扩展、EMA属性摘要。新增差异必须落实为候选消费/共享结构而不只是缓存。即使几何box新增排除为0，该草案仍可能减少资格准备或重复扩邻，但可能因节省占比太小而不值得独立立项。

### 草案二：层级可复用的多属性搜索视图（F2）

一份向量载荷，多个局部导航视图；目录包含关系提供共享机会，额外属性决定局部合格密度。探索部分共享导航层/入口/邻接块而非每个祖先与属性组合建立完整索引。

首先让少数独立视图暴露性能机会，再研究共享能否保住该机会。以“同预算下直接索引集合/共享树”为机制对照，不能只赢一个全局图；所有新增局部图的构建、成员改变与回收计费。

最近前序：ELI、SIEVE、Curator、iRangeGraph、MSG及历史LES。可以复用它们的部件和思想并明确引用；若具体新增是动态层级与交叉属性下新的共享布局/操作或可证明成本差异，仍值得研究。不能靠“层级场景不同”自动认领新意，也不能因为存在索引集合工作就一票否决。

### 草案三：语义层级与几何微分区的联合组织（F4）

不改用户目录语义，在其下或旁边组织几何微分区；普通属性通过posting/bitmap映射到这些分区，分区内复用同一个ANN实现。关注同样的全局选择率下，合法点集中在少量分区与散在所有分区的成本差异。

候选增量可能来自微分区组织、跨层级共享和局部图/入口选择的协同，而不是“做k-means”。必须与属性优先、几何优先及直接分区搜索消融；未过滤query、属性随机/相关、频繁重分类会暴露退化。

最近前序：Curator、Grant、Packing及相关分区式filtered ANN。先核所选具体机制原文；不把这些论文全当成已经实现同一个方案。布局改变前固定属性和查询，避免本轮K32/96各自产生属性的混杂。

## 5. 实验也要拓宽：按瓶颈与工作负载筛选，不再只量box

### 阶段A：六张机制卡，不做六套大系统

每张卡必须给：存储对象/共享粒度、查询走向、更新影响、最近前序的相同点与差异、预期节省的工作、一个失败反例、必要控制、当前状态。新颖性标“待查/部分重合”可以进入小诊断，不能写成已过贡献门。

### 阶段B：至少三个非证书机制族的最小实测

首选F1/F2/F3；若数据/实现路径显示分区问题更明显，可用F4替换其中之一。选择依据是瓶颈，而不是上一个模型偏好。F5先写明确表示/候选策略再做小离线诊断；F6保留已有数据，不要求其他族等待E0/E1。

使用现有WIKI/SIFT小切片，不立即扩到百万规模。工作负载使用下列六种**不同现象**，不是全笛卡尔参数矩阵：

| 场景 | 目的与控制 |
|---|---|
| W0 无普通属性/仅scope | 确认收益与代价来源，不要求所有机制只在过滤条件下有用 |
| W1 宽scope＋较强AND过滤 | 暴露全量资格准备、稀疏合法点导航与视图密度问题 |
| W2 窄scope＋较弱附加过滤 | 防止新结构在简单查询上付出过大固定成本 |
| W3 相同合法数、不同几何/分区分散程度 | 区分选择率与布局/导航难度；报告不能同时匹配的统计，不伪称所有因素受控 |
| W4 不同属性组合＋父子/兄弟scope | 检查共享是否泛化到组合；只在热点缓存命中不能冒称普适结构 |
| W5 短更新窗口前后 | 分别包含属性重分类、目录MOVE及向量插删的小轨迹；校验可见性与更新触达量，不混成吞吐结论 |

这是待执行协议。旧query可作探索，但不可改split后称全新测试；确认阶段须核验未参与路线选择的query/谓词，若没有则明确缺口。属性在比较索引组织前固定；选择率、几何相关性、分区数量不同时改变。语义仍是层级＋多属性硬过滤，不扩成DAG/授权或LLM谓词。

每个机制量自己的主要工作：
- F1：资格准备/消费、posting/bitmap字节、重复判断；
- F2：视图进入/组织、局部搜索、图/向量复用和维护扇出；
- F3：邻接读取、多跳候选、有效距离计算、入口与漏召回；
- F4：命中分区、合法密度、局部访问及移动字节；
- F5：候选覆盖、代理读写、精排成本；
- F6：额外安全排除与证书取得成本。

统一报端到端分项；不能只凭某个计数改善宣称新索引获胜。F1的固定trace回放只证明接口工作量，不证明改变执行顺序后的完整搜索收益；F2独立视图是上限/对照，不能免收初建和更新；F3有限步可达性不等于recall。

### 阶段C：跨族选两个有机会的轻量原型

允许在新颖性待补查时开展受限、可证伪的最小C++原型，不要求先完整证明新算法。但最多保留两个机制不同的候选进行首轮同质量比较；不要只保留“box换gap”“换投影维数”等同族变体。先单因素，单独证据成立后才组合，不自动把六个组件堆进同一系统。

## 6. 公平合同与维护成本不放松

NodeANN仍是主性能基线，正常实现、必要正确性修复和有限校准，不无限优化；每族补一个最近机制的简洁资源匹配对照，不要求先复现全部ACORN/Curator等系统。理论/相关工作仍应比较公开前序，预印本也引用；频繁更新不是排除一切已有结构的理由。

在线C++、固定hnswlib及raw FP32 squared-L2、k=10、macro/pair≥.999、非法/重复/状态错误0。硬资格精确与近似候选覆盖分开。不强迫每个ANN候选策略提供无漏安全证书；只在声称安全/精确剪枝时要求对应证明和数值边界。

内存包括Trie、bitmap/posting、全部图/视图、原向量、代理码、路由/训练状态、日志及峰值；成本包括初建/训练、查询、目录和属性/向量更新、必要回收。把更新作为每族合同，不单独用重建阈值调参替代索引贡献。小scope扫描允许，大scope全扫不能暗中成为主算法；原文使用扫描fallback时只将其作为对应控制，不静默改变用户约束。

## 7. 交付判断应回答什么

不再统一要求“新结构排除了哪些旧box排除不了的点”。改为：
1. 相对NodeANN和最近机制对照，究竟减少了哪类工作：资格处理、候选生成、导航、局部搜索、距离计算还是数据搬运？
2. Trie/bitmap/图等组件分别承担什么职责，新增机制在哪里，哪些明确借鉴前序？
3. 层级与多属性分别对该机制有何作用，去掉其中一项后收益/代价如何变化？
4. 同质量和全维护成本下，变化是否仍有意义？哪些未测、哪些具体实现失败、哪些只是新颖性待查？

本轮交付是扩大后的可执行研究协议，不是六个方案已实现或新颖性已确认。现有WIKI/SIFT证书负结果完整保留，但其外推范围仅限已测机制和设置。
