# 重新确认研究问题与方案，并给出可行路径

本轮不跑新实验。目标是把"在做什么、已经知道什么、还能做什么"重新对齐到可核验的状态，然后给出带证伪判据的候选路径。所有事实均指回已有报告与数据；无新数字。

## 1. 研究问题（重述）

**问题**：属性 DAG（多父、item 直属任意节点）约束下的向量 top-k 检索——给定属性集合 \(A\) 与语义 \(\sigma\in\{\text{direct},\text{recursive}\}\)，用**一张图 + 单一优先队列**返回 top-k，要求在**同召回**下延迟低于 NodeANN（每属性独立完整 HNSW），并使属性/owner 变更的维护代价与子树规模解耦。

三条独立假设，任一条可被单独否定：

| 编号 | 假设 | 已有状态 |
|---|---|---|
| H1 结构 | 跨属性桥在多概念查询（G≥2）下降低延迟；G=1 不降低 | 部分实测，样本量不足 |
| H2 入口/终止 | 与 NodeANN 的剩余差距主要来自入口覆盖与终止条件，而不是边 | 未测 |
| H3 维护 | 把桥的维护单位从 item 降到代表槽，可使单次 owner 变更代价与 \(\lvert members\rvert\) 无关 | 设计完成，未实现 |

**度量**：recall@{10,100}（ties-aware，分母 \(\min(k,\text{eligible})\)）；µs/query（同轮、同核、批内中位）；距离调用；邻接 ID 枚举；有向边数；RSS；单次 owner 变更的距离次数 p50/p95。
**判据**：同召回（±0.005）内时间比 <1.0 支持 H1；≥1.0 否定。
**预算**：单假设 ≤ 4 次运行 ×16 遍；每轮 ≤ 6 h 墙钟；触顶即停。

前提口径：等 k/ef **不是**等召回；不同轮次的构建/缓存状态不可拼接成收益。

## 3. 证据台账

### 成立（可直接引用）

- 数据与结构：168,937 item ×128d FP32；1,929 属性 / 2,040 边 / 103 个多父 / 768 个非空直属属性；owner 随机绑定，非真实语义标注。
- 建图 8.21 s / 7.99 s（两次独立进程）。
- 等 k/ef 对照：recursive 0.675–0.869×，但 Recall 0.977/0.989 vs NodeANN 1.0；direct 1.497–1.713×，Recall 0.999 vs 1.0。
- 工作量：距离调用 101.63/142.18 vs NodeANN 108.15/149.91（更少）；邻接 ID 枚举多 2.1%/8.5%；单属性子集多 25.1%/24.2%。
- G 分组：G=1 全部 NodeANN 更快；G=2 两语义两格我们更快且双方 Recall=1（样本 7/11 条）；G≥3 部分更快但伴随召回损失，含 Recursive G=11 单条 query Recall 0.4/0.57。
- 维护：单次换 owner 定向刷新祖先链，中位 315,392 次距离（p95 509,952），≈73–78 次更新等于一次重建；原因是桥循环按成员遍历。
- 可表达性：744 万次 singleton 与 46 万次复合 scope 的祖先标签 overlap 与 Direct/Recursive OR 资格完全一致（命名空间层面等价，非索引等价）。

### 不成立或已撤回

21.2%/17.7% 的在线成本分解；"按属性布局提速"；packed 分块机制；"距离占大头所以资格检查免费"；"多图一定更快"；"按 G 存在固定交叉阈值"；"合并图内存更省"。

### 未验证（缺一项就不能下结论）

1. **同召回前沿**：recursive 的 0.675–0.869× 是等 k/ef，未做 ef/n 扫描到同召回，Pareto 结论未更新。
2. **S0 对照**：单张全局 HNSW(M=64)+查询期掩码（无 portal、无桥、无合并）**从未在同一 harness 里跑过**。`codes/dag-composition-methods/global_prefilter` 已有按 owner 的 allowed 回调（`dag_composition_method.h:469-470`）和拒绝计数，但 `run_dag_search_perf.sh` 只编译 `dag_merge` 与 `nodeann`。这是当前最关键的空缺：若 S0 在同召回下不慢于合并图，合并机制（MST+桥+portal）在本工作负载上不成立。
3. **G 分层样本量**：Direct G=2 仅 7 条、Recursive G=2 仅 11 条、G≥3 多为单 query。按 G 的任何结论都需要 ≥1k 条分层查询。
4. **更新功能**：`build_variant` 是一次性静态构图，无 insert/delete/relabel；"支持频繁更新"今天不成立。
5. **多父对导航的独立影响**：未单独消融。

### 新颖性状态

与 Stitched、Filtered-DiskANN（OR/多标签起点/共享队列）、LSSG、iRangeGraph、UNG、NGM/IGTM/CGTM、JAG 有直接机制重叠；EMA v1 已把动态更新作为主贡献（属性变更 2.5 s/1M）。**尚未通过创新性确认，也未证整方案重复**；缺的是外部多父 DAG 上"代表汇总 + 桥布局"带来的新导航性质或同质量/同字节优势，不是换术语。

## 4. 可行路径

发散由独立上下文完成（8 张想法卡 + 两两锦标赛），以下为过滤后的路径；每条的机制句不含自造名词。

### P0 归因（前置，约 1 天，必做）

- **机制句**：把 Recall 0.977 的损失拆成"目标的范围内路径上从未出现"（不可达）与"出现过但被队列顺序/掩码/ef 截断丢掉"（被弃）两类，并用"强制访问 GT 邻居"的 oracle 给出该查询的召回上限；同时对边集做三档消融（全桥 / 仅包含边 / 仅不可比边）。
- **前序差别**：现有工作报范围覆盖，不报失败归因；已知前序中未见按"可达/被弃"两分召回损失。
- **证伪判据**：oracle 强制访问后召回上限比现状高 <0.005 ⇒ 损失不在搜索侧，两分法无解释力（H2 否定）。
- **最小实验**：现网搜索加插桩，三档输出（现状 / 关掩码 / oracle）；按"根是否唯一"切两半各扩到 500 条；指标 Recall、距离调用、边数、RSS。
- **风险**：oracle 版污染缓存与计数，需独立进程。

### P1 覆盖终止（若损失主要在"被弃"）

- **机制句**：搜索在队列里记录查询范围内每个非空属性是否已有结果进入前 k，只在全部属性至少命中一次、且第 k 名不劣于未展候选时停止；因为按 ef 截断会让小属性在预算耗尽前一次未被访问，所以 G≥3 召回从 0.977 抬向 1，代价是多展开与属性数成正比的节点。
- **前序差别**：Filtered-DiskANN 的终止仍靠 ef 与拒绝计数，其谓词不可枚举；这里的范围是若干可枚举、互不重叠的属性组，要求逐组覆盖——组可枚举在任意谓词过滤下不成立。
- **证伪判据**：G≥3 召回不升（<0.99），或需 >30% 额外距离调用才换到同样召回 ⇒ 假设错。某档在"全部组已命中"后仍 <1 且 oracle 显示不可达 ⇒ 该档作废。
- **最小实验**：只改停止条件，不动图；1k 分层查询；两格 × 两语义。
- **风险**：不可达的组永远等不到命中，规则退化为跑空队列，延迟明显超 NodeANN。
- **与 H1/H2 的关系**：direct 只有一个组，规则自然退化为普通停止，无需按语义分支。

### P2 代表树（若损失主要在"不可达"）

- **机制句**：建图时给每个属性选一个代表，代表沿每条 DAG 边与其子属性的代表相连，每个 item 只连到自己属性的代表；因为任何属性的后代集合在这套边下连通（多父点的代表同时接多个父代表），所以递归查询从一个入口可走遍范围内所有属性，跨组边从 1.65M 降到约 \(1.8\times10^{5}\)（item 数 + DAG 边数 × 代表数）。
- **前序差别**：NGM/IGTM/CGTM 合并层次图时不保证下闭集合连通；JAG 的单图总度预算不带这条性质；这里把"每个下闭属性集合的诱导子图连通"当作可证构造目标。
- **证伪判据**：**连通可测而召回不动**——若诱导子图 BFS 连通、入口在范围内，recursive 召回仍 <0.95 ⇒ 假设错，连通性不是召回的控制变量。
- **最小实验**：169k 建图约 1 h；逐 G 档比召回、距离调用、边数、RSS；1k 查询。
- **风险**：贪心搜索在连通图上照样可能走不进目标，"连通 ≠ 可搜到"是它自己的证伪点。

### P3 维护解耦（H3，独立轴）

- **机制句**：把桥的维护单位从 item 降到"代表槽"\((c,\text{slot},item)\)，owner 变更只重填受影响属性的槽并刷新祖先链上的槽，计数永不低估（dirty 则停剪枝），因此单次变更代价与子树成员数无关。
- **前序差别**：EMA v1 把属性位或到边上，改值/删除后旧位不在该操作中回收，只能 patch/重建；TrieHI 式元数据层同样不改 ANN 布局，所以"便宜更新"本身不能当贡献，只能与"共享单图的查询效率"组合。
- **证伪判据**：单次变更距离次数与 \(\lvert members\rvert\) 的回归斜率不为 0，或 p95 仍 ≥\(10^{5}\)，或 G≥3 召回 <0.95 ⇒ 假设错。
- **最小实验**：实现 `relabel(owner)` 入口；构造 churn 0/10/50/100% 序列，每档 ≥3 种子；指标 变更 p50/p95 距离次数、与重建的比值、churn 后召回。
- **依赖**：需要 P2 或"只给代表建桥"先行，否则维护单位仍是 item。

### 明确不做的

不再用换术语做新颖性；不再加入口数量/参数（无证据支持）；不重启 packed/量化线；不把 SIMD、布局、并行当贡献。

## 5. 执行顺序与代价

1. **S0 接入**：`global_prefilter` 接入 `run_dag_search_perf.sh` 的 methods 列表，三臂（S0 / dag_merge / nodeann）× 两语义 × 两格，ef 扫描到同召回。这是 H1 成立与否的判据，也是任何比较的前提。约 0.5 天。
2. **P0 归因**：插桩 + 边集三档消融 + 按根唯一性分层扩到 500 条/侧。约 1 天。
3. 由 2 的结论选 P1 或 P2 作为主路径，另一条并入同一篇（分析 + 终止规则 + 构造），避免两篇都只做一半。
4. P3 只在 P1/P2 有正结果后做，否则"便宜更新 + 更慢查询"没有意义。
