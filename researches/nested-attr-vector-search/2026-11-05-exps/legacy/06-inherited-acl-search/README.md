## 问题与权限语义

首版限定树形目录与固定内容快照t，不同时加入DAG多路径。采用显式定义的继承ACL，不宣称等同全部POSIX规则：用户/组集合在授权revision a固定，路径上任一匹配deny优先；存在匹配allow且无deny时允许；无allow则默认拒绝。deny不能被子目录allow覆盖。对象直属ACL作为叶子策略边界处理，组嵌套先由授权服务解析。

**定义1（有效权限）。** 令 $H(v)$ 为根到对象所在节点v的路径，$\operatorname{AllowMatch}_a(u,x)$ 与 $\operatorname{DenyMatch}_a(u,x)$ 表示该revision的策略是否匹配用户u。则

$$
\operatorname{Permit}_a(u,v)=
\left(\bigvee_{x\in H(v)}\operatorname{AllowMatch}_a(u,x)\right)
\land
\neg\left(\bigvee_{x\in H(v)}\operatorname{DenyMatch}_a(u,x)\right).
$$

**定义2（授权前缀集合）。**

$$
S_{p,u,t,a}=\{o:p\preceq s_t(o)\land
\operatorname{Visible}_t(o)\land\operatorname{Permit}_a(u,o)\}.
$$

首版固定当前拓扑t，授权revision a仅描述该拓扑上的策略与组状态；不支持跨历史拓扑复用前沿。未来历史内容读取仍默认使用当前对象授权，必要时逐对象复核；历史权限审计需独立显式API，不允许通过旧快照恢复已撤销权限。t、a通过受信请求生成，客户端不能自行选择过期a绕过撤销。

## 方案

**机制一：编译不交授权前沿。** 为匹配用户/组的策略边界维护有序索引。解析查询p时，沿祖先链计算继承状态，再在p以下只遍历相关策略边界：

- 已有deny：整个子树拒绝，因语义不允许后代覆盖。
- 已allow且子树没有相关策略边界：输出整棵合法子树。
- 存在边界：细分到子目录与当前目录Local，继续携带状态。
- 无allow但后代可能授权：保留边界导航，不输出未授权当前对象。

得到互不相交的目录子树/直属对象集合前沿 $\mathcal F$，满足 $S_{p,u,t,a}$ 等于各前沿范围并集。虚拟分区只是权限表示，不改向量距离。MVP可枚举子目录以保证覆盖，优化版再使用“策略边界Trie＋无边界兄弟范围”压缩，不能把边界查找默认视为常数。

**机制二：缓存前沿，同时保存完整授权依赖。** 缓存键包括稳定scope节点ID、内容/拓扑revision、用户组闭包指纹。每条缓存保存祖先有效策略版本及scope内策略索引的持久化子树根标识，相关策略增删都会改变该根。不能只记旧有策略节点，否则新增deny不会触发失效。

查询读取当前授权根，验证组指纹、祖先依赖与子树根：相同则复用；不同则重编译受影响前沿，最简单安全实现可全量重编译该scope。不重写每个后代对象ACL，但维护边界索引、复制祖先索引节点及缓存重编译都计入更新成本。首版使用COW索引和单写者发布，不声称所有缓存均局部失效。

**机制三：前沿直接驱动过滤。** 对预算内可物化scope生成精确授权bitmap；稀疏访问时保留前沿与成员判定接口，由D0式块消费方式避免完整并集。首版先全量前沿并集，再验证按需执行，防止同时引入多个未知机制。ANN在完整授权scope内搜索，不能先取全局固定top-k再丢弃未授权项。

## 撤销协议与正确性

每次授权更新提交产生单调revision和确认token。请求入场时，在同一线性化的授权根上固定a；完成于提交后的新请求必须读到至少该revision。固定a的在途请求可按原快照完成，这属于**查询入场时授权**语义，不声称响应返回时即时撤销。若业务要求返回前撤销生效，需在返回前重新验证根及依赖，变化则重查；这会引入重试与饥饿风险，单独测量。

需证明：前沿覆盖等于精确权限集合；缓存依赖不变可推出该scope权限结果不变；请求a满足约定的新鲜度。组成员变化必须改变组闭包指纹，不能只依赖目录ACL版本。内容MOVE也改变继承链，必须绑定拓扑revision。

首版安全模型是可信数据库可读取内部向量，禁止将未授权对象、内容和ID返回给用户。不承诺向量距离计算侧信道隔离；若禁止经过未授权向量，需授权范围内导航或扫描，不能直接沿用含非法桥的ACORN/PathSeer式执行。不能把后者悄悄当作同一性能实验。

## 最小实验与停止条件

MVP先固定单用户、树与deny-overrides规则：精确逐对象权限oracle→前沿编译→依赖缓存→同一hnswlib过滤搜索。随后加入组成员变动与并发根发布。数据10K–50K向量，策略边界密度、组数、父目录撤销频率和权限选择率分别变化。

基线：逐对象权限检查、全量展开授权bitmap、版本化全局bitmap缓存、无缓存前沿、依赖前沿；可用Zanzibar/OpenFGA类授权服务另做端到端对照，版本、请求边界和RPC均记录。不直接宣称其具有相同目录规则或原生ANN。

覆盖新增deny、删除allow、组撤销、对象MOVE、旧缓存、在途请求和历史内容。对固定a和入场新鲜度oracle，越权/漏授权均必须零。再报告策略更新写字节、缓存重编译比例、边界数、授权/搜索/P99、召回与Fill。边界密度很高时前沿可退化为逐对象授权；若依赖校验比重新计算更贵，或现有授权集合索引已覆盖全部机制，则收缩工程优化而非宣称新权限模型。
