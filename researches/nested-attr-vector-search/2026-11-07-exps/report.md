# 2026-11-07 实验记录：ASI 与 NodeANN 对齐评测

## 目标

在统一距离实现、线程与查询口径下，核对 ASI/DQS 与 NodeANN 的 top-50 召回和吞吐；定位未命中原始 FP32 真值的追踪阶段。所有结果来自 168,937 个对象、200 条单属性查询；CCS/SciHTC 属性与 SIFT 几何按对象序号绑定，不代表语义相关性。

## 设置

- 128 维 SIFT，平方 L2；PQ($m=16$, 256 码字)还原后的 float32 用于建图和搜索，原始 FP32 用于 GT。
- $k=50$，严格 ID 命中率，8,444 个有效 GT 条目；不是 ties-aware 计分。
- ASI：$M=16,efC=200,p=50,K_{cap}=8,ef_2=16$，$ef\in\{20,30,40,50,80,100,200,400,800\}$。双通道共享查询状态；入口由全闭包 $D$ 内各非空属性最近代表点初始化。单次查询的结果上限是两个 keep 的并集，即 $ef+ef_2$。
- NodeANN：缓存的每属性 HNSW，$M=16,efC=200$，搜索宽度取 $\max(ef,N)$。除原有 $N$ 扫描（$ef$ 固定 50）外，本轮补扫两个维度：$ef\in\{100,200\}$ 且 $N=50$（只加宽搜索），以及 $ef=N\in\{5,10,15,20,25,32,40\}$（搜索宽度与输出预算同时下降）。
- Pre-filter 对 PQ 还原向量做范围内精确扫描。
- CPU 2 单线程；两种图搜索均用 `RawL2Space`，禁用编译器自动向量化及 hnswlib 手写向量路径。主曲线每点 3 个独立进程，每进程 3 批、每批 200 查询；QPS 按总查询数除以总时间汇总。构建、GT 计分、oracle 扫描和诊断 trace 写盘不计入查询时间。

图 5 中每方法只画一条曲线，由全部实测配置按严格支配关系筛选得到；其中满足满容量（ASI $ef+ef_2\ge50$、NodeANN $N\ge50$）的非支配点如下：ASI 六个、NodeANN 一个。NodeANN 之所以只有一个点：$N\ge50$ 后召回已固定在 0.913193，等于 PQ 还原向量上的精确 top-50，即本轮搜索表示的排序上限；继续加宽搜索只增加距离调用（$ef=100$ 为 9,328.5 QPS、$ef=200$ 为 6,746.0 QPS，召回不变），因此都被 $ef=50,N=50$ 支配。原因是本工作负载每个属性平均约 220 个对象（168,937/768），$ef=50$ 已接近穷尽单个属性。

ASI 的容量不足点：$ef=20$ 为 0.474064 / 22,236.8 QPS，$ef=30$ 为 0.640928 / 19,761.2 QPS。中段 ASI 更快（约 0.474 召回时 22.2k vs 19.3k；约 0.65 时 19.8k vs 15.6k）；0.913 顶端则 NodeANN 更快（11.4k vs 5.9k）。两条曲线在 top-50 满容量段的交叉点由上面的表示上限和每属性对象数决定，不能外推到属性更大或选择率更低的数据。

PQ 还原向量 exact top-50 与原始 FP32 GT 有 7,711/8,444 个 ID 重合（0.913193），是表示排序参照，不是近似算法的召回硬上限。互斥操作性归因显示：$ef=50$ 有 664 个 PQ 排序位移、218 个范围内未导航 GT；$ef=200$ 分别为 702、112；$ef=800$ 分别为 724、15。范围内未触达属性、队列拒绝、只参与入口评分及准入后丢失均为 0。该分类按 PQ 参照优先，PQ 位移与导航损失可能重叠，不构成因果分解。

## 结论与限制

当前 ASI 是全闭包多种子、双通道原型，不是 root-only 方案。$ef_2$ 与 $p$ 消融各只有一个进程，不能支持跨种子稳定性结论。当前 JSON 未记录邻接槽位扫描数，距离调用数不能替代槽位成本。工作负载只有单属性查询前缀；不推广到任意多属性 OR、真实语义向量或不同选择率。详细实现边界和图注见 `approaches.md`；参数、数据与程序哈希见 `data/scheme-protocol.json`。

## 下一步

本轮每条 ASI 曲线与两条 NodeANN 曲线的读数差异来自同一个结构事实：平均每属性约 220 个对象，$ef=50$ 已接近穷尽单属性，因此 NodeANN 在表示上限处几乎免费。要检验 ASI 在顶端是否也能占优，需要更大基数的工作负载（1M 扩展或更细的直属标签粒度，使属性平均规模显著上升），而不是继续调参。

分别实现并评估 root-only 入口、单独禁用 $q_2$ 的通道对照；扩展多属性 OR 与不同闭包大小的查询覆盖。需要新增邻接槽位计数后再分析访问开销，不从距离数推断。
