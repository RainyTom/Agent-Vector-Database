# 新方向探索：目录路径可比的跨集合向量连接

状态（2026-10-25）：**仅确定问题背景与定义的研究计划**。未实现、未运行实验，新颖性尚未充分排查。本文是 `01-directory-aware-acceleration` 内的新问题探索，不恢复原 D0“按需块级范围编译”的独立立项决定；原 D0 方案仍见 [README](README.md)。

## 结论与背景

候选问题为 **directory-compatible threshold vector join**：批量找出两个目录化对象库之间，既在同一目录分支、又在向量空间内足够接近的所有对象对。例子是代码仓库的需求/设计片段库 `A` 与实现/测试证据片段库 `B` 的批量对齐。设计文档可能放在模块目录，实现在子目录；也可能实现概述放在模块目录，细节文档在子目录。目录祖先关系给出明确的组织约束，向量距离给出几何相似条件。输出的是待复核的候选对象对，不把几何接近解释成语义等价、需求已满足或证据充分。

这个场景来自 [Directory-Aware/TrieHI v1](https://arxiv.org/html/2606.16903v1) §II–IV 的目录作用域思想，但**查询单位改变**：原文 DSQ 给定一个目录范围和一个查询向量，在范围内做 top-k；这里对两个向量关系执行 threshold join，要求枚举全部合格 pair。它也是项目 A 类的几何 vector join，而非 ANN 单查询的改名。论文目前为 arXiv v1 预印本，正式发表 venue 未核实；预印本状态本身不提供创新性。

## 基本对象与假设

1. `T=(V,E,r₀)` 是两个库共用的有限有根目录树。目录名先解析成**稳定节点 ID**；路径段按顺序匹配，不能用字符串字符前缀代替。例如 `/a/b` 不是 `/a/bc` 的祖先。
2. `A` 与 `B` 是两个对象集合。每个对象 `x` 具有侧内唯一 ID、向量 `v(x)∈Rᵈ`、**唯一规范目录节点** `p(x)∈V`。对象可直接绑定内部节点。两侧向量由相同或可比较的编码空间产生；首版距离为欧氏距离 `d₂`，不预设归一化。
3. 首版目录与向量静态，单机、单命名空间、单路径。一个对象多标签、多路径、跨树映射、MOVE/MERGE、权限与快照语义均需另行定义，不能直接套用以下 pair 计数规则。

## 查询定义

给定目录查询根 `r∈V` 与阈值 `ε≥0`，只考虑双方路径都在 `r` 的含自身子树 `Desc⁺(r)` 内的对象。记 `u≼v` 为节点 `u=v` 或 `u` 是 `v` 的祖先。定义目录兼容性：

`Compat(a,b) := [p(a)≼p(b)] ∨ [p(b)≼p(a)]`。

**精确查询结果**是集合

`J(r,ε) := {(id_A(a),id_B(b)) : a∈A, b∈B, p(a),p(b)∈Desc⁺(r), Compat(a,b), d₂(v(a),v(b))≤ε}`。

结果为有序侧别的 `(A-ID,B-ID)` 对；每对只输出一次。同路径 pair 合法，严格祖先/后代 pair 合法，兄弟目录 pair 不合法；祖先节点上直接绑定的对象不能被当成任意后代节点的直接成员。两侧对象 ID 即使数值相同仍是一个合法跨侧 pair。这里采用 `≤ε`，边界相等需包含。`J` 可为空；没有 `k`，也没有 per-query top-k 或 global top-k 的含义。精确语义要求目录过滤、pair 去重和距离阈值均无误差；后续若研究 approximate join，必须另定义漏报口径与可接受保证。

## 与已知问题的精确边界

| 对象 | 输入与输出 | 与本问题的关系 |
|---|---|---|
| [Directory-Aware/TrieHI](https://arxiv.org/html/2606.16903v1) §II–V | 一个查询向量 + 一个目录 scope → 该范围内 top-k；另研究目录维护 | 目录树及内部节点绑定可借鉴；不支持直接从其 top-k 结果推出全部阈值 pairs。 |
| [Fast Approximate Similarity Join](https://doi.org/10.1145/3725403) §2,4–8 | 跨集合/自连接的近似 threshold pairs，也讨论每查询 kNN | 是 join 主基线；现有本地记录显示其核心模型未含本定义的目录兼容谓词。 |
| [Fast Approximate Vector Joins v2](https://arxiv.org/abs/2603.16360) | 近似阈值 join、工作共享与合并图；作者展望含 filters | 是最接近的后续 join 前序之一；“加入目录过滤”本身不能主张新方法。 |
| [VBASE, OSDI 2023](https://www.usenix.org/system/files/osdi23-zhang-qianxi_1.pdf) §2,4 | 向量查询与关系算子统一执行，讨论 vector join | 系统级对照；本问题必须证明目录结构有可测的增量。 |

## 为什么值得继续定义，但目前不立方法主张

如果逐个 `a` 构造其兼容目录集合、调用范围搜索，再汇总 pairs，就会重复解析范围、访问相关目录和处理阈值输出；如果先将祖先/后代关系摊平成对象对候选，深路径和高密度范围可能产生大量成员复制或无用距离计算。这是**待验证的成本假设**，不是原文报告的 join 实验结果。后续可能研究目录约束与几何剪枝如何联合处理，但 DFS 区间、树上 pair 分解、三角不等式下界、扫描回退均有通用前序，须先逐篇查重。

最小下一步是检查：真实双库数据中是否存在足够多的祖先/后代配对、目录深度与几何相似是否相关、输出密度是否让结果写出成为主成本；随后把 filtered similarity join、hierarchical/dual-tree join 与 predicate-aware batch vector join 的最近正文做逐步骤对照。**本服务器只做文献与方案规划，不执行实验。** 现阶段不能声称新颖性已通过或优于 Directory-Aware/已有 join。
