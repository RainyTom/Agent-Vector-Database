# 效率目标：当前最强候选的耗时分解与超越路径

日期：2026-10-28。定位：**主线是效率、要超越基线；属性更新支持只作动机与补充。** 本轮为既有 CSV 的再分析（未运行新实验），用于把“超越基线”量化成可检验的子目标。

> **进展（同日）：E1 门禁已由 run 14 部分回答。** binary16 tile 影子层 + FP32 精确重排把均值从 1.1275 → **0.8170 ms**、p95 3.55 → **2.35 ms**，recall 保持 1.0/1.0；代价是 RSS 16.0 → 19.8 GiB、构建 5.36 → 9.02 s。详见 §7。

## 0. 结论

1. 当前内部最强候选 run11（`NODE-scope-run`，静态单绑定，精确扫描）为 **1.1275 ms / recall 1.0 / p95 3.55 ms**，已比 NodeANN（6.639 ms，recall 0.999559）快约 5.9×。因此**真正的对手是 run11，不是 NodeANN**。
2. 其耗时**高度集中在尾部**：scope ≥10k 的 33 条查询（14.5%）占 **91.1%** 的时间；单条最坏查询 `qi=397`（scope 925,829）独占 **111.9 ms = 43.7%**。50% 的时间只由 **3 条**查询贡献。
3. 这些大 scope 的有效吞吐稳定在 **28.7–33.9 GB/s**——内核**已经是带宽受限**。推论：继续优化指令/布局的边际收益已很小（run11 vs run12 仅差 2.65% 就是同一信号），**唯一有量级空间的杠杆是降低每个候选的字节数，或证明某候选可跳过**。

## 2. 为什么“再调布局”不行，而“降字节”可以

FP32 下每个候选 4,096 B。以 `qi=397` 为例：

| 表示 | 每向量字节 | 总读取 | 若仍 33 GB/s 的纯带宽时间 |
|---|---:|---:|---:|
| FP32 | 4,096 | 3,792 MB | 112 ms（实测 111.9，吻合） |
| SQ8 | 1,024 | 948 MB | ~28 ms |
| SQ4 / PQ-64×8-bit | 512 | 474 MB | ~14 ms |
| PQ-64×8-bit（64 段） | 64 | 59 MB | ~1.8 ms |
| 1-bit binary | 128 | 118 MB | ~3.6 ms |

**但这只是带宽项**。字节降下来后，瓶颈会转到“每个候选的计算/查表次数”：

- 逐维标量量化（SQ8/SQ4）仍需约 $d=1024$ 次运算/候选，降字节不降运算；
- 乘积量化（PQ，$m$ 段）只需 $m$ 次查表累加，可同时降字节与运算，但需要码本训练与编码；
- 1-bit 码用 popcount，每次比较 64 维，运算量最低。

所以在 d=1024、N≈1e6 的量级上，**（字节/候选，运算/候选，可跳过率）三元组**才是设计空间；不能只报压缩率。

## 3. 效率主线：三项工作，按顺序

### E1（门禁）微基准：先测，再设计

在 926k 级 scope 上，用同一份数据测四种内核的 **ns/候选 与 有效 GB/s**：FP32、SQ8、SQ4（FastScan 风格批量 LUT）、PQ-64、1-bit popcount。

判据：若某表示满足

$$
\frac{\text{ns}}{\text{candidate}}\times N \;+\; \text{重排成本} \;<\; \text{FP32 的 } 112\ \text{ms},
$$

则该表示进入 E2。**若没有任何表示通过，说明该 workload 下量化无收益，效率主线应转向“减少候选数”（E3）而不是压缩。**

这一条必须先做：它决定后面所有设计，且成本远低于任何索引改造。

### E2 两阶段精确扫描（可证跳过）

粗码给每个候选一个**可计算的下界**：若构建时保存 $\varepsilon_i \ge \lVert x_i-\hat x_i\rVert_2$，则

$$
\lVert q-x_i\rVert_2 \;\ge\; \max\!\bigl(0,\ \lVert q-\hat x_i\rVert_2-\varepsilon_i\bigr),
$$

与当前第 $k$ 个精确距离 $\tau$ 比较即可**可证地跳过**该候选；剩余候选做 FP32 精确重排。这样得到的是**精确 top-k**（浮点保守裕度另计），而不是近似——正好匹配 run11 的 recall=1.0，不需要用召回换速度。

代价：每向量多存 4 B 的 $\varepsilon$（1.94M 条共 **7.77 MB**，算术）。收益取决于下界紧不紧，必须实测跳过率。

### E3 减少候选数（若 E1 判定压缩无收益）

同一 scope 内先用廉价摘要（如质心距离、低维投影）排序，只对前 $B$ 个候选做精确距离。注意：本轮已有负结果——**球下界 best-first 只裁掉 9.45% 的向量扫描量**（[§10.3](report.md#103-观测结果)），说明几何剪枝在 1024 维上很松。因此 E3 的前提是先测“要多少候选才能保证 top-10 命中”，若所需比例接近 100%，E3 直接关闭。

**明确不做**：按 scope 大小或选择率切换索引。E2/E3 都是**单一算法**，在所有 scope 上走同一路径，只是候选集合与预算由数据决定。

## 5. 与“更新支持”的关系（仅动机与补充）

更新的作用只有两个，都不进入效率主张：

1. **动机**：若索引把名称或谓词固化进结构，一次改名/MOVE 就迫使重建；这就是“为什么不选静态专用索引”的理由。
2. **补充要求**：新索引必须在 A 类更新（改名）下满足结果逐位不变、且不写向量侧结构（[R1/R2](dynamic-attribute-updates.md#97-修订判据替代-6-的-u2u4)）；B/C 类只需给出维护协议，不承诺性能。

因此效率候选的评估顺序是：先证明快，再证明改名无副作用。**不把维护成本写成主要贡献。**

## 6. 风险与未测

- 未测任何压缩内核的 ns/候选；上表“纯带宽时间”是算术外推，不是结果。
- 下界紧不紧完全未测；若 $\varepsilon_i$ 与真实距离同量级，E2 的跳过率为 0，等于白付 7.77 MB。
- PQ 码本训练与离线编码需要 GPU 侧准备（与[上一轮 GPU 约定](igp-quantization-assessment.md#6-gpu-使用约定与当前可用性)一致），本轮未做。
- 最坏查询 qi=397 的 scope 是 925,829（约全库 48%），这一条本身接近“全库检索”；若它在目标 workload 中属异常值，应在报告里单列，而不是悄悄平均掉。

## 7. 已达成的结果（run 14，冻结 harness 全量 3 次）

**候选**：`ScopeRunIndex` 新增 mode 5——为 tile 布局的 packed payload 建一份 **binary16 影子**（八通道同布局），扫描时用 F16C `cvtph2ps` 换算后照常累加（保留 mode 4 的 64 维共享截止反馈），最后把粗排前 $k+8$ 名按**全局 ID 回到行主序 FP32 base** 精确重算，输出精确 squared-L2。

| 指标 | run11（mode 4，FP32） | **run14（mode 5，fp16）** | 变化 |
|---|---:|---:|---:|
| recursive mean e2e | 1.127503 ms | **0.817029 ms** | **−27.5%** |
| recursive p95 | 3.5477 ms | **2.3479 ms** | −33.8% |
| recursive macro / pair recall | 1.0 / 1.0 | **1.0 / 1.0** | 不变 |
| non-recursive mean | 0.00315 ms | 0.00619 ms | +96%（仍 < 0.025 门槛） |
| build | 5.36 s | 9.02 s | +3.7 s（fp16 转换） |
| peak RSS | 16,032 MiB | 19,824 MiB | +3.87 GiB（影子层） |
| 3 次离散度（MAD） | 0.0086 ms | 0.0314 ms | 变大，仍远小于均值差 |

判定依据：冻结评估器用独立 NumPy GT 核对实际返回 ID；recall 仍为 1.0，说明加速**没有**用召回换。日志置信度 8.9× 噪声底。

**为什么有效**：run11 的大 scope 传输速率实测 28.7–33.9 GB/s，已贴带宽上限；fp16 把每候选字节从 4,096 降到 2,048，指令数不变（一次 `cvtph2ps` + 一次减法 + 一次 FMA，仍是 8 路），因此尾部直接受益。

**过程中修掉的两个真实 bug**（都有回归证据）：
1. 首次实现用 tile 布局的 `packed_` 做重排——tile 不是行主序，取到的向量错位，2000×64 fixture 上 hit 从 10/10 掉到 3/10。改为按全局 ID 读调用方的行主序 base。
2. 空 scope 使 `capacity==0`，`filled == capacity` 立即成立并读空 vector 的 `coarse[0]` → SIGSEGV（run 13 exit 139）。

**代价与已知退化**：non-recursive 均值翻倍，来自每次调用的两个小 vector 分配与 18 元素排序；绝对量 6.2 µs 仍在门槛内，但它是下一个免费优化点（栈上缓冲/线程局部复用）。

**下一步（尚未运行）**：fp16 只减半字节；按 §2 的表，2-bit 残差码理论上是 16×、PQ-64 是 64×。但字节降下来后瓶颈会转到解码运算，所以 §3 的 E1 微基准仍需先做，且必须先验 §2 的 $\varepsilon_i$ 下界是否足够紧——否则只是把带宽换成了更多运算。更新支持仍只作动机。
