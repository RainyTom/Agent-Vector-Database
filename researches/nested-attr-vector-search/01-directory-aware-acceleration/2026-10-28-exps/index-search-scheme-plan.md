## 1. 目标与非目标

**目标**：在层级目录约束的 top-k（DSQ）上，以**建图或搜索的算法改动**取得比 NodeANN、PE-Online/PE-Offline（含其精确形态）更好的 recall–延迟曲线；同 recall 下更快，或更高 recall 下同样快。

**非目标**（明确排除，且不作为贡献声明）：
- SIMD 内核、转置/打包等物理布局、字节压缩——只能作为共同基建出现，且在消融中保持不变。
- 按数据集规模或选择率切换索引。
- 属性更新的性能贡献（仅作动机：把名称/谓词固化进结构会在改名或 MOVE 时逼重建）。

## 2. 证据前提（全部为本项目实测，不是假设）

| P2 | 同一过滤 HNSW 在大 scope 上可用 | 0.463（1k–10k）、0.758（≥10k） | 同上 |

**由 P1–P4 得到的核心判断**：小 scope 的问题是**走不到**（可达性），大 scope 的问题是**不能靠剪枝少走**（只能用图的候选生成）。两者都指向同一个东西——图的**连通性**，而不是剪枝强度或距离预算。

## 3. 索引结构

三个组件，全部按节点 ID / eID 组织，**不含名称**（改名零成本，见 §7）。

### 3.1 基础邻近图 $G_0$

- FAISS `IndexHNSWFlat`，M=16，efConstruction=200，一次 `add` 全部点（分块会得到不同图实例）。
- 第 0 层邻接以 tile/CSR 形式只读暴露；层 ≥1 仅用于入口下降。
- 与既有基线**同一构造参数**，因此任何差异不来自图参数。

### 3.2 层级连接边 $E_{\text{conn}}$（建图侧创新）

对每个节点 $u$，令簇集合 $\mathcal C(u)=\{L(u)\}\cup\{S(c):c\in\text{child}(u)\}$，每簇取组合式代表点
$r_{\text{up}}(u)=\arg\min_{x\in K(u)}\lVert x-\overline{S(u)}\rVert,\;K(u)=\{r_{\text{loc}}(u)\}\cup\{r_{\text{up}}(c)\}$，
在各代表点上按欧氏距离建 Prim MST，加入 $|\mathcal C(u)|-1$ 条边。

- 已测：$|E_{\text{conn}}|=n-1$（等号，与定理 1(ii) 一致），占 M=16 粗略边预算 6.25%。
- 性质（已证）：对任意目录 $u$，$G_0[S(u)]\cup E_{\text{conn}}$ 连通；非空 scope 不会返回零结果。
- **已知弱点**：新增度数最大 66。度数上界是设计上要压的指标，见 §3.4。

### 3.3 每节点入口 $r_u$

递归查询用 $r_{\text{up}}(u)$（子树代表点），非递归用 $L(u)$ 首元素。入口必在 scope 内，否则报错而不是回退到全局入口——避免"入口不可达"被掩盖。

### 3.4 度数受限的连接边（建图侧第二个候选，待验证）

现状 MST 可能给根附近节点 66 条新增边。备选：按度数预算 $D_c$ 做**受限 MST**（Kruskal 按边权排序，跳过会使端点超预算的边；不连通时用最便宜的跨簇边补齐）。这是构造算法改动，代价与收益都可测：

- 指标：$\max$ 度数、$E_{\text{conn}}$ 实际条数、G1 连通性（必须仍 100%）、G2 召回。
- 判据：度数降到 ≤16 而 G2 不降 → 采用；若连通性破坏 → 放弃。

## 4. 搜索算法

### 4.1 主过程：scope 受限、代价封顶的最优优先遍历

```
search(q, u, rec, k, ef, E):
    iv   = rec ? [lo[u], hi[u]) : [lo[u], lo[u]+nloc[u])     # O(1)
    if iv.card == 0: return {}
    s    = r_u                                                # 必在 iv 内
    C    = {s};  B = {s};  visited = {s};  evals = 1
    while C 非空 and evals < E:
        v = argmin_{c∈C} d(q,c);  C -= v
        if |B| == ef and d(q,v) > max_{b∈B} d(q,b): break      # 经典停止
        for w in adj0(v) ∪ adjConn(v):
            if w ∈ visited or w ∉ iv: continue                 # 边两端都必须合法
            visited += w;  evals += 1
            if |B| < ef or d(q,w) < max_{b∈B} d(q,b):
                B += w;  C += w;  if |B| > ef: B -= argmax
    return topk(B ∩ iv, k)
```

三个要点：

1. **自然自适应，不是切换**：|S| 很小时，遍历会在访问完 scope 内全部节点后因 $C$ 空而终止，代价 $\Theta(|S|)$，与扫描同阶；|S| 大时由 $E$ 与 $ef$ 封顶。同一个循环，没有"按 scope 大小选算法"的分支。
2. **合法性检查在边上而非结果上**：$w\notin iv$ 直接不扩展，避免"过滤发生在结果侧"的候选浪费。
3. **连接边只补可达性，不携带谓词**：属性/名称变化不改变任何边。

### 4.2 停止条件与精确性阶梯

- **$E=\infty$ 且 $ef=|S|$** ⇒ 退化为 scope 内精确 top-k（在连通性成立时）。
- **有限 $E$ / $ef$** ⇒ 近似；召回随 $E$ 单调（待验证）。
- 因此"精确/近似"不是两个索引，而是同一搜索的两个端点——这一点必须在实验里用同一份代码验证。

### 4.3 参数策略（推导，不拟合）

两级：

1. **$ef$ 由目标召回反解**：用项目已有的"标准化 margin 分箱翻转率"框架（arXiv:2609.09854 §8.2 的度量方式），在**校准查询集**上测 $ef \mapsto$ recall 曲线，拟合为 $\text{recall}=1-c\,ef^{-\beta}$，给出
   $ef^\*(ρ)=\lceil (c/(1-ρ))^{1/\beta}\rceil$。$\beta$ 由数据决定，不是手调常数。
2. **$E$ 由 scope 规模给出**：$E=\lceil \alpha\,|S|^{\gamma}\rceil$，$\gamma$ 从同一批曲线拟合；$\gamma=1$ 即退化为扫描，$\gamma<1$ 才是亚线性证据。**$\gamma$ 本身就是本方案的核心结论**——它必须由实测给出，而不是假设。

不使用学习型预测器（避免与 VADER 的重叠）；若解析式拟合失败，则如实报告"参数只能按表"，并说明这削弱了方案。

## 5. 正确性与召回语义

| 命题 | 状态 |
|---|---|
| 任意 scope 的诱导子图连通（含 $E_{\text{conn}}$） | **已证**（定理 1），待 G1 实测确认 |
| 非空 scope 不返回零结果 | **已证**（命题 4），前提是入口在 scope 内 |
| 有限预算下召回有下界 | **不提供**；连通性不蕴含跳数或召回（命题 3 已给反例） |
| 精确模式（$E=\infty, ef=|S|$）返回真实 top-k | 在连通性成立且边合法时成立，待 G2 验证 |

明确不写"连通 ⇒ 召回"这种推论；召回一律用冻结 GT 实测。

## 6. 创新主张与逐项前序

| 我们的改动 | 最近前序 | 可辩护差异 |
|---|---|---|
| 连接边按**目录子树**共享构造，$|E_{\text{conn}}|=n-1$ | StitchedVamana（按标签拼子图）、ACORN（两跳放宽）、iRangeGraph（区间专用图）、TFANNS/UNIFY（含性） | 前序不保证**任意子树**的诱导子图连通，也不共享同一份边集；本方案一份图服务所有 scope |
| 搜索在**边上**做合法性判定 + scope 常驻入口 | Filtered-DiskANN/ACORN 沿途判定谓词、入口仍取全局 | 入口不可达被结构性消除（命题 4），而不是靠更大预算 |
| 度数受限的受限 MST | 经典 degree-bounded MST | 在"共享连接边"语境下的度数–召回权衡，需实测 |
| 参数由曲线反解（$ef^\*,E$） | VADER（GBDT 预测 + 早停）、Quake（概率分区 + 估计召回停止） | 不做学习预测；用解析式从校准集反解，且只作用于**同一份结构** |

**不声称**：新的连通性定理范式（RNSG 已更强）；不声称"用 HNSW"是贡献。

## 7. 与更新动机的关系（不进贡献）

名称不进入任何结构（键为 eID/节点 ID），因此 A 类改名对索引零写入；连接边只依赖拓扑与几何，改名不动边。这是次要约束，用来论证"为什么不选把谓词固化进结构的方案"，不作为性能主张。

## 8. 复杂度与预期位置

- 建图：$G_0$ 同基线；$E_{\text{conn}}$ 实测 90.8 s（12 线程）。空间：$E_{\text{conn}}$ 约 15.5 MB（每条 2×uint32）。
- 查询：$O(E\cdot M)$ 次距离评估 + 每次 $O(1)$ 区间判定；最坏退化为 $O(|S| d)$。
- 预期（待验，不作承诺）：大 scope 由 $E$ 封顶，若 $ef^\*$ 在高选择性下较小，则可低于扫描的 5.1 ms；小 scope 因 $\Theta(|S|)$ 退化而与扫描同阶。

## 9. 评测协议

**基线（同机、同 workload、同 k、单线程）**

| 基线 | recall | 延迟 | 备注 |
|---|---:|---:|---|
| NodeANN（局部 HNSW ef64） | 0.999559 | 6.639 ms（3 次） | 需补 ef 扫描形成曲线 |
| TrieHI + PG-HNSW ef2048 | 0.212 | 20.09 ms | 需补 ef 扫描 |
| TrieHI + IVF np256 / np1024 | 0.467 / 1.0 | 6.77 / 25.13 ms | np1024 为精确形态 |
| 精确 scope 扫描（现最强） | 1.0 | 0.817 ms（3 次） | 工程基建，用以界定"算法是否真的赢" |

**同 recall 比较**：在 recall $\in\{0.99, 0.995, 0.999, 1.0\}$ 四档上比延迟与 p95；不比较单点。

**消融（用于排除工程归因）**

| 对照 | 固定的东西 | 唯一变量 | 归因 |
|---|---|---|---|
| A1 | 图实例、ef、搜索代码 | `connectors on` vs `off` | 连接边是否有效（建图侧） |
| A2 | 图实例、连接边、ef | 入口：$r_u$ vs 全局入口 | 入口策略（搜索侧） |
| A3 | 全部 | $E$ 封顶 vs 不封顶 | 预算策略（搜索侧） |
| A4 | 布局与 SIMD 内核 | 图搜索 vs 扫描 | 候选生成方式（算法） |

A1–A3 的增量必须只有在算法改动存在时才出现；A4 用同一份扫描内核保证布局/SIMD 不参与归因。
