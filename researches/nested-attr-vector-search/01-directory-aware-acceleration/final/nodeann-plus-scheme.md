# NodeANN+ ：属性 DAG 上的单层局部图 + 唯一入口 + 可证合并（2026-11-05）

本文件是**方案规格**（不是实验记录）。基线冻结见 `baselines-frozen.md`；实验数字写进各自的 `report.md`。

## 0. 目标与硬不变量

| 项 | 规定 |
|---|---|
| 目标 | 在 NodeANN（每概念独立图）基础上，让"同一子树下的 item"能被**一次搜索**快速触达，而不是每概念各出 top-N 再归并 |
| 不变量 I1 | **单队列**：一次查询只有一个候选队列；不得以"每概念 top-k 再合并"作为主路径 |
| 不变量 I2 | **唯一入口**：任一属性节点的搜索都从该节点的入口倒排项进入，不从随机点进入 |
| 不变量 I3 | **结构跳过 vs 谓词跳过分离**：`own(v) ∉ E` 的节点不访问、不算距离（结构跳过）；合格但不进结果的仍参与导航（谓词跳过） |
| 不变量 I4 | 计数永不低估；无法同步时标 dirty 并停剪枝 |
| 不变量 I5 | 文档只写当前正确版本，历史差异留给 Git |

## 1. 结构

```
concept c ──► 局 部 图 G_c（单层）: items with own(i)=c
          │
          ├─ 入口倒排 entry[c] = 1..k 个入口（默认取中位点或代表点）
          ├─ 代表点集 rep[c] = farthest-first 选出的 K 个点
          └─ 骨架 MST[c] = rep[c] 上的最小生成树（按距离）
跨节点 ──► 门户桥 bridge(c→child)：父子图之间的有向桥（保留边，不重剪）
校验   ──► bitmap[c]（祖先/后代闭包）、bloom[c]（邻接级否定）
```

- **item 唯一归属**：`own(i)` 单一 owner（当前数据满足）。
- **局部图**：每概念一张图，节点只在该概念内部连边（保边，不跨概念重连）。
- **入口倒排**：`entry[c]` 是数组而非单点——代表点同时也是入口候选；查询按"距查询最近的代表点"选入口。
- **MST 的作用**（避免"处理得太简单"）：MST 不是查询结构，而是**跳转的骨架**。给定入口 `e`，MST 上从 `e` 到目标代表点的路径给出**有序的中间代表点序列**，用于：(a) 递归搜索时按路径顺序向子节点跳转；(b) 非递归搜索时限制跨概念跳转的方向，避免在图上盲目跳。MST 保证任意两个代表点之间存在唯一有序路径，因此跳转代价有上界 `O(直径)` 次桥接。

## 2. 单层图 vs 多层图：实测与判断

实测（168,937 对象，PQ 还原向量，k=50，ef=50，200 查询，4.2 个概念/查询，M=16，标量距离）：

| 概念内索引 | N=10 recall / QPS | N=60 recall / QPS | 每概念搜索 |
|---|---:|---:|---:|
| 单层（精确 M 近邻 + 对称化 + 组件桥接） | 0.3651 / 9,340 | 0.9101 / 9,446 | 25.5 µs |
| 多层（hnswlib，M=16, efC=200） | 0.3668 / 19,020 | **0.9132** / 16,450 | **12.5–14.5 µs** |

**判断**：

1. 两者在召回上**没有实质差别**（0.9101 vs 0.9132，差的是 0.3 个百分点）；差别在**每概念 25.5 vs 12.5 µs**。
2. 这个 2× 差距**不是层数造成的**，而是两个实现差异：(a) 我的单层用"精确 M 近邻"构图，缺少增量插入 + 启发式剪边，图的可导航性差；(b) 我的 visited 用 168k 长的 stamp 数组（每次搜索随机访问），hnswlib 用紧凑 visited pool。
3. 结论：**层数在本规模（每概念中位 70、均值 220）上是次要因素**，multilayer 的 `max_level≈2` 只多几个节点；决定性的是**构图质量 + visited 结构**。因此：
   - **采纳单层**（更简单、无层级参数、入口即代表点，符合"唯一入口"设计）；
   - 但单层必须满足两个前提：**增量插入 + 启发式剪边**（而非精确 kNN 图），以及**紧凑 visited**（按查询复用的小数组）。
   - 已预注册的验证：单层（增量插入 + heuristic prune）vs 单层（精确 kNN）vs hnswlib 多层，三臂同召回比 QPS；若单层增量版不能追上多层，则退回多层。

## 3. 两种执行模式（同一入口）

| 模式 | 入口 | 路径 | 适用 |
|---|---|---|---|
| **非递归（局部）** | `entry[c]` | 只在 `G_c` 内搜索，`own(v)≠c` 的邻居结构跳过 | 单概念/窄范围查询；此时它就是"属性节点局部空间内搜索" |
| **递归（自上而下）** | 根/最小覆盖节点的 `entry` | 在 `G_c` 内搜到代表点 → 沿 `MST` 有序跳转到子节点入口 → 进入子图继续 | 跨子树查询；MST 提供跳转顺序，避免在扁平图上盲目跨概念 |

两种模式的切换由范围解析决定：`|D|=1` 走非递归；`D` 覆盖多个概念时，若这些概念**同属一条祖先链**则递归（沿链下降），否则退化为"入口集合上的并行局部搜索 + 单队列合并"。

## 4. 合并逻辑：候选与文献依据

| 候选 | 机制 | 文献 | 与我们的差别 |
|---|---|---|---|
| **S0 无合并（NodeANN）** | 每概念图各出 top-N 后归并 | 本项目冻结基线 | 违反 I1（多队列） |
| **S1 Stitching** | 各子图构建后按距离互连边，再剪枝到度上界 | Filtered-DiskANN / StitchedVamana，WWW 2023 | 其剪枝按"标签子集"；我们按 `own` 分区且**不重剪**（保边） |
| **S2 Navigating graph** | 每 label-set 一张图 + 一张导航图连各组 | UNG（Cai et al., 2024） | 我们的谓词是**可达闭包**（多概念），不是 label set；导航图即"代表点 MST 骨架" |
| **S3 门户桥（保边合并）** | 父子图之间加有向桥，子树内边一条不减 | 本项目 v6 规格 | 目标是"子树内快速访问"，桥的选择由 MST 决定 |
| **S4 共享代表点层** | 用小图/代表点做全局路由，再下沉局部图 | 本项目 v4/v8 的入口层 | 与 S3 可叠加：代表点同时作为桥端点 |

**选择依据（不是二选一，而是分层）**：
- **局部层**：S0 的局部图保留（每概念一张，保边）。
- **跨层**：S3 门户桥 + S2 的骨架 = MST 桥接。理由：闭包谓词要跨多个概念，纯 stitching（S1）会因"不同概念的向量分布不同"产生大量无效边并需要重剪，破坏"保边"不变量；UNG 的 label-set 图不适用于闭包（查询覆盖的概念集不是预定义集合）。
- **失败判据（预注册）**：若 S3 在等召回下 QPS 不优于 S0，则"门户桥"因子无效；若 S2（MST 骨架）在递归模式不优于"直接枚举入口"，则 MST 无价值，退化为入口集合。

## 5. 属性校验结构

| 场景 | 结构 | 成本 | 何时启用 |
|---|---|---|---|
| 概念数 ≤ 8k | `Anc`/`Desc` 位图（V/8 字节） | 1,929 概念 → 242 B/图 | 默认（当前数据） |
| 概念数 > 8k | 排序 `concept_id` 数组 + 64-bit Bloom | 每概念 ≤ 8 B + O(log) 查 | 大本体 |
| 邻接级否定 | 每节点 64-bit 签名（2 哈希） | 8 B/节点 | 跨概念桥接后，避免进入无关子图 |
| 多属性（tenant） | 每 tenant 一组位图 + 共享图 | 位图 × tenant | 属性特别多的场景 |

校验只做**否定判断**（"这个邻居不可能合格"才跳过），不做肯定判断，保证不漏答案。

## 7. 未决与风险

- **单层增量版的构造质量**尚未实测（本轮只测了"精确 kNN 单层"），这是 P1-P4 的前置。
- MST 的 K（代表点数）需要与概念规模挂钩（如 `K=min(64, ⌈√n_c⌉)`），当前未定。
- 桥的度数上界（`pcap`）与"保边"冲突时，用**双向计数与 dirty 标记**兜底，不给下界。
- 本方案的"新"限于**组合**：单层局部图 + 唯一入口 + MST 骨架跳转 + 闭包谓词。StitchedVamana / UNG / 门户桥各自已有前序，完整组合尚未见同构工作，但未做穷尽检索。
