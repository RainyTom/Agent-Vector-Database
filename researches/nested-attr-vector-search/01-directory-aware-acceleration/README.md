# Directory Aware的按需块级范围编译与执行加速

> **2026-10-26 选择率诊断。** 在 SIFT100k + CCS 形状层级上测量了属性过滤选择率 $s$ 对精确扫描、FAISS BF-HNSW、post-filter 与目录解析成本的影响：交叉点约 $s\approx0.06$（1M 上左移到约 0.0194），HNSW 维持 r95 的 `ef` 在 100k 约按 $s^{-0.77}$、1M 约按 $s^{-0.67}$ 增长，TrieHI 解析约 1 µs、PE-Online 子树 OR 在高 $s$ 达 933 µs。见[当日报告](2026-10-26-exps/report.md)。这是测量诊断，不恢复本方向的独立新颖性主张。补充：cluster 相关谓词下，HNSW 在 $s\le0.3$ 即使 `ef=32768` 也只有 50–87% 召回，随机谓词的 0.06 交叉点不能外推到相关属性；PathSeer filter-aware 基线在 ef≤4096 也未达 r95。但同一可行集把查询移到簇中心后，HNSW 用 ef=32 在 s≥0.03 胜出（召回 98–99.5%），说明决定因素是相关性方向；属性分区 flat 布局与只 gather 可行点的分区布局也都只在 s=0.3 略胜精确扫描。新增选择率动机实验：在 1%–30% 网格上，FAISS BF-HNSW 固定 ef 的召回随 s 崩塌，维持 r95 的 ef 约按 s^-0.60 增长，交叉点约 s≈0.065（1M 上左移到约 0.023）；见 [动机实验](2026-10-26-exps/experiments/motivation-selectivity.md)。

## 问题与动机

TrieHI已支持递归与非递归查询，不能再次把Trie解析作为创新。拟优化的具体成本是：范围表达式必须生成多少、在哪种粒度生成，以及ANN仅访问部分ID时能否避免准备未访问区域。原文§V-E的深目录PG遍历开销不全来自scope生成，本方向只优化可隔离的范围及过滤部分。[Directory-Aware §III–V](https://arxiv.org/pdf/2606.16903v1)。

**定义1（精确范围表达式）。** 递归范围 $S_v=\operatorname{Inc}(v)$；非递归范围为

$$
S_v=\operatorname{Inc}(v)\setminus
\bigcup_{w\in\operatorname{child}(v)}\operatorname{Inc}(w).
$$

这是已有语义。不假定原TrieHI另存Local；显式物化Local是计入空间的基线。

**定义2（块与访问批次）。** 将稳定ID域分成大小b的块 $B_j$，不按DFS重编号。ANN提交候选ID批次 $A_t$，范围执行器准确返回 $A_t\cap S_v$。块可对齐Roaring container或取其子块。

## 方案

**机制一：编译范围计划，按访问块兑现。** 查询固定拓扑/bitmap revision，编译Inc及必要child-Inc负项。首次触及块j时，从三种等价策略中选择：

- 对本批次各ID直接执行表达式成员测试，不构造块结果。
- 精确计算 $S_v\cap B_j$ 并缓存，后续批次复用。
- 对热点非递归目录读取预算内物化的Local块；其余继续执行表达式。

空块、全合法块、混合块均须由精确运算证明，不能用采样命中率推断。缓存键为“目录ID、查询模式、revision、块ID”；未知不当作空。递归查询Inc可直接读取时退化为原生成员测试，不额外物化。

**机制二：实际复用决定编译粒度。** 设每ID直接判定成本 $c_e$，物化块成本 $c_m$，缓存后判定成本 $c_b$，预计后续访问数r。仅当

$$
r(c_e-c_b)>c_m+c_{\mathrm{cache}}
$$

且满足缓存预算时物化。r来自历史和本次访问，只决定性能，不参与合法性证明。以不同上/下阈值抑制反复转换；估计开销计入。短查询可以一直直接测试。

**机制三：融合批量过滤。** 在C++内批量获取资格位；全合法批次直接消费，混合批次使用精确掩码。底图若允许不合法对象作桥，不能因块不合法擅自跳过导航距离或出边。首版保持候选顺序和原停止规则，隔离范围处理收益；重排及PathSeer再profile另做消融。

~~~text
FilterBatch(plan, ids):
    按块组织ID引用，保留原输出次序
    对每个实际触及块：
        有相同revision缓存则读取
        达到盈亏阈值则精确计算该块
        否则仅对请求ID做精确表达式测试
    按原次序返回资格位
~~~

## 正确性与成本

三种策略计算同一批次交集，相同候选顺序下应逐位等价；这不是ANN召回提升定理。重复ID、尾块、空目录、根目录均处理。更新首版用全局epoch失效；旧读者持有旧集合，不能混用新负项和旧缓存。MOVE沿用原系统，不声称只改指针或常数耗时。

若访问t块，至多物化这些块。最坏仍访问全域；表达式测试可能比现成Roaring融合运算更慢。计划、块目录、缓存全部计入总字节。

## 前序与候选创新

| 前序 | 已有机制 | 需验证的增量 |
|---|---|---|
| TrieHI §III–IV | inclusive集合与目录表达式 | 按ANN实际访问兑现表达式；简单递归查询允许零优化 |
| [CRoaring](https://github.com/RoaringBitmap/CRoaring)，官方实现 | 压缩容器、高效集合运算 | 容器压缩不新，必须比较原生成员测试和融合ANDNOT |
| [Curator §4.2](https://arxiv.org/abs/2601.01291) | 临时视图、延迟构建 | 固定语义ID块上的精确表达式消费，不是重建几何树 |
| [PathSeer §4–5](https://doi.org/10.1145/3802098) | 成本profile与邻居处理策略 | 不把成本自适应当新意，先固定候选规则独立测量 |

候选贡献是ANN消费轨迹约束下的范围编译器，不是一般缓存。需补查selection vector、向量化表达式执行、sideways information passing和自适应物化是否已覆盖这一决策接口。

## 最小实验与停止条件

MVP：readonly Inc/ANDNOT接口→块级缓存和阈值→hnswlib C++批量接口。一个参数化runner输出逐查询JSONL，本轮没有实现或结果。

10K–50K向量，深度2/8/16、分支数2/16/64，递归/非递归、冷热缓存、路径相关/独立分开。基线为原生Inc、整体ANDNOT、直接表达式、物化Local、无控制器lazy块、完整方案；缓存预算一致。首先核成员位及固定候选序列的最终结果完全一致。

报告scope、过滤、搜索和端到端P95，访问/物化块数、重复访问、总内存、构建与失效成本。若瓶颈在距离和遍历，或Roaring原生操作已覆盖收益，则不作为独立算法贡献；可保留为D2/D5组件。
