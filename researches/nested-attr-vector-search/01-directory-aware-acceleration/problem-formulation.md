# Problem Formulation：文件目录约束下的跨集合向量连接

## 应用背景

大型代码仓库通常按产品、模块和子模块组织文件。一个模块目录下可以同时存放设计文档、源代码和测试文件；概述文档也可能直接放在模块目录，而具体实现位于更深的子目录。例如，`/repo/payments/` 下的设计说明与 `/repo/payments/api/` 下的实现片段属于同一目录分支，`/repo/payments/billing/` 与 `/repo/payments/search/` 中的片段则属于不同分支。

考虑对仓库中的两类文件内容做批量关联：集合 A 包含设计文档的文本片段，集合 B 包含代码或测试文件的片段。每个片段既有内容向量，也继承其所在文件的目录位置。关联结果需要同时满足目录约束和向量距离约束：目录约束限定两个片段是否处于可比较的模块范围；向量距离在该范围内筛选相近片段。结果是供后续分析的候选片段对，向量接近本身不证明代码实现了文档要求。

[Directory-Aware/TrieHI](https://arxiv.org/html/2606.16903v1) §II–IV 使用文件目录树表达单次向量检索的作用域。本问题沿用目录树背景，但查询对象变为两个片段集合：给定距离阈值，输出所有同时满足目录关系和距离条件的跨集合对象对，而非对一个查询向量返回目录内的 top-k。

## 数据模型

目录结构为有限有根树 T=(V,E,r₀)。每个节点代表一个目录，父子边代表直接包含关系。目录路径由完整路径段确定；因此 `/repo/payments/api` 是 `/repo/payments` 的后代，`/repo/payments/api-v2` 不是 `/repo/payments/api` 的后代。

A 和 B 是两个片段集合。每个对象 x 有侧内唯一标识 id(x)、d 维向量 v(x)∈ℝᵈ，以及唯一的所属目录节点 p(x)∈V。片段可以直接属于内部目录中的文件，不要求只出现在叶目录。两侧向量位于同一可比较的表示空间。这里的目录树和向量均为静态；距离函数固定为欧氏距离 d₂。

记 Desc⁺(u) 为包含 u 自身的后代节点集合；记 u≼v 表示 u=v 或 u 是 v 的祖先。两个对象的目录路径**可比**，当且仅当

Compat(a,b) = [p(a)≼p(b)] ∨ [p(b)≼p(a)]。

可比性允许同目录及祖先—后代目录配对，不允许兄弟目录配对。它是明确的目录过滤条件，不是语义相似度的近似判定。

## 查询与输出

查询 Q=(r,ε) 包含一个目录范围根 r∈V 和距离阈值 ε≥0。双方对象都必须位于 r 的子树内。精确结果定义为

J(Q) = {(id_A(a),id_B(b)) ∣ a∈A, b∈B,
        p(a),p(b)∈Desc⁺(r), Compat(a,b),
        d₂(v(a),v(b))≤ε}。

每个结果是带有 A/B 侧别的有序对象对 `(A-ID, B-ID)`。同一对只输出一次；两侧 ID 的数值相同不影响其作为跨集合 pair 的身份。距离恰为 ε 的 pair 包含在结果中。若没有合格 pair，结果为空。

这是 **cross、threshold、exact** 的几何向量连接。输出要求覆盖全部且仅有合格 pair；它既不是每个 A 对象的 k 近邻集合，也不是全局 top-k pairs。当前模型限定一个共享目录树和每对象一条规范路径。多路径标签、跨树目录映射、目录移动和版本可见性会改变目录谓词或对象身份，需在扩展模型中另行定义。
