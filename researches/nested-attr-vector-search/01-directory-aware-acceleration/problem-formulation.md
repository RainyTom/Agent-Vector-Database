# Problem Formulation：层级品类与多维属性约束下的跨平台向量连接

## 问题背景

商品目录有两种不同的组织关系。**品类本身有层级**，例如“鞋类 → 运动鞋 → 跑鞋”；浏览者可以从上级品类进入下级品类。**品牌、颜色、尺码是筛选面（facet）**：在“跑鞋”范围内可以先选品牌再选尺码，也可以先选尺码再选品牌，两种顺序得到相同的商品范围。[OpenSearch 文档](https://docs.opensearch.org/latest/tutorials/faceted-search/)分别介绍了品牌、颜色、尺码等 facet 过滤，以及“Category → Subcategory → Product type”的 hierarchical faceting。它们是两种可组合的导航方式；普通 facet 本身没有“品牌甲是尺码 42 的子节点”这类层级含义。

跨平台商品目录中的记录粒度还可能不同：平台 A 把一件商品放在“运动鞋”品类，标有品牌但缺少尺码；平台 B 放在其下的“跑鞋”品类，标有尺码但缺少品牌。两条记录的品类有祖先—后代关系，已知属性也不冲突，因此可进一步比较商品描述或图片向量。若两侧已知品牌分别为甲和乙，则即使向量很近也不满足目录兼容条件。

这里研究的结果是供商品对齐流程核验的**候选对象对**：品类关系、已知属性和向量距离共同决定 pair 是否进入结果。几何相近不等于两个商品确实是同一 SKU。[Directory-Aware/TrieHI](https://arxiv.org/html/2606.16903v1) §II–IV 的文件目录模型处理单查询范围内 top-k；这里的目录是“品类层级 × 可交换的属性筛选”形成的复合结构，查询输出两个平台之间的全部阈值内 pair。

## 目录与对象模型

设 `T=(C,E,r)` 为有限有根品类树，`u≼_T v` 表示 u 等于 v 或为 v 的祖先，`Desc⁺(u)` 包含 u 自身及其后代。每件商品直接标注一个品类节点；商品可停留在内部品类，不强制标到叶节点。品类树是领域分类的一部分，不是文件系统路径。

设 `F` 为有限的单值属性维度集合，例如品牌、颜色、尺码；`D_f` 为维度 f 的规范化取值域。属性状态 `σ` 是部分函数，未定义表示该维度**未知**。属性状态按约束包含关系排序：`σ₁⊆σ₂` 表示 `σ₂` 保留 `σ₁` 的所有已知取值，并可增加约束。

一个目录筛选状态是 `(c,σ)`，其中 `c∈C`。状态的细化关系定义为 `(c,σ)≼(c',σ')` 当且仅当 `c≼_T c'` 且 `σ⊆σ'`。细化既可以沿品类边进入子品类，也可以增加一个属性约束；两类操作可交换。例如 `(运动鞋,{品牌=甲})` 与 `(跑鞋,{})` 都能细化到 `(跑鞋,{品牌=甲})`。因此**品类分量有明确层级，整体筛选目录却不是单父树**。

平台 A、B 的商品集合分别为 `A`、`B`。每个对象 x 有侧内唯一 ID、向量 `v(x)∈ℝᵈ`、直接品类 `c_x∈C` 和已知属性状态 `σ_x`。两侧使用统一的品类映射、属性取值规范及可比较的向量空间；距离固定为欧氏距离 `d₂`。模型考虑静态快照、每商品一个直接品类，以及单值属性。浏览目录的多条细化路径不复制商品。

## 兼容性与查询

两个对象的品类兼容，当且仅当它们的直接品类可比较：

`CatCompat(a,b)=[c_a≼_T c_b] ∨ [c_b≼_T c_a]`。

属性兼容，当且仅当所有共同已知维度的取值相同：

`AttrCompat(a,b) ⇔ ∀f∈dom(σ_a)∩dom(σ_b), σ_a(f)=σ_b(f)`。

属性状态不必互相包含。例如 A 已知 `{品牌=甲}`、B 已知 `{尺码=42}` 时二者兼容；A 已知 `{品牌=甲}`、B 已知 `{品牌=乙}` 时二者冲突。未知值不被推断为任何具体取值。

查询 `Q=(u,φ,ε)` 包含品类范围根 `u∈C`、属性筛选状态 `φ` 和阈值 `ε≥0`。对象 x 属于查询范围，当且仅当 `c_x∈Desc⁺(u)` 且 `φ⊆σ_x`：查询指定的属性必须在该对象中已知且相等。记满足范围的商品集合为 `A_Q`、`B_Q`。精确结果定义为

`J(Q)={(id_A(a),id_B(b)) : a∈A_Q, b∈B_Q, CatCompat(a,b), AttrCompat(a,b), d₂(v(a),v(b))≤ε}`。

结果是带平台侧别的 `(A-ID,B-ID)` 集合，每个逻辑 pair 只出现一次。距离恰为 ε 的 pair 包含在内；没有合格 pair 时结果为空。这是 **cross、threshold、exact** 几何向量连接，要求枚举全部满足条件的 pair，不是每商品 kNN，也不是全局 top-k。它不判定商品实际身份是否相同。

## 精确基线算法

各基线使用同一品类映射、属性规范化、L2 距离、阈值及 pair 输出规则。记 `P_Q` 为 `A_Q×B_Q` 中同时满足 `CatCompat` 和 `AttrCompat` 的候选 pair 数。

| 基线 | 执行方式 | 主要成本 |
|---|---|---|
| B0 全量验证 | 枚举 `A_Q×B_Q`，逐对检查品类与属性兼容，再计算合格候选的精确 L2。 | 精确 oracle；兼容性检查最多 `|A_Q||B_Q|` 次，距离计算 `P_Q` 次。 |
| B1 目录状态分组 | 按直接品类与完整已知属性状态 `(c_x,σ_x)` 将两侧分组；仅对兼容的组对做精确 block nested-loop join。 | 组对只判定一次兼容性，距离计算 `P_Q` 次；需计构建、偏斜组和结果写出。 |
| B2 品类范围与属性倒排 | 对右侧维护品类本地 posting 和各 `(f,v)` 的属性 posting。对每个 `a∈A_Q`，先取 `B_Q` 中品类与 `c_a` 可比的对象，再排除所有已知属性冲突的 posting，逐一计算剩余对象的精确距离。 | 候选恰为两个目录谓词均合格的右侧商品，距离计算 `P_Q` 次；需计范围并集、差集与去重。 |
| B3 物化兼容范围 | 对常用左侧目录状态预存其在右侧的品类可比且属性不冲突的对象 ID 集；查询时与 `B_Q` 相交，再精确扫描。 | 将 B2 的部分集合计算移至构建期；计全部物化集合、构建、交集与内存成本。 |
| B4 向量优先 | 对每个 `a∈A_Q` 在 `B_Q` 上执行**完整精确** L2 range search，再检查品类和属性兼容。exhaustive flat range scan 可保证完整性。 | flat 实现最多 `|A_Q||B_Q|` 次距离计算；阈值稀疏时可减少后续目录判定。会访问不兼容商品的向量。 |

B2/B3 的精确候选范围为

`Eligible_B(a;Q)=B_Q ∩ Cat_B(c_a) \ Conflict_B(σ_a)`，

其中 `Cat_B(c)=⋃_{v∈Desc⁺(c)∪Anc⁺(c)} Local_B(v)`，`Local_B(v)={b∈B:c_b=v}`，`Conflict_B(σ)=⋃_{f∈dom(σ)}⋃_{w∈D_f,w≠σ(f)} Posting_B(f,w)`。集合差只排除右侧**已知且不同**的属性值；右侧未知值保留。`Eligible_B(a;Q)` 因而恰为 `{b∈B_Q:CatCompat(a,b)∧AttrCompat(a,b)}`。B2 在线构造，B3 对常用状态物化；多条目录细化路径不改变结果 pair 的计数。
