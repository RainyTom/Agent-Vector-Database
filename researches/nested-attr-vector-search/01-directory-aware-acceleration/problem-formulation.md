# Problem Formulation：共享虚拟目录中的跨集合向量连接

## 问题背景

协作知识库可以用文件夹整理项目资料，同时通过文件夹快捷方式让同一个共享资料夹出现在多个工作区。[Google Drive 的官方说明](https://support.google.com/drive/answer/9700156?hl=en)给出了文件夹快捷方式的实例：快捷方式引用原对象，并不复制目标文件夹。本研究将这类共享入口抽象为**指向同一逻辑目录节点的边**；这是查询模型的选择，不声称该产品原生提供下述向量连接或采用相同索引。

例如，`支付项目` 与 `年度审计` 两个目录都指向共享的 `发票资料` 目录。`发票资料` 因而有两个上级入口；在 `支付项目 → 发票资料` 与 `年度审计 → 发票资料` 中看到的文档是同一逻辑对象。普通单父目录树不能同时表达这两个入口，若复制整棵子树又会引入重复对象与更新一致性问题。

设集合 A 为设计说明、操作流程等文本片段，集合 B 为工单、测试记录或审计证据片段。两个集合中的对象都有内容向量，并直接归属一个逻辑目录。批量关联的目标是找出目录位置具有祖先—后代关系、且向量距离不超过给定阈值的跨集合片段对。结果仅表示满足目录约束的几何近邻候选，不判定文本在业务上是否等价或证据是否充分。

[Directory-Aware/TrieHI](https://arxiv.org/html/2606.16903v1) §II–IV 以单父文件目录树为背景，研究目录范围内的单查询向量检索。本问题改用**多父共享目录**，并要求枚举两个集合之间的全部阈值内 pair。

## 数据模型与目录语义

目录是有限有向无环图 G=(V,E)。边 `(u,v)∈E` 表示目录 u 包含、引用或提供到逻辑目录 v 的入口，方向从上级指向下级。一个节点可有多个入边；禁止环，以便“后代”具有有限、明确的可达语义。具体产品可能存在会成环或失效的快捷方式；它们不属于本模型。目录节点用稳定逻辑 ID 标识，**同一节点经不同路径到达仍只算一个节点**。

对象集合 A、B 中的每个对象 x 有侧内唯一逻辑 ID `id(x)`、向量 `v(x)∈ℝᵈ` 和一个直接归属目录 `p(x)∈V`。对象可以直接归属中间目录。共享的是目录节点及其下对象，不通过每条访问路径复制对象。两侧向量处在同一可比较的空间；距离固定为欧氏距离 `d₂`。图、对象及向量均取自同一静态快照。

记 `Reach⁺(u)={u}∪{v∈V : u→*v}`，其中 `u→*v` 为沿 E 的有向可达。记 `u≼_G v` 表示 `v∈Reach⁺(u)`。对象 `a∈A` 与 `b∈B` 的目录兼容，当且仅当

`Compat_G(a,b) = [p(a)≼_G p(b)] ∨ [p(b)≼_G p(a)]`。

相同目录与有向可达的上、下级目录兼容；仅有共同后代的两个并列目录不兼容。多条路径证明同一次可达关系，不生成多个结果。

## 查询与精确结果

查询 `Q=(s,ε)` 给定作用域目录 `s∈V` 和距离阈值 `ε≥0`。双方对象都必须位于从 s 可达的目录。其结果为

`J(Q) = {(id_A(a),id_B(b)) : a∈A, b∈B, p(a),p(b)∈Reach⁺(s), Compat_G(a,b), d₂(v(a),v(b))≤ε}`。

结果是带侧别的 `(A-ID,B-ID)` 集合；每个逻辑对象对只出现一次，即使其中的目录有多个上级或两节点之间有多条路径。两侧 ID 数值相同仍可组成一个跨集合 pair。距离恰等于 ε 的 pair 包含在结果中；没有合格 pair 时返回空集。

这是 **cross、threshold、exact** 几何向量连接：目录可达性和距离阈值都必须精确，不能用每对象 top-k 或全局 top-k 替代。模型暂不涉及权限、版本、环、对象直接多目录归属或近似漏报；这些条件会改变合法范围或输出保证。

## 基线算法

下列基线都计算同一个 `J(Q)`，按逻辑对象 ID 去重。设 `A_s,B_s` 为作用域内的对象集合，`P_s` 为目录兼容的跨侧候选 pair 数。B1/B2 在目录过滤后需要 `P_s` 次精确距离计算；B0/B3 的距离计算可达 `|A_s||B_s|` 次。最坏情况下 `P_s=|A_s||B_s|`。端到端成本还包括目录解析、范围生成、索引构建及 pair 输出。

| 基线 | 执行方式 | 主要成本与用途 |
|---|---|---|
| B0 全量成对验证 | 枚举 `A_s×B_s`，对每对检查双向可达和精确 L2 距离；可达性用图搜索或预先计算的闭包。 | 距离最多 `|A_s||B_s|` 次，作为最直接的精确 oracle；闭包若预计算，其构建及空间必须计入。 |
| B1 在线目录优先（PE-Online 风格） | 对每个 `a`，从 `p(a)` 枚举后代目录和祖先目录，收集这些目录中、且属于 `B_s` 的对象 ID；去重后逐个算精确距离。 | 精确距离为 `P_s` 次；重复遍历和 posting 并集可能成为主成本。借鉴 Directory-Aware 的在线范围解析，但它不是原文已经实现的 join。 |
| B2 物化目录范围（PE-Offline/TrieHI 风格） | 对每个目录预存去重的后代对象 ID 集；祖先侧由本地 posting 并集或另行物化得到。查询时组合两侧集合、与 `B_s` 相交，然后精确扫描。 | 精确距离为 `P_s` 次；需计入全部物化集合的字节、构建和范围交并。多个父节点会使同一对象出现在多个祖先集合中。原文树上物化不能直接当作 DAG join 实现。 |
| B3 向量优先 | 对每个 `a∈A_s` 做**完整精确** L2 range search，得到距离 `≤ε` 的全部 `b∈B_s`，再检查目录可达性。可用 exhaustive flat range scan 实现完整性。 | 适合几何阈值较紧、距离候选很少时；仍可能对大量不兼容目录对象做距离工作。ANN range search 若漏 pair，就不属于本组精确基线。 |

对 B1/B2，令 `Local_B(u)={b∈B:p(b)=u}`，则每个左侧目录 u 的精确合格右侧对象集合为

`Eligible_B(u;s) = B_s ∩ ( ⋃_{v∈Reach⁺(u)} Local_B(v) ∪ ⋃_{v:u∈Reach⁺(v)} Local_B(v) )`。

两项并集分别覆盖后代与祖先，集合并集消除 DAG 多路径和相同目录造成的重复。B1 在线求这个集合，B2 预物化其可复用部分；随后才按距离阈值筛选。这一等价式也规定了基线的正确性检查点。
