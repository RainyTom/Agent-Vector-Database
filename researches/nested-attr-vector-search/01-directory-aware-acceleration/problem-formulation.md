# Problem Formulation：多维商品目录约束下的跨平台向量连接

## 问题背景

跨平台商品目录常按多个维度逐步筛选商品，而非沿唯一的分类路径向下浏览。[OpenSearch 的商品目录示例](https://docs.opensearch.org/latest/tutorials/faceted-search/)使用品类、品牌、颜色、尺码等筛选维度。以“跑鞋”为例，可以先选品牌再选尺码，也可以先选尺码再选品牌；两种顺序对应同一个筛选状态。一个状态因而可能由多个上级状态到达，整个目录是由属性约束构成的偏序结构，而不是单父目录树。

跨平台商品匹配还会遇到属性不完整：平台 A 的商品可能标有“跑鞋、品牌甲”但缺少尺码，平台 B 的商品可能标有“跑鞋、42 码”但缺少品牌。这两个商品既不是同一目录节点，也不存在祖先—后代包含关系，却没有已知属性冲突，可以进一步用商品描述或图片向量筛选。若平台 B 明确标为“品牌乙”，则与平台 A 的商品冲突，即使向量距离很近也不应进入此目录约束下的结果。

因此，目录条件是**部分属性描述之间的兼容性**，几何条件是向量距离阈值。输出是供商品对齐系统后续核验的候选 pair；满足两项条件并不证明两个挂牌商品确实是同一 SKU。

[Directory-Aware/TrieHI](https://arxiv.org/html/2606.16903v1) §II–IV 处理单路径文件目录作用域与单查询向量 top-k。本问题中的筛选目录与商品均可具有不完整的多维属性；合法 pair 可以来自两个互不可包含的目录状态，查询结果为跨平台的全部阈值内 pair。

## 多维目录与对象

设 `F` 是有限的单值筛选维度集合，例如 `品类、品牌、尺码、颜色`；每个维度 `f∈F` 有规范化取值域 `D_f`。一个目录状态 `σ` 是从 `F` 到各取值域的**部分函数**：`σ(f)=v` 表示已选定该维度，未定义表示尚未指定。目录状态集合按约束包含关系组织：`σ₁≼σ₂` 当且仅当 `σ₁⊆σ₂`。一条目录边增加一个维度的约束。例如 `{品类=跑鞋, 品牌=甲, 尺码=42}` 同时可由 `{品类=跑鞋, 品牌=甲}` 和 `{品类=跑鞋, 尺码=42}` 到达；这不是单父路径结构。

平台 A 和 B 的商品集合分别为 `A`、`B`。对象 `x` 具有侧内唯一 ID、商品内容向量 `v(x)∈ℝᵈ`，以及已知属性构成的部分函数 `σ_x`。`品类` 是每件商品必有的规范化维度，其余维度可以缺失。缺失值表示**未知**，不是一个与所有已知值冲突的取值。同一商品只有一个逻辑 ID；目录浏览的多种顺序不复制对象。两侧使用同一维度词表、取值规范和可比较的向量空间，距离固定为欧氏距离 `d₂`。本文考虑静态目录及商品快照。

两个属性描述兼容，当且仅当它们在共同已知的每个维度上取值相同：

`Compat(σ_a,σ_b) ⇔ ∀f∈dom(σ_a)∩dom(σ_b), σ_a(f)=σ_b(f)`。

兼容性不要求 `σ_a⊆σ_b` 或 `σ_b⊆σ_a`。例如 `{品类=跑鞋, 品牌=甲}` 与 `{品类=跑鞋, 尺码=42}` 兼容；前者与 `{品类=跑鞋, 品牌=乙}` 不兼容。该谓词只处理目录元数据，不把缺失值推断成任何实际商品属性。

## 查询与精确输出

查询 `Q=(q,ε)` 由目录筛选状态 `q` 和距离阈值 `ε≥0` 组成，其中 `q` 必须指定 `品类` 取值。商品 `x` 位于该查询目录内，当且仅当 `q⊆σ_x`；换言之，查询指定的每个属性都必须在商品中**已知且相等**。设 `A_q={a∈A:q⊆σ_a}`、`B_q={b∈B:q⊆σ_b}`。精确连接结果为

`J(Q)={(id_A(a),id_B(b)) : a∈A_q, b∈B_q, Compat(σ_a,σ_b), d₂(v(a),v(b))≤ε}`。

结果是带平台侧别的 `(A-ID,B-ID)` 集合，每个逻辑 pair 只出现一次。距离恰为 `ε` 的 pair 包含在结果中；无合格 pair 时结果为空。这是 **cross、threshold、exact** 的几何向量连接，须完整枚举所有满足目录与距离条件的 pair。它不是每个 A 商品的 k 近邻，也不是全局 top-k pairs。商品实际是否同一 SKU 不属于该几何连接的正确性定义。

## 精确基线算法

所有基线都计算同一个 `J(Q)`，并在相同的属性规范化、L2、阈值、pair 去重及输出物化规则下比较。设 `P_q` 为 `A_q×B_q` 中属性兼容的 pair 数。

| 基线 | 执行方式 | 主要成本 |
|---|---|---|
| B0 全量验证 | 枚举 `A_q×B_q`；逐对检查共同维度是否冲突，再对兼容 pair 计算精确 L2。 | 最直接的精确 oracle；属性检查最多 `|A_q||B_q|` 次，距离计算 `P_q` 次。 |
| B1 目录状态分组 | 按完整的已知属性描述 `σ_x` 将两侧商品分组；仅枚举兼容的状态对，对对应商品组做精确 block nested-loop join。 | 属性兼容性按状态对计算并复用；最坏仍需 `P_q` 次距离计算。组构建、空组及偏斜组成本计入。 |
| B2 属性倒排与冲突排除 | 为右侧每个 `(f,v)` 建 posting。对每个 `a∈A_q`，先取 `B_q`，再减去所有与 `σ_a(f)` 不同的已知取值 posting；剩余对象逐一算精确 L2。 | 需要 posting 集合运算与去重；候选恰为兼容的右侧商品，总距离计算 `P_q` 次。未知维度对象不能被误删。 |
| B3 物化兼容目录范围 | 对重复使用的左侧状态 `σ` 预存右侧兼容商品 ID 集；查询时与 `B_q` 相交，再精确扫描。 | 将 B2 的部分集合运算移到构建期；计入全部物化集合的字节、构建及交集成本。 |
| B4 向量优先 | 对每个 `a∈A_q` 在 `B_q` 上执行**完整精确** L2 range search，再检查属性兼容性。可用 exhaustive flat range scan 保证完整性。 | 适合几何阈值很紧的情形；flat 实现可能计算 `|A_q||B_q|` 次距离。会先访问属性冲突的向量。 |

B2/B3 的精确候选集合可写为

`Eligible_B(a;q)=B_q \ ⋃_{f∈dom(σ_a)} ⋃_{v∈D_f, v≠σ_a(f)} Posting_B(f,v)`。

这个集合保留右侧属性未知或与左侧一致的商品，恰好等于 `{b∈B_q:Compat(σ_a,σ_b)}`。B2 在线计算，B3 对常用状态物化。商品目录中的多条筛选顺序不会产生多个逻辑对象，也不会增加结果 pair 的计数。
