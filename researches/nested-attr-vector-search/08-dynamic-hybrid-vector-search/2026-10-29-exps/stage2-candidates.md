## 1. C1：层级子树联邦路由 + 不等预算（主线）

**假设**：把 NodeANN 的局部索引当逻辑 shard，递归查询不必对 scope 内全部节点执行同等搜索。按节点摘要路由、按节点分配不等预算，可以在召回损失可控的前提下减少大 scope 内访问的 item 数——这是 2026-10-29 实测确认的唯一主瓶颈（D5；D6 的"启动成本"已被否定）。

**算法改动**
1. 每节点维护摘要：质心、item 数、距离分布统计（均值/方差或分位数）、可选均匀样本集。
2. 查询（recursive，锚点 $u$）：枚举子树节点（已有，≤2.5%）→ 对每个节点用摘要计算路由分数 → 选节点子集并分配不等预算（ef / 返回条数）→ 局部搜索 → 全局合并；协调器用 TA 式阈值做早停判断。
3. 预算分配的第一形态：向量版 Rank-S/Dynamic Cutoff——按路由分数比例分配，低分节点分配 0。

**与最近前序的差别**
- Taily/Rank-S/Dynamic Cutoff 是文本 flat shard、BM25 特征可加；这里是**谓词决定的层级子树**（每次查询的目标 shard 集合不同且嵌套）、同向量空间（免分数归一化）、预算是 ANN ef/返回数而非取深。
- ELI 做"为查询标签集合选物化子索引"，最接近；差别：ELI 的键是 flat 标签组合，我们是**层级节点**（父摘要可复用于任意后代 scope，不需要为每个谓词组合物化）。
- Gottesbüren 的 routing 是静态 flat 划分；我们的 shard 由属性谓词动态决定且可重挂。

**预期变化（相对 PE-ONLINE/PE-OFFLINE/NODEANN-B1/全局过滤基线）**

| 指标 | 预期 | 依据 |
|---|---|---|
| Recall@10 | 可控下降（目标 ≥0.99 档实测标定） | 启发式路由无严格保证，D4 表明召回损失来源可隔离 |
| 大 scope 查询延迟 | ↓（≥10k 桶，目标 ≥2×） | 省 item 访问量（当前 84% 时间在扫描） |
| 小 scope 查询延迟 | 不变 | scope 小则路由集天然小 |
| 更新成本 | 不变或微增 | 摘要随局部统计增量更新 |
| 空间 | +每节点摘要（d 维质心 + 统计，WIKI 约 1.5 GB 质心已有先例） | 实测锚点存在 |

**风险与失败场景**：高维距离分布建模失败（与块剪枝负结果同源）→ 路由命中率低 → 预算错配 → 召回崩；WIKI 节点太小（均值 5.34）时路由收益集中在大节点，小 scope 无收益。**明确失败判据：同 recall 下 ≥10k 桶不快于 B1 扫描 20% 即关闭。**

**可证伪最小实验（先于实现，数小时）**：离线 oracle 分析——对 WIKI/SIFT 的 ≥10k scope 查询，计算 (a) 真实 top-k 落在哪些节点（oracle routing）；(b) 按"只访问 oracle 节点 + 每节点精确"所需的 item 访问量节省上界；(c) 质心/样本投票两种摘要对 oracle 节点的召回率。若 (b) 的上界 <20% 或 (c) 的命中率过低，C1 直接关闭，不进入实现。

## 2. C2：Sample-ANN 路由（并入 C1 的 routing 机制候选）

每节点均匀采样 s 条向量进**中央样本 ANN**；查询在样本索引上取 k' 近邻，按节点归属投票得到节点选择与预算比例。与 CRCS/Rank-S 的差别：shard 是层级节点，样本随属性更新**局部刷新**（只重采受影响节点，成本 O(s)，不触发全局重建）。作为 C1 的 routing 机制与质心路由做对照臂；离线证伪实验 (c) 同时评估两者。

## 3. C3：层级属性更新协议（辅线）

**假设**：NodeANN 的局部索引使属性更新天然局部化；补齐 MERGE 冲突与摘要可回收性后，可以做到"任何属性/层级更新不触发全局 ANN 重建"且有显式成本界。

**内容**
1. **MERGE 冲突协议**：目标节点已有局部索引时，两索引**惰性并存**（逻辑上一个节点挂两个索引，合并照常 fan-out）vs **重建合并** vs **后台增量合并**；给出三者的更新延迟/查询开销/空间权衡。
2. **MOVE 成本核算**：局部索引整体重挂（已有事实）+ 依赖 DFS 区间的辅助结构重编号成本——修正"MOVE=O(1)"的误读，按任务书要求核算 posting/bitmap/摘要/一致性全套成本。
3. **可回收属性摘要**：EMA 的一跳 OR 摘要单调不可回收（删除/改值只能等重建）；引用计数摘要可精确回收但维护成本高。在层级属性下给出两者的失效曲线对比。
4. **staleness 语义与测量**：定义更新可见性（查询看到的属性版本），实测 base+delta 下的 staleness 分布。

**与最近前序的差别**：EMA/Curator 的属性模型是平铺标签；TrieHI 有 DSM 但无局部 ANN 合并协议；**层级属性的 MERGE/重挂 + 局部索引处置无任何工作**（G1）。

**预期变化**：更新延迟 MOVE 不变（已实测 2.75 ms TrieHI 级）、MERGE 惰性方案 ≫ 快于重建方案；查询延迟惰性方案微增（fan-out +1）；召回不变（语义不变）。

**最小实验**：WIKI `dsm_wiki.txt` 的 MERGE 流（1,000 ops），三臂对比更新延迟与查询质量；摘要失效曲线用 20%/50% 更新比例两档。

## 4. C4：树形阈值聚合（并入 C1 的理论组件）

父节点摘要给子树一个**距离分布估计**（不是几何下界——已在 d=1024 证死），协调器维护"已见候选的第 k 距离 τ vs 未访问子树的估计尾部"做早停。有分布假设时可证条件保证；假设失败则退化并报 recall 损失。不单独立项，作为 C1 的停止规则组件。

## 5. C5：集合四语义统一执行层（第三优先）

位图/倒排执行层把 containment/overlap/equality/reverse-containment 精确分离（不混用 "contains"）；item⊆query 的 in-filter 探索（item 标签集签名 + 查询集包含测试）。**风险**：item⊆query 的索引内加速可能本质不可行（需先读 LSH Ensemble 等相邻领域，已列入补查）；执行层统一偏工程。**决定**：排在 C1/C3 之后；先做四语义的精确定义与 GT 生成（这是所有后续实验的基础），in-filter 探索视补查结果再定。

## 6. C6/C7：暂缓与降级

- **C6（索引级 MVCC）**：与 05-versioned-directory-search（2026-10-19 alphaXiv 查重冻结）主题重叠；先做差异核查，未澄清前不动。
- **C7（热点物化）**：ELI 的弹性子索引选择与 Curator 的 per-label 物化已覆盖主要空间；降级为工程对照臂，不作研究贡献。

## 7. 推荐与下一步

**主线 C1（含 C2/C4）**：直接命中任务书"特别要探索"的联邦视角，且是三路文献扫描共同认定的最强空白（G2），并与本仓库实测瓶颈（D5）精确对齐。**第一步不是写索引，而是跑 §1 的离线 oracle 证伪实验**（数小时，纯分析，无新索引）。

**辅线 C3**：G1 置信度最高、与主线正交（查询 vs 更新），复用 TrieHI DSM 测量设施；在 C1 证伪实验排队期间即可启动 MERGE 三臂实验。
