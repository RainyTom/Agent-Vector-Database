# 动态三臂同协议对照（2026-10-29）

## 1. 问题、相关工作与可证伪假设

研究对象是 **NodeANN 动态维护策略的实测比较**，不是已经优于公开论文的新索引。沿用 [基线定义](baselines.md) 和 [TrieHI 作者稿](https://arxiv.org/abs/2606.16903) 的问题背景；本轮不提出文献新颖性声明，不将旧论文/FAISS 数字作为同协议对照。

**H1（待测）**：随更新覆盖率和查询局部性变化，A/B/C 的查询—更新总成本可能出现交叉；交叉位置取决于查询范围、更新类型和热点分布。若测定区间始终同一臂占优，则该区间内“不支持存在交叉”，不得强行拟合一个交叉点。

**H2（待测）**：A 的移动/插删成本受局部图大小、墓碑、阈值跨越与压实影响；B/C 的属性更新通常不改全局图。这可能抵消 A 的查询收益，不预设高更新率有利于 A。

**H3（待测）**：子树重挂与逐 ITEM 移动不是同一种操作。A 可保留局部图，但树合法性检查、受影响目录与元数据维护仍需计时；B/C 的路径键重写和祖先成员变化需真实执行。

## 2. 结构和维护（不偷换基线）

| 臂 | 存储与查询 | 单 ITEM 跨节点 | 子树重挂 |
|---|---|---|---|
| A：NodeANN 维护策略 | 稳定节点 Trie；直接绑定节点局部 HNSW；小节点精确扫描；后代 scatter-gather + 全局 top-10 | 目标局部图插入、源图标删；阈值跨越/死比阈值可能触发局部重建 | 重挂稳定节点，局部图不搬迁；树校验与相关维护均计时 |
| B：PE-ONLINE 动态版 | 路径键→直接 posting；查询展开前缀目录并集；全局 HNSW in-filter | 修改直接 posting/catalog；不改全局图 | 重写被移动子树的路径键，保留直接 posting |
| C：PE-OFFLINE 动态版 | 路径键→含后代 inclusive posting；非递归查询必须用父集合减子集合；全局 HNSW in-filter | 旧/新独有祖先 posting 删除/增加；不改全局图 | 路径键重写 + 旧/新独有祖先中所有受影响 ITEM 成员更新 |

无向量变化的 category/numeric/tag 修改只维护属性状态；不假装 A 必须为这些操作改图。所有臂对真实 ITEM 删除做图标删，插入恢复/加入图。批量移动先在操作开始时冻结源子树活 ITEM 集合，再全部直接绑定到目标节点；和改树的 `R` 操作分开报告。节点合并（重名冲突）不在本轮负载中，不能由重挂实验推断其成本。

### 成本符号

$N$ 总 ITEM；$M$ 目录数；$d$ 平均深度；$f$ 查询后代数；$C$ 过滤后候选数；$U$ 更新频率；$k=10$；$b$ 批量影响 ITEM 数；$s$ 重挂子树目录数；$a$ 新旧路径独有祖先数；$L_v$ 局部活 ITEM 数；$D_v$ 墓碑数；$I_v,D_v^{\mathrm{mark}},R_v$ 分别表示局部插入、标删、重建的**实测成本函数**。

- A 单 ITEM 移动成本：$I_{dst}+D_{src}^{\mathrm{mark}}+\text{catalog维护}+\text{触发的重建}$。不能整体写成 $O(1)$，也不给 HNSW 未证明的最坏复杂度保证。
- B 单 ITEM 移动：两次直接 posting 修改和 catalog 修改。本轮 posting 为 `std::set`、路径索引为 `std::map`，成员/键查找不是哈希 O(1)；计入树集合查找和字符串比较，不混用其他实现的复杂度。
- C 单 ITEM 移动：$a$ 次成员操作，集合实现和 key 查找成本另计；相同祖先不重复删加。标量/标签更新、插删、子树重挂不能统写 $O(d)$。
- B 重挂至少处理 $s$ 个路径键及其字符串字节；C 还处理约 $a b$ 个祖先成员变化。A 保留图不等于整个重挂 $O(1)$。
- A 查询成本：目录枚举 + 各节点 ANN/小节点扫描 + 全局合并；B/C：候选解析 + 统一全局 filtered HNSW。实际 ANN 距离数与跳数单独计量。
- 空间：A 包含每局部 HNSW 固定开销/容量/墓碑；B 直接 posting；C inclusive posting（与 ITEM 路径长度有关）。报告 RSS、HNSW 序列化字节与明确标记的元数据估算，不将估算说成精确内存。

## 3. 正确性与可见性协议

本轮是**单线程提交的事件流重放**，同一个进程内一次只执行一个更新或查询。三臂运行相同 trace，各次查询看到所有此前更新，不看到后续更新；更新失败即整次运行失败，不以部分提交继续计数。这给出相同的当前已提交状态语义，**不代表并发吞吐/MVCC 已验证**。

每次查询均从独立 canonical ITEM 表和父链判定当前 scope，不使用被测 posting 作为 oracle；所有满足相同谓词的活 ITEM 做精确 top-k。GT 与 ANN/扫描都使用 `raw_l2_space.h` → hnswlib `L2Space::get_dist_func()`；GT 在被测查询之后计算、计时单列。被测搜索不使用 oracle 的 eligible_count 决定跳过或搜索 k；额外属性在过滤回调/小节点扫描中判定。C 递归直接引用 inclusive posting，不为统计指标强制复制/遍历全候选集合。

目录约束始终 AND；普通属性支持 category equality、inclusive numeric range、tag 四语义（query⊆ITEM、交集非空、相等、ITEM⊆query），普通属性组内支持 AND/OR。禁用字段不参与 OR。零结果查询：正确返回空集时 query recall=1，pair recall 分母只累计真实 GT 数；另外报告零结果查询数。相同距离按 (distance,id) 排序；出现边界等距需单列处理，不能悄悄放宽谓词。

本轮固定每个潜在 ITEM 的向量不变；局部/全局图对于同一删除标签恢复都统一 `unmarkDelete`，新标签才 `addPoint`。不让某一臂额外执行已有向量的图修复，避免等价功能模块不一致。不同向量的 ID 重用/向量更新不在本轮范围。

质量门：macro recall 与 global pair recall 均≥0.999，invalid/duplicate/state violations 均为0。未过门结果保留为失败点，不进入“同质量更快”结论；禁止靠在查询中兜底全范围精确扫描达到门槛。

## 4. 数据和变量

先做小数据与可控合成 workload：真实 SIFT/WIKI 向量子集，**合成层级和普通属性**。这不是原始 WIKI 树，也不是 SIFT1M 全量结论。默认主曲线 N=12,000（另留插入 reserve），8 叶、80%叶 ITEM/20%内部 ITEM；深度3/7保持叶数固定，深度7用单链扩展，以避免深度和叶数混淆。

因子化矩阵（不是全笛卡尔积）：
1. mixed（仅 ITEM 级 V/T/M/D/I，结构操作单列）、depth3、uniform 的更新覆盖率 0/10/20/50/80%，Q/U=0.25/1/4；
2. rate=50%、Q/U=1 的单标量、标签、单 ITEM 移动、批量移动、子树重挂、插删、mixed 七类；
3. rate=20/80%、uniform/Zipf/热点迁移、depth3/7 的交互检查；
4. 查询持续覆盖宽/窄/空 scope、递归/非递归、不同候选选择率及 AND/OR 多属性组合。
5. 预登记的 `move-crossover` 补充：N=12000、50%覆盖、仅单 ITEM 移动，Q/U=0.01/0.1/1，3次重复；隔离“不改全局图”的维护优势，避免 mixed 中新向量插入成本掩盖移动取舍。

当前属性为类别8值、整数0–999、16标签中3标签/ITEM（执行器64-bit标签mask）；不是任意字符串标签或无限标签基数的完整实现。查询四类等量：root recursive、root child recursive、leaf recursive、固定空节点non-recursive；**非递归非空的性能未覆盖**（语义回归覆盖）。25%固定空scope不是生产负载比例假设。query vector复用64个，热点/热点迁移是加权合成采样，唯一覆盖约束会耗尽热点候选，不能声称恒定经验Zipf分布。

更新覆盖率定义为测试窗口内**至少被更新一次的初始活 ITEM 并集 / 初始活 ITEM 数**，不等于操作数/N，不等于独立随机抽样命中率。批量操作/重挂可能超出目标，必须报告 actual coverage、实际操作数与 actual Q/U。重挂影响其子树内活 ITEM 的层级路径；插入新 reserve 不虚增初始 ITEM 覆盖分子。更新频率与事件覆盖率是两个不同概念；本轮事件重放不声称是外部到达率压测。

种子、输入/trace/binary hash、完整命令和失败点保存。以独立进程并行跑任务节省时间，但不称为“隔离串行测量”；同一进程内搜索/建图单线程。主要曲线重复3次；不把一次筛查当稳健胜负。

## 5. 指标与交叉图

- 每查询 Recall@10、GT数、命中数、invalid、duplicate；scope size/eligible size、depth、fan-out、ANN distance calls/hops。
- 查询端到端 p50/p95/p99、目录/属性解析时间、ANN时间；不把 directory-only 与完整查询放同列。
- 更新 p50/p95/p99、更新操作吞吐及受影响 ITEM 吞吐；按 V/T/M/B/R/D/I 分开，不把大批量与单 ITEM 操作均值直接比较。
- 构建、同步局部图维护时间/次数（字段 `compaction_*` 包含墓碑重建、阈值转换与释放，未分离纯墓碑压实）、HNSW序列化格式字节、估计metadata字节、峰值RSS；写放大报告metadata成员写与ANN insert/delete/rebuild调用，**不是设备写字节**。
- 总负载成本 $T=\sum_q T_q+\sum_u T_u$，含触发的同步压实，排除 GT、初始构建和文件输出；构建另列。不同事件数另给每查询摊销 $T/|Q|$，不可直接比较原始总量。
- 横轴 actual coverage 或 actual Q/U，分三幅画查询、更新和总成本；显示质量失败点。若实际 Q/U 因批量操作偏离目标，不用目标值冒充横轴实值。

GT在同进程逐查询计算，虽在计时外，仍可能改变下一次查询的缓存状态；所有臂按相同协议执行，但结果不等于无GT干扰的生产尾延迟。吞吐为操作数/测量的服务时间和，非包括GT、CSV、构建的进程墙钟吞吐，更非并发到达率压测。

## 6. 旧证据降级（本协议优先）

旧 `churn_probe.cpp` 的 alpha=done/total_moves，total_moves=0.8×索引 ITEM，因此 alpha=1 是0.8次尝试/初始 ITEM，**不是100%独立 ITEM 覆盖**；失败尝试也曾推进计数。旧查询与更新共用 RNG，不保证不同维护臂拥有完全相同更新流。

旧 `churn_concurrent.cpp` 的 `node_of` 存在不同锁保护的读写，不能作为一致性保证或“MVCC无用”的证据；候选合并亦非完整同状态 scope Top-k。其窗口/异常数字仅保留为待重新验证的历史观测。

摘要实验是合成统计与操作/空间模型，不是端到端 ANN 时间。分层路由原型的子树摘要覆盖不完整，不能据此否证所有分层路由。历史数据保留，结论以新同协议实验为准。
