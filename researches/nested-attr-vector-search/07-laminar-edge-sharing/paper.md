## 1. Introduction

大模型时代的检索增强生成、电商多层目录导航与学术检索系统，都把同一类负载推到了前台：对象带有层级属性（taxonomy、目录、分类法），查询既要在某个节点下做**全景检索**，也要在该节点做**精确限定**，还可能需要跨层级的组合条件。以 ACM Computing Classification System（CCS）为例，论文被组织成由粗到细的分类树，一篇论文可同时挂在多个类目下，类目成员沿祖先继承。用户检索"高效的语义检索索引"时，可以在 "Information systems" 整棵子树内搜索（Subtree 语义），也可以只要直接标注在 "Retrieval models and ranking" 的论文（Exact 语义），还可以要求"位于 Information systems 子树内、但不属于 Information retrieval 子树"（布尔组合）。三种请求的可行集合不同，排序都按向量距离。

现有索引范式在这类负载上各自付出了不同的代价。**谓词无关（predicate-agnostic）的过滤图**把谓词判定放进图遍历：ACORN 通过谓词子图扩展让任意谓词下的诱导子图近似保持 HNSW 性质 [1]，但递归子树要求把节点展开成后代标签集，候选集随之膨胀，遍历中反复遇到不可返回的邻居，形成谓词死锁（predicate dead-ends）。**标签分区（label-partitioned）的物化方案**为每个作用域各建一张图：Filtered-DiskANN 把标签信息编进 Vamana 构图 [2]，逐作用域物化则直接为每个非空节点建独立图。它们把在线合并移到了构建期，代价是存储随标签重复线性增长——在本地的 85 节点层级上，逐作用域物化的 level-0 边有 760 万条，而去重后只有 366 万条，重复率 51.9% `[已测]`。**过滤感知（filter-aware）的执行优化**在单次查询内自适应切换过滤时机 [5]，但图拓扑不变，Subtree 的多索引合并与 Exact 的差集问题依旧存在。**层级索引**最接近本文：LSSG 用标签集分层把 equality / containment / overlap 三种语义统一进一张多层图 [3]；iRangeGraph 用线段树式的元素图把范围过滤归约为普通 ANN [8]；Directory-Aware 把目录语义提升为一等抽象，用 Trie 保留拓扑并提供递归/非递归两类查询 [9]。它们都没有回答一个问题：**同一张向量图里的同一条边，被多个作用域重复使用时，能否只存一次，且查询仍然是纯区间操作？**

本文的回答建立在层级拓扑的一个结构性事实上：作用域集合沿祖先向上是单调的——对象 $i$ 的可行祖先集 $A_i$ 是一个向上封闭的集合。于是对任意一条无向边 $(i,j)$，其"同时可行"的节点集合恰是 $A_i\cap A_j$，而任何向上封闭集合都由它的**极小元**唯一确定。把边存放在这些极小元上，一次存储即可服务该集合中的**所有**祖先作用域；而 DFS 先序把"节点及其后代"映射成连续区间，于是"取出某个作用域可用的边"退化为一次区间切片。这两点合起来，使 Subtree 查询在热路径上不需要任何谓词求值，也使共享边的空间开销可以按重复率精确预测。

我们把这个设计实现为 **Laminar Edge Sharing（LES）**，并在其上补齐了支撑一个完整系统的若干组件：多层共享导航（同一去重规则推广到 HNSW 的每一层，并给出层高分配与入口绑定）、区间化查询编译（把布尔表达式编译成不相交的 DFS 区间）、代价驱动的执行计划选择（在倒排扫描、区间切片、专属物化之间按测得的成本参数选择）、激活数组的游程编码（利用同一对象的邻居高度聚集于同一激活节点这一实测结构），以及增量维护路径（delta 段、边归属迁移与压实）。本文**没有**把这些组件全部实现到可测状态；第 5 节严格区分已测与待测。

**贡献**（均给出可核验的证据位置）：

1. **作用域代数的切片定理**：证明 Subtree 作用域在层 $\ell$ 上可用的边集，恰等于边归属节点集合与该作用域 DFS 区间的交集；Exact 作用域则必须按**全部**共同直接标签（而非其极小元）存放，否则祖先—后代同时出现在共同标签中时会漏边。给出反例与修正后的规则（§4.1，`production/nested-attr-vector-search/src/les_build.cpp`）。
2. **存储与去重的可预测性**：把共享存储量表达为"边—极小元关联数"，并给出与实测一致的下界论证：85 节点下观测 7,602,554 条有向边、唯一边 3,658,543 条、桶条目 3,822,238 条（多重度 1.045），压缩 51.9% `[已测]`（§4.2，`les-analysis.txt`）。
3. **激活数组的游程结构**：实测 13,387,704 个桶条目中 92.4% 的相邻条目属于同一激活节点，游程数 1,015,143，游程编码后 3.05 MB 对比 u16 的 26.78 MB（8.8×），熵下界 1.15 MB `[已测]`（§3.5，`act-delta-stats.txt`）。
4. **可复核的系统评测**：在同一批 1365 节点查询上与三类基线对照：LES 在 ef=32 时 15,694 QPS、Recall@10 0.9967、104 MB；逐作用域物化 74,706 QPS、0.9641、194 MB；Filtered-HNSW 在 0.9524 召回下 1,282 QPS、75 MB `[已测]`（§5，`ccs-les.csv`、`ccs-baselines.csv`）。并明确给出未对齐之处，不声称"同召回胜出"。

## 2. Problem Statement and Cost Model

### 2.1 数据模型与查询语义

**定义 1（属性树）** 属性树 $T=(V,E_T,r)$ 是一棵有根树；$\mathrm{Anc}^{+}(v)$、$\mathrm{Desc}^{+}(v)$ 分别表示含自身的祖先集与后代集；树深 $h=\max_v|\mathrm{Anc}^{+}(v)|$。

**定义 2（直接标签与祖先闭包）** 对象集 $\mathcal{D}=\{1,\dots,n\}$，对象 $i$ 有向量 $x_i\in\mathbb{R}^d$ 与直接标签集 $L_i\subseteq V$。祖先闭包 $A_i=\bigcup_{v\in L_i}\mathrm{Anc}^{+}(v)$。注意 $A_i$ 向上封闭：若 $v\in A_i$ 且 $w\in\mathrm{Anc}^{+}(v)$，则 $w\in A_i$；反之不成立。

**定义 3（两种原子作用域）**
$$
\mathcal{S}_{\text{rec}}(u)=\{i\in\mathcal{D}\mid L_i\cap\mathrm{Desc}^{+}(u)\neq\varnothing\},\qquad
\mathcal{S}_{\text{exact}}(u)=\{i\in\mathcal{D}\mid u\in L_i\}.
$$
二者关系为 $\mathcal{S}_{\text{exact}}(u)\subseteq\mathcal{S}_{\text{rec}}(u)$，且差集 $\mathcal{S}_{\text{rec}}(u)\setminus\mathcal{S}_{\text{exact}}(u)$ 恰是"仅由后代继承"的对象。等价地，$i\in\mathcal{S}_{\text{rec}}(u)\iff u\in A_i$，这一等价是全文的枢纽：**递归可行性在祖先闭包上是成员判定**。

**定义 4（反链与布尔查询）** 节点集 $U$ 是反链，当且仅当任意 $u\neq v\in U$ 互不为祖先。查询 $Q=(q,\Phi,k)$，$\Phi$ 由原子 $\mathcal{S}_{\text{rec}}(u),\mathcal{S}_{\text{exact}}(u)$ 经 $\cup,\cap,\setminus$ 组合而成，返回可行集内距离最小的 $k$ 个对象。

反链上的并**不一定不交**：对象 $i$ 可同时有标签落在两棵不同子树中，此时 $i\in\mathcal{S}_{\text{rec}}(u_1)\cap\mathcal{S}_{\text{rec}}(u_2)$。因此本文只使用次可加性
$$
\big|\mathcal{S}(U)\big|\le\sum_{u\in U}\big|\mathcal{S}_{\text{rec}}(u)\big|,
$$
等号当且仅当没有对象跨子树多标。后文所有成本上界都按此不等式给出，不再假设不交。

### 2.2 三种执行策略及其代价

| 策略 | 存储 | 查询期谓词 | Subtree 处理 | Exact 处理 |
|---|---|---|---|---|
| 全局图 + 谓词过滤（ACORN、Filtered-HNSW） | $O(nd)$ 向量 + $O(nM)$ 边 | 每候选 $O(1)$ 位图判定，但候选膨胀 | 展开后代标签、多起点合并 | 位图判定，差集大时退化为扫描 |
| 逐作用域物化（B4） | $\Omega(\sum_u|\mathcal{S}_{\text{rec}}(u)|)$ 条边 | 无 | 单图直查 | 需第二套图，空间翻倍 |
| 倒排 + 精确扫描（B0） | $O(nd)$ + 倒排 | 无 | $O(|\mathcal{S}_{\text{rec}}(u)|\,d)$ | $O(|\mathcal{S}_{\text{exact}}(u)|\,d)$ |
| **LES（本文）** | $\sum_e|\mathrm{MA}(e)|$ 条边 | 无 | 一次区间切片 | 直属段切片，或按阈值转扫描 |

逐作用域物化的边数在单标签、全部标签位于叶、树深 $h$ 时达到 $\Theta(nh\ell)$（$\ell$ 为平均标签数），这就是 §1 中"存储随标签重复线性增长"的来源。B0 的扫描代价在 CCS 形状负载上并不总是劣势：实测 Exact 作用域的 p50/p95/max 为 126/396/6,973 个对象 `[已测]`（`ccs-stats.json`），扫描 6,973 个 128 维 u8 向量是微秒量级，因此**Exact 语义的正确默认策略是扫描**，而不是为它物化图。这个观察直接决定了 §3.4 的调度规则。

### 2.3 实测负载特征

两个层级与查询集全部由 `prep.cpp` / `prep_ccs.py` 确定性生成：

- **H1（85 节点）**：4 叉、深 3，每对象 1–3 个直接标签；1000 条混合 Subtree 查询（root / 深度 1 / 深度 2 / 叶 / 反链 2–3）。
- **H2（1365 节点，CCS 形状）**：4 叉、深 5、1024 叶；每对象 1–5 个标签（均值 2.1）；25% 主标签落在中间节点；叶类目 Zipf(1.1) 与 512 个向量中心相关；1000 条 Subtree + 1000 条 Exact 查询，另含 1 个空 Exact 作用域 `[已测]`（`ccs-stats.json`）。

H2 的 Subtree 作用域大小为 p50 = 10,334、p95 = 49,305、max = 86,699 `[已测]`；Exact 作用域 p50 = 126、p95 = 396、max = 6,973 `[已测]`。两者相差约两个数量级，这解释了为什么单一策略无法同时服务两种语义。

## 3. The LES System

### 3.1 架构总览与一次查询的全过程

![LES 架构](figures/fig_architecture.png)

**图 1** 三联图。(a) 属性树，高亮部分是某个作用域的子树，DFS 先序把它压成一段连续区间；(b) 层 $\ell$ 的共享导航图，每条边只出现在其极小激活节点上；(c) 区间切片的 CSR：`act` 数组在对象内按激活节点先序单调排列，蓝色为直属桶 $B_{\text{exact}}$，橙色为跨子树桶 $B_{\text{cross}}$，一次切片读出该作用域可用的全部边。

LES 由五个部分构成，数据流为：**构建器**读入层级、标签与每作用域的基础图，算出边归属并写出区间化 CSR；**查询编译器**把布尔表达式编译成区间计划；**计划优化器**按统计与成本参数为每个区间选择执行策略；**执行器**在共享图上做受限 best-first 或走倒排扫描；**维护器**处理增量更新并在压实期合并。压缩编码作用于存储层，对上述四者透明。

**手工走查**：取一棵小 CCS 树 $r\to A$（Information systems）、$r\to B$（Computing methodologies），$A\to A_1$（Data management）、$A\to A_2$（Information retrieval），$A_2\to A_{2.1}$（Retrieval models）、$A_2\to A_{2.2}$（Evaluation）。三篇论文的直接标签为：$p_1=\{A_{2.1}\}$，$p_2=\{A_1,A_{2.1}\}$，$p_3=\{A_{2.2},B\}$。于是

$$
A_{p_1}=\{r,A,A_2,A_{2.1}\},\quad
A_{p_2}=\{r,A,A_1,A_2,A_{2.1}\},\quad
A_{p_3}=\{r,B,A_2,A_{2.2}\}.
$$

- $\mathcal{S}_{\text{rec}}(A_2)=\{p_1,p_2,p_3\}$（三者都在 $A_2$ 之下），$\mathcal{S}_{\text{exact}}(A_2)=\varnothing$（没有论文直接标 $A_2$）——这正是 H2 中"空 Exact 作用域"的真实形态，执行器应当直接返回空集而不启动任何搜索。
- $\mathcal{S}_{\text{exact}}(A_{2.1})=\{p_1,p_2\}$，$\mathcal{S}_{\text{rec}}(A_1)=\{p_2\}$。
- 边 $(p_1,p_2)$：$A_{p_1}\cap A_{p_2}=\{r,A,A_2,A_{2.1}\}$，极小元为 $\{A_{2.1}\}$，故该边存放在 $A_{2.1}$ 的桶里。它出现在 $\mathcal{S}_{\text{rec}}(A_{2.1})$、$\mathcal{S}_{\text{rec}}(A_2)$、$\mathcal{S}_{\text{rec}}(A)$、$\mathcal{S}_{\text{rec}}(r)$ 的切片中，但不出现在 $\mathcal{S}_{\text{rec}}(A_1)$ 的切片中——因为 $p_1\notin\mathcal{S}_{\text{rec}}(A_1)$，该边本就不该被 $A_1$ 使用。切片条件自动给出了正确性。
- 边 $(p_1,p_3)$：交集为 $\{r,A_2\}$，极小元 $\{A_2\}$，存放在 $A_2$；边 $(p_2,p_3)$ 同样存放在 $A_2$。因此在 $\mathcal{S}_{\text{rec}}(A_2)$ 上搜索时，三条边都可用；在叶作用域上只看到与自己相关的边。

一次 Subtree 查询的执行顺序是：定位入口（该作用域中最高的合格对象）→ 逐层贪心下降 → 在 level-0 上对区间做 best-first → 若结果不足 $k$（可行集本身小于 $k$），返回已找到的全部对象并置 `truncated` 标记，而不是继续扩张到作用域外。一次 Exact 查询的顺序是：查倒排得到 $|\mathcal{S}_{\text{exact}}(u)|$ → 小于阈值 $\tau$ 则直接扫描 → 否则读 $u$ 的直属段（注意：**不是子树区间**）→ best-first → 同样的不足 $k$ 语义。布尔查询则先把 $\Phi$ 编译成若干不相交区间，再对每个区间重复上述过程并合并。

### 3.2 共享导航：边归属、多层与入口

**定义 5（边归属集）** 对无向边 $e=(i,j)$，递归语义下的归属集为
$$
\mathrm{MA}_{\text{rec}}(e)=\min\big(A_i\cap A_j\big),
$$
即 $A_i\cap A_j$ 中不被其他成员的真后代所覆盖的节点；Exact 语义下为
$$
\mathrm{MA}_{\text{exact}}(e)=L_i\cap L_j \quad(\text{全部共同直接标签，不取极小元}).
$$
二元组 $(\mathrm{MA}_{\text{rec}},\mathrm{MA}_{\text{exact}})$ 决定边在存储中的全部落点。之所以递归侧取极小元而直属侧取全量，原因不同：$A_i\cap A_j$ 向上封闭，极小元生成整个集合；$L_i\cap L_j$ 一般不是向上封闭的，只取极小元会漏掉同时作为祖先出现的标签（§4.1 给出反例）。

**多层共享与层高分配（HALA）** 把同一规则推广到每一层。对象 $i$ 的全局层高 $\lambda_i$ 按 HNSW 的几何分布采样，$\Pr[\lambda_i\ge \ell]=p^{\ell}$，$p=1/\ln n$；对象 $i$ 在作用域 $u$ 的层 $\ell$ **合格**，当且仅当 $\lambda_i\ge\ell$ 且 $u\in A_i$。层 $\ell$ 的边只在合格对象之间产生，并按 $\mathrm{MA}_{\text{rec}}$ 去重。由于高层对象数是几何衰减的，层 $\ell$ 的条目数期望为 $E^0\cdot p^{2\ell}$（两端点都需要层 $\ell$），因此多层共享的总额外空间是一个收敛级数（§4.2）。**入口绑定**：作用域 $u$ 的入口取 $\arg\max\{\lambda_i : u\in A_i\}$，即该作用域内层高最大的对象；入口必须是该作用域的合格对象，否则下降会从作用域外开始，等价于放宽了过滤条件。

需要强调的是，多层共享解决的是**导航**问题，不是**过滤**问题：切片条件（§4.1）对任意层独立成立，而"共享层上仍存在单调下降路径"是概率性命题，条件写在 §4.2 的定理里，本文不把它当作无条件保证。

**构建**（`les_build.cpp`，已实现）

```
算法 1  LES-Build
输入: 对象向量与 u8 量化副本, 直接标签 {L_i}, 属性树 T, 每作用域基础图 {G_u}
输出: 共享层 CSR（offsets/nbr/act/dist16/dflag）+ 每作用域上层结构 up_<v>
 1: for i in D: A_i ← ⋃_{v∈L_i} Anc⁺(v)            // 位图, O(n|V|/64)
 2: DFS(T) → tin/tout                                // 子树 → 区间
 3: for u in V, for (i,j) in G_u.level0:
 4:     S ← A_i ∩ A_j
 5:     for m in minimal(S):                          // 递归语义
 6:         emit(m, i→j, dist16(i,j), dflag = [L_i∩L_j ≠ ∅])
 7: for u in V, for (i,j) in G_u.level0:              // 直属语义
 8:     for m in L_i ∩ L_j: emit_exact(m, i→j)
 9: 按 (act, nbr) 排序, 写 CSR; act 数组在对象内单调
10: for u in V: 保留 G_u 的上层, 绑定入口 e_u
```

### 3.3 区间化存储布局

存储层是三个数组加一个位图：`offsets[i]` 给对象 $i$ 的邻接段，`nbr[]` 存邻居 id，`act[]` 存该条边的归属节点先序，`dist16[]` 存量化距离，`dflag[]` 标记该边是否同时是直属边。由于 $B_{\text{exact}}$ 与 $B_{\text{cross}}$ 都按 `act` 排序，二者在物理上交错但不互相干扰：Exact 读 `act == tin(u)` 的那一段，Subtree 读 `tin(u) ≤ act ≤ tout(u)` 的整段。两种读取都是一次二分加连续指针滑动，没有随机访存，也没有逐候选的谓词判定。

**关键细节：直属段不等于区间**。若把 Exact 也实现成"读子树区间"，就会把仅由后代继承的对象错误地纳入可行集；反过来，若把 Subtree 实现成"读 $u$ 的直属段并向下扩展"，则会遗失只在后代出现的边。本文把这两条读取路径在代码与定理中都分开（§4.1），一处混用即可被 §5.4 的违规计数检出。

### 3.4 查询编译、代价模型与执行选择

**区间代数** 由定义 3，$\mathcal{S}_{\text{rec}}(u)$ 与区间 $I(u)=[\mathrm{tin}(u),\mathrm{tout}(u)]$ 一一对应；并由向上封闭性，任意布尔组合都可以先在区间层面化简。三条恒等式支撑编译：

$$
I(u)\cup I(v)\ \text{（}u,v\text{ 反链时两段）；}\qquad
I(u)\cap I(v)=I(v)\ \text{（}v\in\mathrm{Desc}^{+}(u)\text{）};\qquad
I(u)\setminus I(v)=[\mathrm{tin}(u),\mathrm{tin}(v))\cup(\mathrm{tout}(v),\mathrm{tout}(u)]
$$

差集产生的两段仍是区间，因此递归编译保持"区间并"这一闭包形式。编译结果是一组互不相交的区间加一个直接标签集合（Exact 原子不进区间，转成倒排集合运算）。区间数是 $O(t\cdot h)$，$t$ 为项数，$h$ 为树深；这一点在 §4.3 给出证明，并在实现上限制了编译期的内存。

**代价模型与阈值** 设扫描的单位成本为 $c_s$（每对象），图搜索的固定成本为 $c_0$（入口下降与初始化）加 $c_g\cdot \mathrm{ef}$。两者在
$$
s^{*}=\frac{c_0+c_g\cdot \mathrm{ef}}{c_s}
$$
处相交：可行集小于 $s^*$ 时扫描更优。**这就是本文唯一使用的"阈值"，它由测得的成本参数算出，而不是一个调参旋钮**。本地已测的分量是 $c_s$：191,914 QPS、p95 11.3 µs 的精确扫描 `[已测]`，对应 $c_s\approx 5.2\,\mu s/126\approx 41\,\text{ns}$ 每对象（按 p50 作用域折算）；$c_0$、$c_g$ 尚未在 LES 上测得 `[待测]`，因此 $s^*$ 的数值需要补测后才能定稿，本文不给出未经测量的阈值。

**计划优化的形式** 给定每个区间的候选策略集合 $\{\text{scan},\text{slice},\text{materialized}\}$ 与内存预算 $B$，选择使期望代价最小的组合。无预算约束时该问题按节点可分，逐节点取 argmin 即可；有预算约束时它是带权的集合选择问题，本文采用按"单位字节收益"排序的贪心，**并明确声明不声称近似比**——收益函数的子模性尚未证明。

**执行器** 的接口约定保证三件事：(i) 结果数不足 $k$ 时返回全部可行对象并标记 `truncated`；(ii) 可行集为空（如 $\mathcal{S}_{\text{exact}}(A_2)$）时立即返回，不启动搜索；(iii) 切片内的候选若不在作用域内不得返回——由切片条件保证，且 §5.4 用逐查询违规计数验证。

### 3.5 压缩与增量维护

**激活数组的游程结构** 同一对象的邻居在 `act` 上高度聚集：实测 13,387,704 个桶条目中相邻同值占 92.4%，游程总数 1,015,143（0.076 游程/条目）`[已测]`。因此对每个对象先存基准 `act`，随后存 (gap, value) 游程，编码后 3.05 MB，对比 u16 的 26.78 MB 为 8.8×，而零阶熵下界是 1.15 MB `[已测]`（图 2）。这不是"层级压缩"的胜利，而是**归属聚集**的副产品：边按极小元归类，天然形成同值长跑。

![激活数组编码](figures/fig_act_rle.png)

**图 2** 激活数组的三种编码：现行 u16、实测游程编码、以及零阶熵下界。游程编码的收益来自 92.4% 的相邻同值，与向量维度或距离度量无关。

**为何不做区间局部量化** 一个自然的设想是按子树分别建码本，理由是"子树内向量更集中"。本文在 H1 上实测了每个子树的覆盖半径并与根比较 `[已测]`：$\gamma_u=R(u)/R(r)$ 的均值在深度 0/1/2/3 上依次为 1.000/1.042/1.131/1.207，即**深层子树的覆盖半径反而更大**（图 3）。原因是覆盖半径以集合自身的均值为中心，小子树的均值估计噪声更大；在 SIFT 的均匀分布上，按子树切分不会带来更紧的量化误差界。因此本文不采用区间局部量化，也不给出相应定理；这是由数据划定的边界，而不是一个待调参数。

![覆盖半径](figures/fig_radius.png)

**图 3** 各深度子树的覆盖半径比 $\gamma_u$。虚线为 $\gamma=1$。若"子树更紧"成立，曲线应随深度下降；实测相反，故区间局部量化在本文数据上没有依据。

**增量维护** 静态 CSR 不适合原地插入。维护路径设计为三层：**delta 段**（新边追加到每对象的短增量段，查询时先读主段再读 delta 段）、**归属迁移**（标签变更使某对象的 $A_i$ 变化，受影响的边需要在新旧极小元之间迁移；迁移量正比于该对象度数而非全库）、**压实**（delta 比例或迁移比例超过阈值时重写受影响子树区间）。维护只影响 §4.1 切片定理的前提"$A_i$ 已更新"，因此正确性可归约到静态情形；但吞吐与写放大均未实测 `[待测]`。

## 4. Correctness and Analysis

### 4.1 切片等价性及其边界

**定理 1（Subtree 切片等价）** 固定层 $\ell$。对任意作用域 $u$ 与任意边 $e=(i,j)$（两端点在该层合格），$e$ 是 $\mathcal{S}_{\text{rec}}(u)$ 在层 $\ell$ 上可用的边，当且仅当 $\mathrm{MA}_{\text{rec}}(e)\cap\mathrm{Desc}^{+}(u)\neq\varnothing$。

*证明* 由定义 3，$i\in\mathcal{S}_{\text{rec}}(u)\iff u\in A_i$，同理 $j$。两端点同时可行 $\iff u\in A_i\cap A_j$。$A_i\cap A_j$ 向上封闭：它是两个向上封闭集合的交。任何向上封闭集合 $S$ 满足 $S=\bigcup_{m\in\min S}\mathrm{Anc}^{+}(m)$，故 $u\in S\iff\exists m\in\min S:\ u\in\mathrm{Anc}^{+}(m)\iff\exists m\in\min S:\ m\in\mathrm{Desc}^{+}(u)$。而 $m\in\mathrm{Desc}^{+}(u)$ 正是 $m$ 落在区间 $I(u)$ 内。∎

**推论** Subtree 查询只需读 $I(u)$ 内的条目，不需要任何谓词求值；反之，读区间外的条目会引入不可返回的候选（这正是"读整张图再过滤"效率低的根源）。

**定理 2（Exact 必须存放全部共同标签）** 设边 $e$ 的直属归属按 $L_i\cap L_j$ 计算。若只存放在 $\min(L_i\cap L_j)$ 上，则存在合法查询 $u\in L_i\cap L_j$ 使该边不可见。

*反例* 设 $L_i=\{A_2,A_{2.1}\}$，$L_j=\{A_2\}$。则 $L_i\cap L_j=\{A_2\}$，极小元也是 $A_2$，此例无损。改设 $L_i=\{A_2,A_{2.1}\}$、$L_j=\{A_2,A_{2.1}\}$，交集为 $\{A_2,A_{2.1}\}$，极小元为 $\{A_{2.1}\}$。此时查询 $\mathcal{S}_{\text{exact}}(A_2)=\{i,j\}$ 需要该边，但边只存在于 $A_{2.1}$ 的直属段，$A_2$ 的读取会漏掉它。∎

**修正规则** 直属侧按 $L_i\cap L_j$ 的**每个**元素存放（算法 1 第 8 行）。代价是直属条目数最多为 $\sum_e|L_i\cap L_j|$，实测 H1 中为 1,966,214 条 `[已测]`，相对递归侧 1,856,024 条只多 5.9%，可接受。

**接口约定** 上述两条读取路径在实现中严格分离（`les_query.cpp` 的 `subtree` / `exact_edges` / `exact_strict` 三种模式），`exact_strict` 会回读标签做独立校验，用于 §5.4 的违规计数。

### 4.2 空间：关联数与放置最小性

**命题 1（关联数：一个恒等式与一个经验界）** 设 $E_{\text{obs}}$ 为所有作用域基础图的 level-0 有向边总数，$E_{\text{unique}}$ 为去重后的无向边数，$\mathrm{MA}_{\text{rec}}(e)$ 为边 $e$ 的递归归属集，则桶条目数精确等于
$$
N_{\text{bucket}}=\sum_{e} \big|\mathrm{MA}_{\text{rec}}(e)\big|,
$$
并有恒等式下界 $N_{\text{bucket}}\ge E_{\text{unique}}$（每条唯一边至少有一个落点），多重度 $N_{\text{bucket}}/E_{\text{unique}}$ 度量"一条边平均被几个祖先作用域共享"。

*实测* 在 H1 上 $E_{\text{obs}}=7{,}602{,}554$、$E_{\text{unique}}=3{,}658{,}543$、$N_{\text{bucket}}=3{,}822{,}238$，多重度 $1.045$ `[已测]`，即 $N_{\text{bucket}}$ 同时低于 $E_{\text{obs}}$（压缩 49.7%）且仅比 $E_{\text{unique}}$ 高 4.5%。$N_{\text{bucket}}\le E_{\text{obs}}$ 在本负载上成立，但它是**经验性质而非定理**：若某负载中大量边同时有多个极小元，$N_{\text{bucket}}$ 可以超过 $E_{\text{obs}}$；实现中以多重度为监控量，超过阈值时回退到"只放在 DFS 序最小的极小元 + 查询侧补集扫描"的方案。

**命题 2（放置最小性，区间模型内）** 在"边只能通过区间成员关系被检索到"的存储模型中，把边放在 $\min(A_i\cap A_j)$ 的**全部**元素上是必要的：少放任一元素 $m$，作用域 $m$ 自身的切片就会缺失该边。

*证明* 作用域 $u=m$ 的切片只含 $\mathrm{Desc}^{+}(m)$ 内的归属节点；若边不放在 $m$ 也不放在 $m$ 的其他后代上，则不可见。而 $m$ 是极小元，$m$ 的后代中不含 $A_i\cap A_j$ 的其他成员，故无处可放。∎

**多层空间** 层 $\ell$ 的条目期望为 $E^0p^{2\ell}$，求和得 $E^0/(1-p^2)=E^0(1+o(1))$。这是**期望值**，依赖层高采样的独立性；实测未覆盖多层共享（当前原型只共享 level-0）`[待测]`。

### 4.3 布尔编译与阈值

**定理 3（区间编译的项数与长度）** 设布尔表达式 $\Phi$ 有 $t$ 个原子、最大嵌套深度 $d_\Phi$，则 $\Phi$ 的可行集可表示为至多 $O(t\cdot h\cdot d_\Phi)$ 个互不相交的 DFS 区间，编译时间同阶。

*证明* 对 $\Phi$ 的结构归纳。原子为单区间（Subtree）或直接标签集（Exact，不参与区间代数，转交倒排）。$\cup$：两两区间求并，数量不超过两者之和；$\cap$：区间求交，数量不超过 $\min$；$\setminus$：单区间减多区间，每次减法至多把一段切成两段，故数量线性增长且每段的端点是某个 $\mathrm{tin}/\mathrm{tout}$，总数为 $O(t)$。经过 $d_\Phi$ 层嵌套，数量上界为 $O(t\cdot d_\Phi)$；端点排序后合并相邻区间，并的表示不含重叠。深度 $h$ 只影响端点的可比性判定，不增加数量。∎

**命题 3（阈值存在性）** 若扫描成本线性于可行集大小 $c_s s$，图搜索成本为 $c_0+c_g\mathrm{ef}$ 且与 $s$ 无关，则二者在 $s^*=(c_0+c_g\mathrm{ef})/c_s$ 处相交；$s<s^*$ 时扫描严格更优。

*证明* 直接比较两条线性/常数成本函数。∎

> 注意：真实图搜索成本随 $s$ 下降而上升（可达性变差），因此上式给出的是**乐观**阈值；实际阈值需按 §5.4 的方法标定 `[待测]`。

### 4.4 导航性

**命题 4（共享层的连通性条件）** 固定作用域 $u$、层 $\ell$。若层 $\ell$ 在 $\mathcal{S}_{\text{rec}}(u)$ 内的合格对象集合非空，且基础图在其上的诱导子图满足 HNSW 的入口可达性，则贪心下降存在。合格对象数的期望为 $|\mathcal{S}_{\text{rec}}(u)|\cdot p^{\ell}$，故当 $\ell\lesssim \log_{1/p}|\mathcal{S}_{\text{rec}}(u)|$ 时该集合以高概率非空。

这是**条件命题**：它把"共享层可用"归约为"诱导子图上入口可达"，后者是 HNSW 本身的概率性质，本文没有重新证明。本文能给出的是切片条件对任意层成立（定理 1），以及当合格集合为空时执行器必须回退（§3.4 的策略选择），二者共同保证正确性，而复杂度主张保留为条件形式。

三点结论。第一，图搜索在直属语义上比扫描慢约 $4\times10^3$ 倍——因为直属作用域 p50 只有 126 个对象，入口下降与 beam 初始化的固定成本占主导，而扫描的 126 次距离计算是纯顺序访存。第二，不做后置过滤时 7.4% 的返回对象违反作用域，说明"直属桶里的边"并不等于"两个端点都直接标注在该节点"（§4.1 定理 2 的反例在真实数据上出现）；后置过滤把违规率压到 0，代价是 QPS 45 与 5.9% 的查询无法填满 $k$——这正是稀疏区间上图连通性不足的实测形态。第三，两者共同给出 §3.4 调度规则的依据：**Exact 的默认路径必须是扫描，图搜索只在大直属类目上作为可选分支**，而这需要先用 §4.3 的成本模型标定 $s^*$ `[待测]`。

- **召回一致性**：LES 在 ef ≥ 96 时达到 Recall@10 = 1.0000 `[已测]`，说明切片没有遗失可行边（若切片遗漏，召回无法到 1）。
- **Subtree 违规计数**：对 ef=32 的 1000 条查询逐一回读标签核验，返回的 10,000 个结果全部落在所查询节点的子树内，违规 0，填满 $k$ 的查询 1000/1000 `[已测]`（离线核验，不计入 QPS）。
- **稀疏区间**：H2 中 Exact 作用域 p50 = 126，远超图搜索的启动成本；这支持 §3.4 的"小集走扫描"规则，但阈值本身仍需实测 `[待测]`。
- **ACORN 的适配边界**：两种 metadata 编码在 ef ≤ 1024 下 Recall@10 ≤ 0.8479 `[已测]`。这不是实现错误（同一驱动在扁平标签上复现了原文趋势），而是 metadata 编码未表达层级；把层级编码进 metadata 会引入 §1 所述的展开成本。
- **未测项**：多层共享、布尔编译、增量维护、1M 规模、真实 CCS 标签分布。四项均给出设计与接口，但无实测数据，不计入任何结论。

## 6. Related Work

**过滤向量检索的三条路线。** 谓词无关路线以 ACORN 为代表，用谓词子图扩展让任意谓词下的诱导子图近似保持 HNSW 性质，并用两跳邻居扩展与压缩启发式控制空间 [1]；其代价是构图期需要为谓词多样性付费，查询期仍需逐候选判定。过滤感知路线以 Filtered-DiskANN 与 PathSeer 为代表：前者把标签编入 Vamana 的构图与剪枝 [2]，后者在查询期按选择性动态切换 pre/post-filtering 并融合向量索引 [5]。分区路线为每个标签集合建子图再缝合，或按作用域整体物化；它把在线成本移到构建期，空间随重复线性增长，本文的 B4 与 H1 静态分析给出了这一增长的实测形态。

**层级与范围索引。** iRangeGraph 用线段树式元素图把二维单调范围过滤归约为普通 ANN，并用 $O(\log n)$ 个元素图在线拼装 [8]；LSSG 用标签集分层统一 equality / containment / overlap，并给出 containment 与 overlap 下的扩展概率下界 [3]；Directory-Aware 把目录语义提升为一等抽象，定义递归/非递归查询与维护操作，并用 Trie 保留拓扑 [9]。三者与本文最接近，但关注点不同：iRangeGraph 面向单调数值范围而非树形层级；LSSG 的分层对象是标签集合而非其祖先闭包的极小元；Directory-Aware 解决目录语义的表达与维护，不讨论导航边的跨作用域共享。

**与本文的可检验差异。** 本文不主张"支持 Exact/Subtree 两种语义"本身是新的——ACORN 的任意谓词、LSSG 的 containment、Directory-Aware 的递归/非递归都已覆盖语义层面。本文主张的是三条可被反驳的机制差异：(i) 导航边按祖先闭包交集的极小元存放，使一次存储服务该交集的全部祖先作用域；(ii) 查询期以 DFS 区间成员关系代替谓词求值；(iii) 直属语义必须存放全部共同直接标签，且默认执行策略是扫描而非图搜索。第 (iii) 条同时是一个负面结论：为 Exact 建图的收益低于直觉。

| 方法 | 语义 | 边共享方式 | 查询期谓词 | 层级组合 | 多层共享 |
|---|---|---|---|---|---|
| ACORN [1] | 任意谓词 | 无 | 逐候选 | 无 | HNSW 层 |
| Filtered-DiskANN [2] | 标签 | 按标签分区 | bitmap | 无 | Vamana 层 |
| PathSeer [5] | 标签 | 无 | 动态切换 | 无 | HNSW 层 |
| iRangeGraph [8] | 二维范围 | 元素图 | 区间 | 单调 | 专用图 |
| LSSG [3] | 集合包含/交叠 | 标签集分层 | 分层遍历 | 标签格 | 分层图 |
| Directory-Aware [9] | 前缀 | Trie | 前缀匹配 | 树 | 无 |
| **LES** | 递归/直属/布尔 | **按极小元去重** | **无（区间）** | **树/森林** | **按层去重（待测）** |

## 7. Conclusion

本文研究了层级属性向量检索中"同一批导航边被多个作用域重复使用"这一结构性问题，提出按祖先闭包交集的极小元去重、并用 DFS 区间切片执行查询的 LES 索引。可核验的结论是：在 85 节点层级上，去重把 760 万条观测边压到 366 万条唯一边（51.9%），桶条目 382 万；在 1365 节点的 CCS 形状负载上，LES 以 104 MB 索引达到 15,694 QPS / Recall@10 0.9967（ef=32），而逐作用域物化以 194 MB 达到 74,706 QPS / 0.9641，Filtered-HNSW 在 0.9524 召回下为 1,282 QPS / 75 MB。本文同时给出两条负面或受限结论：Exact 语义的正确默认策略是扫描而非图搜索；按子树做区间局部量化在实测数据上不成立（覆盖半径随深度增大）。多层共享、布尔区间编译、增量维护与真实 CCS 标签分布尚未实测，是后续工作的主体。
