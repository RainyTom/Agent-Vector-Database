# 下闭锥图：DAG 层级多属性过滤的单图搜索

## 0. 状态声明

- 本轮只做推理、设计与结构核验，**没有实现、没有 ANN 实验、没有速度或召回数字**。
- 结构数字来自真实 CCS/SciHTC 工作负载的概念拓扑与 owner 分布，不含向量、不含距离。
- 12-item 例没有真实向量；文中所有连线与顺序都是**手工示例**，不是训练输出或实测结果。
- PQ 编码 Trie 路线是**用户定位驳回**、从未实施；本文不重启、不换名。
- 每概念独立 top-k 再合并是**用户已观测的慢路径**；本文不把它作为主线，也不重跑确认。

## 1. 动机与关键想法

### 1.1 已观测事实

| 事实 | 来源 |
|---|---|
| 按概念建局部图、各自 top-k 再合并，比整图搜索慢 | 用户观测，不重跑 |
| 固定 proxy 覆盖不足，增大代表数不是新机制 | WQR 固定报告 |
| 邻域页降低二跳取得成本，但几何状态不变，仍慢于 NodeANN | 502753c 报告 |
| 邻接改动不等于 expanded 下降 | 5fc1be3 / 2f8c4e0 报告 |
| 全局过滤 HNSW 的 callback 只限制结果，不阻止不合格点参与导航与距离计算 | `hnswalg.h` 语义 + a1db223 |
| 触及多父概念的对象占 7.64%；这不是树化漏答率 | a1db223 复核 |

### 1.2 推导出的瓶颈

过滤图索引的浪费不在"结果里混入不合格对象"，而在**搜索预算被不合格对象占用**：为了凑够 k 个合格结果，beam 必须穿越大量不合格节点，每个节点都要算距离、扫邻边。选择率越低，浪费越大。

现有两条应对都不成立：

- **每概念局部图**：把"哪些合格"变成"搜哪个子图"，但引入 N 次独立遍历、N 份预算与一次归并；用户已验证更慢。
- **给图附加资格元数据**（bitmap、JBF 边界、CoPack 分组）：只决定"能不能返回"，不改变"遍历谁"，距离数量不降。

真正的问题是：**在几何图上，是否有办法在不看向量的情况下，定理式地排除一整批节点，而仍然保留通往合格对象的路径？**

### 1.3 关键想法（DAG 独有的性质）

设查询的概念条件为 U（recursive 取后代闭包）。对象的合格性只取决于它的 direct owner：

\[
i\ \text{eligible}\iff owner(i)\in D,\qquad D=\downarrow U=\bigcup_{u\in U}\mathrm{Desc}^+(u).
\]

由此得到一个纯拓扑结论：

> **合格集合在 poset 上是下闭的**：若 c ∈ D 且 c′ 是 c 的后代，则 c′ ∈ D。

原因是 D 本身由后代闭包生成。这个性质是 DAG 独有的：普通标量属性没有"后代"关系，标签集合无论怎么组合都得不到"某类标签一旦合格、其后代必定合格"。

于是：

1. 若图的边**只指向同一 owner 或 owner 的后代**，那么任何从合格节点出发的边都落在 D 内——遍历不可能离开合格集合。
2. 反过来，从外部接近 D 的唯一方式是沿祖先**向下**走；不合格但不是祖先的节点，其整个子树与 D 不相交，**不可能通向任何合格对象**。

第 2 条给出可判定的精确剪枝：节点 v 可访问 ⟺ `Desc⁺(owner(v)) ∩ D ≠ ∅`。这是**概念位图的一次求交**，不涉及向量。

### 1.4 由剪枝推出的可访问锥（已量化）

在真实工作负载上（1,929 概念、168,937 item、1,234 条查询）计算：

| 集合 | 定义 | 均值 | p50 | p95 | 占全部 item |
|---|---|---:|---:|---:|---:|
| 合格集 D | 后代闭包 | 815.9 item | 77 | 2,394 | — |
| 祖先闭包 Ant(D) | D 的全部祖先并 D | 3,874.9 | 1,591 | 18,693 | 2.29% / 0.94% / 11.1% |
| **入口最小锥** E(D) | D ∪ Anc(min(D)) | **2,951.1** | **1,457** | **10,818** | **1.75% / 0.86% / 6.4%** |

**E(D) 比 Ant(D) 更紧**，因为共享后代会把兄弟分支带进祖先闭包：查询 A 时，F 是 A 与 B 的共同后代，B 是 F 的祖先，于是 Ant(D) 包含 B；但 F 可以从 A 直接下行到达，B 不必访问。12-item 例中这使可访问 item 从 10 降到 8。

入口最小锥的合法性依赖一个前提：**D 的每个元素都能从 min(D) 沿 D 内部的下行边到达**。D 下闭保证成立（每个 d ∈ D 的祖先链在 D 内终止于某个极小元）；已在 12-item 例的 6 条查询上逐条验证。

结论：**对于绝大多数查询，可以定理式地把可访问对象限制在全部对象的 1%–6%，而全局过滤图没有任何这样的限制。**

## 2. 候选机制与选择

先列出三条本质不同的路线，再说明选择。

| 候选 | 机制 | 省掉什么 | 为何不选 |
|---|---|---|---|
| C1 概念摘要分支限界 | 每个概念的几何摘要（质心/半径/少量代表）做 DAG 自顶向下 branch-and-bound，用下界剪枝 | 距离计算 | 主检索变成树遍历，不是图导航；高维下界松弛，且 WIKI 低维证据显示摘要信息不足；与 IVF/Curator 类分区索引重合度高 |
| C2 计划器 | 保留全局过滤 HNSW，用 DAG 求交改写 AND、用闭包基数选择"扫描 or 图搜" | 只省执行策略 | 用户已明确"全局 HNSW + bitmap"不算完成创新；没有新的图机制 |
| **C3 下闭锥图（选定）** | 边只向下；查询把可访问集精确限制在入口最小锥；单队列 best-first | 锥外全部节点及其距离计算；合并与每图配额 | — |

选择 C3 的理由：它是唯一同时满足"图承担主检索""DAG 参与导航与候选生成""精确剪枝而不是启发式资格前处理"的路线；且它天然消除用户观测到的多图合并开销——因为它是**一张图、一个队列**。

C2 的一部分（AND 用 DAG 求交、基数估计）并不与 C3 冲突，作为查询计划的前置步骤保留，但不作为贡献主体。

## 3. 选定方案：下闭锥图（DCG）

### 3.1 数据与符号

- 概念 DAG：`parents`、`children`；闭包 `Desc⁺`、`Anc⁺` 以概念位图存放。
- item：唯一 ID、原始向量、唯一的 direct owner、独立普通属性。
- item 的 owner 可以在根、内部或叶节点。
- 查询：概念条件 U（recursive 并集；多个条件是交集时取 down-set 求交）、属性硬过滤 P、向量近邻 k。

### 3.2 图里有什么

**节点**：每个 item 一个节点，唯一物理存在。共享后代的 item 只有一个节点（F 的 f1/f2 不被 A、B 各复制一份）。

**边**：只有两类，且都满足 `owner(v) ⪯ owner(u)`（v 是 u 的同 owner 或后代）：

| 边类 | 定义 | 作用 |
|---|---|---|
| S 边 | 端点同 owner | 概念内部近邻导航；保证概念内连通 |
| D 边（桥） | `owner(v)` 是 `owner(u)` 的严格后代，且 `(owner(u), owner(v))` 是概念 DAG 的**一条直接边** | 沿 poset 下行；保证跨概念下行可达 |

**没有向上的边，也没有跨不可比概念的边。** 这是与全局 HNSW 的根本差异：全局 HNSW 的邻接可以连接任意 owner 的两个 item（因为它们按几何选边），因此任何资格剪枝都会切断路径。

**辅助索引（不参与几何导航，只做判定）**：

1. 概念闭包位图：`Desc⁺`、`Anc⁺`，用于 `Desc⁺(owner(v)) ∩ D` 的 O(1) 判定。
2. 概念 → item 列表（直接 owner 倒排），用于种子选择与桥端点挑选。
3. 属性子树摘要：对每个概念 c 与每个属性谓词分量，记录 `Desc⁺(c)` 内满足该分量的 item 计数。用于把"子树内 0 命中"的概念整体剪掉。这是 zone map / inclusive count 的常规做法（TrieHI 的 `Inc(v)` 同类），**不是新机制**，但它是"多属性参与剪枝"的落点。

### 3.3 构建

```text
Build(items, DAG, M, M_bridge):
  1. 概念闭包：Desc⁺/Anc⁺ 位图（O(D·|V|/64) 或按需遍历）
  2. owner 倒排：concept → [item]
  3. 每个非空概念 c：
       用现成 HNSW 算法在 items(c) 上构图，得到 S 边
       （概念间不共享边；M、efConstruction 与基线同参）
  4. 每条概念边 (p → c)：选 M_bridge 对端点
       对 items(c) 建临时近邻结构，或在 items(p) 中随机采样若干点，
       取 items(p)×items(c) 的最近点对；加入有向 D 边 p→c
  5. 属性子树摘要：自底向上累加每个概念的属性值分布/计数
```

构建不变量（后面定理依赖它们）：

- **I1 概念内连通**：`items(c)` 在 S 子图上连通。
- **I2 桥完备**：概念 DAG 的每条边 `(p→c)` 至少有一对 `p-item → c-item` 的 D 边。
- **I3 单向**：所有边满足 `owner(v) ⪯ owner(u)`。

### 3.4 查询

```text
Search(q, U, P, k):
  # 1. 概念域求解（精确，位图 + 计数，不算向量距离）
  D  ← ⋃ Desc⁺(u)  for u in U                  # 交集条件则对各条件取交集
  if |P| > 0:
      D ← {c ∈ D : subtree_match(c, P) > 0}     # 子树 0 命中 → 精确剪掉
  if D = ∅: return ∅
  entry ← D ∪ Anc(min(D))                        # 入口最小锥
  if |P| > 0:
      entry ← {c ∈ entry : subtree_match(c, P) > 0} ∪ min(D)

  # 2. 种子：entry 中没有"带 item 的祖先"的概念
  seeds ← ⋃ items(c) for c in entry
              if no ancestor c' of c with c' ∈ entry and items(c') ≠ ∅

  # 3. 单队列 best-first
  H ← min-heap over (distance, item)
  for s in seeds: push (dist(q, s), s)
  best_eligible ← max-heap of size k           # 只放 owner ∈ D 且 P 通过的 item
  visited ← set()
  while H ≠ ∅ and expansions < budget:
      (d, v) ← pop min
      if |best_eligible| = k and d > kth(best_eligible): break   # k-th 界
      if v ∈ visited: continue                                  # 去重
      visited.add(v)
      for w in down_neighbors(v):                               # S 边 + D 边
          if owner(w) ∉ entry: continue      # 精确剪枝，不算距离
          if w ∈ visited: continue
          dw ← dist(q, w)                    # 唯一计算距离的位置
          push (dw, w)
          if owner(w) ∈ D and passes_P(w):
              offer best_eligible (dw, w)
  return top-k of best_eligible
```

**去重**：一个 item 只有一个节点，进入 best_eligible 时才做 (distance, id) 比较；visited 集合防止同一节点二次计算距离。多父共享的 f1/f2 只出现一次。

**预算与停止**：硬预算 `expansions`（与 HNSW 的 ef 同类，不是 R）；软停止用第 k 个合格结果的距离。**祖先层节点不参与停止界**，否则近但无用的祖先会顶住 frontier（见 §3.7 反例），所以维护两个计数：`expansions_total` 与 `expansions_ancestor`，后者单独限额。

### 3.5 精确保证与近似损失

**G1（剪枝精确性，可证明）。** 若 I3 成立，则被剪掉的节点 v（`Desc⁺(owner(v)) ∩ D = ∅`）的全部后代都在 D 之外；从 v 沿边只能到达其子树内节点，因此**任何合格 item 都不在 v 之后**。剪枝不损失候选空间。

**G2（覆盖，可证明，依赖 I1+I2）。** D 下闭；由 §1.4，D 的每个元素可由 min(D) 沿 D 内部下行到达；I2 保证每条概念边的桥存在，I1 保证概念内可达。因此 entry 中所有 item 都可从种子沿允许的边到达。**被剪的兄弟分支（如查询 A 时的 B）不需要**，因为 D 可由 min(D) 独立到达。

**G3（无不合格距离之外的浪费）。** 在锥内，距离计算只发生在 entry 的 item 上；其中 `entry \ D` 恰是"必要的导航层"——它们是不合格但必须经过的祖先。

**召回不是保证的。** 损失来自三处：

1. **beam 截断**：`expansions` 有限，与 HNSW 的 ef 同性质。
2. **桥的几何质量**：下行路径由桥决定；如果最近邻在另一个分支，而通往它的桥很远，beam 可能到不了。这是本方案最关键的风险。
3. **属性摘要的粒度**：子树 0 命中是精确的，但子树"有命中"不代表命中 item 在几何上近。

### 3.6 12-item 例逐步说明

概念：R→A、R→B、A→C、A→F、B→E、B→F。每概念 2 个直属 item：`r1 r2 | a1 a2 | b1 b2 | c1 c2 | e1 e2 | f1 f2`，共 12 个唯一 item。

**索引形态**

| 边类 | 内容（结构示意，非由距离导出） |
|---|---|
| S 边 | r1–r2，a1–a2，b1–b2，c1–c2，e1–e2，f1–f2 |
| D 边（桥） | R→A: r1→a1；R→B: r1→b1；A→C: a1→c1；A→F: a1→f1；B→E: b1→e1；B→F: b1→f1 |

满足 I2：概念 DAG 的 6 条边都有桥。概念 C、E、F 无子概念。注意 F 只有一份 item，桥从 A 和 B 各来一条，**没有复制**。

**查询 1：U={A}**

1. `D = {A,C,F}`；合格 item = {a1,a2,c1,c2,f1,f2}。
2. `min(D) = {A}`（R 不在 D 内）；`entry = {R,A} ∪ {A,C,F} = {R,A,C,F}`。
3. 种子：R 在 entry 中且无祖先，items(R)={r1,r2} → 种子 r1、r2。
4. 从 r1：S→r2（owner R ∈ entry，允许）；D→a1（A ∈ entry）；**r1 若还有指向 b1 的边，因 B ∉ entry，直接跳过、不算距离**。
5. 从 a1：S→a2；D→c1、f1（均在 entry）。
6. c1→c2；f1→f2。
7. 结果只接受 owner ∈ {A,C,F}：`{a1,a2,c1,c2,f1,f2}` 中取 top-k。

**距离被计算过的 item：r1,r2,a1,a2,c1,c2,f1,f2 共 8 个；B、E 的 4 个 item 从未被算距离。** 对比全局过滤 HNSW：b/e 若几何上更近，就会被访问并计算距离，且没有任何规则能排除它们。

**查询 2：U={C,E}（散开的多条件）**

1. `D={C,E}`；合格 item = {c1,c2,e1,e2}。
2. `min(D)={C,E}`；`entry={R,A,C,B,E}`（R 是 C、E 的共同祖先；A、B 分别是入口路径）。
3. 种子：R 的 item r1,r2。
4. r1 → a1（A ∈ entry）与 b1（B ∈ entry）都允许；再分别下行到 C 与 E。
5. **entry 外的 F 被剪掉**：`Desc⁺(F)={F}` 与 D 不相交，且 F 无后代。所以 f1、f2 不算距离。
6. 结果 {c1,c2,e1,e2} 中取 top-k。

**查询 3：A AND B**

1. 交集条件按 down-set 求交：`Desc⁺(A) ∩ Desc⁺(B) = {A,C,F} ∩ {B,E,F} = {F}`。
2. `D={F}`；合格 item 只有 f1、f2。
3. `entry={R,A,B,F}`（F 的两个父都保留，因为 F 是极小元且两条入口路径都可能有用）。
4. 结果最多 2 个；k>2 时不补其他概念的对象。

**更新示例**

- `f1` 的 owner 由 F 改为 C：从 `items(F)` 的 S 图移除、插入 `items(C)`；A→F、B→F 的桥需要换端点；`Desc⁺` 不变，但 C 的属性摘要与 F 的计数改变。**不需要重算闭包**。
- 概念边 `A→C` 删除：闭包、桥、相关摘要全部失效，需局部重算；这属于高代价事件。
- 新增属性谓词：只需给每个概念补一列计数，不改图。

### 3.7 最坏反例

1. **概念几何不连贯**：若同一概念的向量在空间里分散，S 边与桥都很长，下行路径失去指引，beam 在小预算下会漏。此时本方案退化为"随机分组的树搜索"，可能比全局过滤图更差。
2. **近但无用的祖先**：某祖先 item 距 q 很近，但其子树中的合格 item 很远。它持续占据 frontier，第 k 界迟迟不生效，expansions 用尽。这就是必须把祖先层预算单独限额的原因。
3. **深而窄的链**：每个概念只有 1 个 item，深度 d 的查询需要 d 次下行，每次都要扫该层全部子概念的桥；分支因子大时，扫描成本 = Σ 子概念数。
4. **单概念查询**：`D` 只含一个概念、且该概念 item 很多时，entry 几乎等于该概念，剪枝收益接近零，退化为"概念内 HNSW 搜索"（即 NodeANN 的单图情形）。
5. **根查询**：`D` 为全部概念，entry = 全部，退化为全局下闭图搜索，没有剪枝收益。

## 4. 为什么有机会更快，以及新增成本

### 4.1 省掉的工作（可量化部分）

- **锥外节点完全不算距离**：真实 DAG 上 entry 锥中位数为全部 item 的 0.86%（p95 6.4%）。全局过滤图没有这个上界。
- **没有 N 次图遍历与归并**：单队列，用户观测到的"多图独立 top-k + merge"开销不存在。
- **没有每图配额**：NodeANN 必须让每个概念图各自返回 k 个，本方案按全局距离顺序动态分配 expansions。

### 4.2 新增成本

| 项 | 成本 |
|---|---|
| 空间 | 每概念一张 HNSW 的邻接（总量与全局图同阶，M 相同则约等于 n·M 条边）+ 每概念边 M_bridge 条桥（本例 2,040 条概念边）+ 闭包位图（约 D²/8 字节）+ 属性子树计数 |
| 构建 | 每概念构图（与全局构图同阶）+ 桥端点选取（每条概念边一次小规模最近点对） |
| 查询 | 概念位图求交 O(D/64)；种子选择；祖先层额外访问 |
| 维护 | owner 变更 = 两张概念图 + 桥 + 摘要；概念边变更 = 闭包与桥重算；属性变更 = 摘要更新 |

### 4.3 与基线的诚实对比

- 对**全局过滤 HNSW**：本方案多了"下行桥与概念内图"的构建复杂度，少了锥外访问；在概念与几何相关的数据上可能赢，在概念与几何无关的数据上会输。
- 对**NodeANN**：本方案少了每图独立 top-k 与归并，多了沿祖先的下行路径；概念多、单概念 item 少时优势更明显。
- 两者都必须在**同一实际 Recall 层**比较；距离数下降不等于时间下降。

## 5. 直接前序、可迁移部分与新增部分

| 前序 | 可迁移 | 本方案的差异 |
|---|---|---|
| [HNSW](https://arxiv.org/abs/1603.09320) | 单队列 best-first、beacon 式停止、M/efConstruction | 邻接被约束为 poset 下行 |
| [ACORN](https://arxiv.org/pdf/2403.04871v1) §5 | 谓词子图需要额外边才能连通 | ACORN 用一/二跳扩展维持连通，是**启发式**；本方案用"下行边 + 桥完备"使剪枝**可证**，且剪枝对象是整棵子树 |
| [Filtered-DiskANN](https://harsha-simhadri.org/pubs/Filtered-DiskANN23.pdf) §3 | 标签参与建图 | Stitched 把标签图边叠加；本方案不按标签建边，而是按 poset 方向建桥，覆盖任意 down-set |
| [TrieHI / Directory-Aware](https://arxiv.org/pdf/2606.16903v1) §III–IV | 概念闭包、inclusive 集合、scope 解析 | 该文是元数据层，执行器仍是单全局图；且数据集把 DAG 压成 canonical tree。本方案保留多父，并让闭包参与**图遍历剪枝** |
| [Curator](https://arxiv.org/pdf/2601.01291v3)、IVF 树 | 层级分区与自上而下路由 | 它们是树/分区，且在分区内做 ANN；本方案的分区之间由几何桥连接，搜索仍是一张图的 best-first |
| [NodeANN](https://arxiv.org/pdf/2606.16903v1)（本项目基线） | 每概念局部图 | 本方案把多个局部图用下行桥接成一张图，单队列；**不**各自 top-k 再合并 |
| zone map / inclusive count | 子树计数剪枝 | 常规；本方案只把它当辅助判定，不当贡献 |

**真正的新增点（候选，尚未认证）**：

1. 把"资格是 poset 下闭集"变成**可证的整子树剪枝规则**，并据此定义"入口最小锥"这一精确可访问集。
2. 由该规则反推**图构造约束**（I1–I3）：边只向下、桥完备、概念内连通。这三条是定理的前提，而不是实现细节。
3. 单队列跨越整条锥：既不是全局过滤图，也不是每概念 top-k 合并。

**尚未认证**：多父 DAG 上的"下行桥 + 锥剪枝"是否已有等价工作；是否只是"层级图索引 + 谓词剪枝"的组合。需要一次针对 hierarchical/label-constrained graph ANN 的查重。

## 6. 最小且有判别力的下一步

只做一个实验，三臂，同一数据、同一 M=16 / efConstruction=200、k=10、ef 15/20/40、单线程、全驻内存：

- **A**：全局过滤 HNSW（callback 过滤）
- **B**：NodeANN（每概念图 + 各自 top-k + 归并）
- **C**：下闭锥图（本方案）

数据需要**概念与几何相关**，否则测的不是机制：在 SIFT 上按概念生成簇（每概念一组、共享后代 F 由两个父各贡献一部分），属性作为独立谓词，多父比例与 SciHTC 对齐（约 5%）。再补一组**打乱绑定**的对照，用来验证机制解释而不是刷分。

**预测**：选择率 s ≤ 2% 时，C 在相同 Recall 下 expansions 与距离数显著低于 A，端到端时间也低于 A 和 B；s 接近 100% 时三者收敛。打乱绑定后 C 的优势应消失。

**失败标准**：

- 若在概念相关的数据、s ≤ 2%、同 Recall 下端到端**不优于 A**，方案否决。
- 若 C 只靠"改小 ef 或放宽停止规则"取胜，视为劣化基线，否决。
- 若 C 的 Recall 在任何预算下都无法接近 A，说明桥的几何质量不足，需要改桥选择而不是调参。

**不做的**：不铺维护矩阵、不扩到 WIKI/SIFT1M 全量、不重跑已报告失败、不调候选预算追正结果。
