# 方案 v6：子树分图 + 保边合并（不重新剪边）

> 按"先在 DAG 上划分 → 建小子图 → 用新的合并逻辑合起来"的思路设计。核心是**合并算子**，不是路由规则。

## 1. 划分

- 对每个概念 `c`，取其直属 item 集合 `items(c)`（owner 精确等于 `c`）。
- 划分是**按 owner 的精确划分**：每个 item 只属于一个概念组；多父概念只有一份，共享后代不复制。
- 子树图 `G_c` 定义为覆盖 `items(Desc⁺(c))` 的图；它由 `items(c)` 与各子节点 `G_child` 合并而来，不物理复制子图。

## 2. 建小子图

对每个非空概念 `c`：在 `items(c)` 上用标准 HNSW 建内部图（`M`、`efConstruction` 同基线）。

得到 `V` 个小图，规模由该概念的直属 item 数决定。

## 3. 合并算子 `Merge(G_p, {G_child})`

**这是与"把点插进全局图"根本不同的一步：合并只做并集与桥接，不重新选边。**

```text
Merge(parent p, children c1..ck):
  1. 保边：保留每个子图与 items(p) 内部图的所有边（不剪枝、不重排）
  2. 门户：每个子图预存 q 个门户 item（farthest-point sampling，或 k-means 中心最近点）
     门户同时兼作该子图的入口集
  3. 桥：对每条概念边 (p → c)：
       在 items(p) 里取 q 个"朝向 c"的点（对 c 的门户做最近匹配后去重）
       每个点上加 1 条有向边，指向 c 门户中最近的那个 item
  4. 度上限：门户与桥端点共享一个配额（每 item 最多 pcap 条外向桥），
     超配额时按"该桥到对侧最近 item 的距离"升序保留
```

三条关键性质：

| 性质 | 内容 | 为什么重要 |
|---|---|---|
| **保边** | 合并后每个 item 在其原子图内的边一条不减 | 子树内导航质量与单独建图时完全相同；这正是"同子树快速合并"的意思 |
| **门户=入口** | 子图的门户集同时是该子图的入口集 | 进入子图只需命中门户之一，不需要从全局入口穿过 |
| **桥单向** | 桥只在 `p → c` 方向 | `Desc⁺` 是下闭的，桥永远落在可访问集内 |

与 HNSW 的区别：HNSW 插入新点会重选邻居并剪掉旧边，合并次数越多，早期子图的内部结构被改写越多；本算子不改写。

## 4. 不变量

- **I1**：`items(c)` 内部图连通（由小图构建保证）。
- **I2**：每条概念边 `(p→c)` 至少一条桥（门户非空即成立）。
- **I3**：所有边满足 `own(v) ⪯ own(u)`（内部边同 owner，桥到直接子概念）。
- **I4**：每 item 的外向桥数 ≤ `pcap`（度数不被合并撑爆）。

## 5. 查询

```text
1. D ← ⋂_组 ⋃ Desc⁺；属性子树 0 命中剔除；D=∅ 返回空
2. E ← D ∪ Anc(min D)
3. 种子 ← min(D) 各概念的门户 item（门户即入口）
4. 单队列 best-first：
     第 k 名界；visited 去重；距离每 item ≤1 次
     合格且过属性 → 结果堆
     邻居 own ∉ E → 跳过且不算距离
5. 回退：结果不足 → 取消 E 剪枝（放到 Ant(D)）重跑
```

无每概念 top-k、无归并。查询只沿实体边，门户只是初始种子。

## 6. 代价

| 项 | 内容 |
|---|---|
| 构建 | `Σ_c n_c log n_c`（各小图）+ `Σ_{概念边} q`（桥） |
| 合并代价 | 每条概念边 O(q)，与两侧规模无关（HNSW 合并是 O(n log n) 重插） |
| 空间 | 内部边 `n·M` + 门户 `V·q` + 桥 `≤ |E_c|·q` |
| 度数 | 内部 M + 外向桥 ≤ pcap |
| 维护 | 新增 item 只改其概念小图；概念边变更只增删对应桥 |

**最坏反例**：
1. 单概念极大（`items(c) = n`）→ 退化为普通 HNSW，无收益；
2. 门户质量差（概念内几何分散）→ 进入子图后退化；
3. `pcap` 过大 → 桥噪声边增多，导航被拉长；
4. 深链 DAG → 查询需逐层下行，每层一次门户命中。

## 7. 12-item

概念 `R→A,B；A→C,F；B→E,F`，每概念 2 item，`q=1`、`pcap=2`。

| 子图 | 内部边 | 门户 |
|---|---|---|
| G_R | r1–r2 | r1 |
| G_A | a1–a2 | a1 |
| G_B | b1–b2 | b1 |
| G_C | c1–c2 | c1 |
| G_E | e1–e2 | e1 |
| G_F | f1–f2 | f1 |

桥（父→子，各 1 条）：`r1→a1`、`r1→b1`、`a1→c1`、`a1→f1`、`b1→e1`、`b1→f1`。F 只建一次，两条桥从 A、B 各来一条。

- `U={A}`：`D={A,C,F}`、`E={R,A,C,F}`，种子 = 门户 of min(D)={A} → `a1`；`b1` 因 `B∉E` 不访问、不算距离。
- `U={B}`：对称，种子 `b1`。
- `A AND B`：`D={F}`，种子 = `f1`（min(D)={F}）。

## 8. 与 v1/v4 的差别

| 项 | v1 DCG | v4 ESG | v6 |
|---|---|---|---|
| 构建方式 | 每概念图 + 最近点对桥 | 全局图 + 入口 | 子树分图 + **保边合并** |
| 入口 | 无门户概念 | 入口表（独立于图） | 门户即入口（同一份数据） |
| 桥选取 | 最近点对 | 无 | 门户对 + 每边 O(q) |
| 度数控制 | 每边 M_bridge | 无 | 全局 `pcap` 配额 |
| 合并代价 | O(1)（无合并动作） | — | O(q) / 概念边 |

## 9. 待验证

- 合成数据：同一批子树，分别用"HNSW 合并（重插）"与"保边合并"，测子树内查询的同 Recall 距离数；预测保边合并 ≥ 重插合并。
- 扫 `q ∈ {1,2,4}`、`pcap ∈ {1,2,4}`；失败判据：保边合并在子树内查询上不优于重插合并，则"保边"这一核心主张作废。

## 10. 更新路径（属性、owner、DAG 边）

v6 的分区+保边结构让更新**局部化**：一次变更只触及一个概念小图与常数条桥，而不触及全图。但要成立，必须先改两处设计。

### 10.1 门户与桥改为"稳定槽"

原设计要求门户 = item。删除或移动一个 item 会直接断桥。改为：

```text
门户槽 slot = (concept c, slot_id, item_id, 邻接)
桥指向 slot，而不是指向 item
```

- 槽的 `item_id` 失效时，在 `items(c)` 内部图上做一次小搜索，取最近的幸存 item 填入同一槽。
- 桥不需要修改：目标仍是同一 `slot_id`。
- 代价：一次概念内小图搜索 `O(log n_c)` + 指针更新。

桥端点同理：桥从 `slot_u → slot_v`，任一端失效只换该槽的 `item_id`。

### 10.2 计数只允许"保守"，不允许"乐观"

剪枝规则是"子树内 0 命中 ⇒ 整概念剪掉"。若计数被低估（实际有命中却报 0），会**丢答案**；若高估（报 >0 而实际为 0），只是少剪一次、多算。因此：

> **计数必须永不低估。** 任何无法同步更新的批量变更期间，把该子树标为 dirty，停止对其剪枝（只损失性能，不损正确性）。

逐 item 的属性判定始终在查询期对候选对象执行，不依赖计数；计数只决定剪枝。

### 10.3 三类事件

| 事件 | 触及的结构 | 代价 |
|---|---|---|
| **普通属性值变更**（等值/标签/数值区间） | 只改 `match(c,·)`，沿 `Anc⁺(own(i))`；**不触图** | `O(|Anc⁺|)`，CCS 均值 5.04、最大 16 |
| **owner 变更 `c→c'`** | ① 从 `G_c` 删除、插入 `G_c'`（各自 `O(log n_c)`）；② 若曾是门户，重填该槽；③ 若是桥端点，换 `item_id`；④ 计数差分沿 `Anc⁺(c) ∪ Anc⁺(c')` | 两次概念内局部操作 + 常数条桥 |
| **DAG 边增删** | ① 重算受影响祖先的闭包；② 增删该概念边的桥（`O(q)`）；③ `match` 沿所有 `Desc⁺` 发生变化的祖先重算 | 最贵；边变更比 item 变更稀少，可离线或标脏 |

### 10.4 与全局 HNSW 的对比

| 操作 | 全局 HNSW | v6 |
|---|---|---|
| 删除/插入一个 item | 全图邻居修复或惰性删除；影响面与全图规模相关 | 只碰该概念的 `n_c` 个小图 |
| 普通属性变更 | 需重建资格位图/整表扫描 | 沿祖先改计数，不触图 |
| 概念边变更 | 全图重建或大规模资格重算 | 闭包 + 常数条桥 + 受影响子树计数 |
| 批量变更 | 需整图重建 | 标脏降级剪枝，图不动 |

**这是 v6 相对"全局图 + 滤波"的主要结构性优势**：图维护的最小单位是概念，不是全库。

### 10.5 最坏情况

1. 某概念极大（`n_c ≈ n`）：owner 变更退化为全图操作；
2. 门户槽所在的 item 反复失效（热概念频繁删除）：每次一次小图搜索；
3. DAG 边批量重挂：闭包与计数重算代价高，必须标脏；
4. 多属性高基数（如自由文本标签）：`match(c,·)` 无法逐值计数，只能退化为 min/max 或位图，剪枝变弱。
