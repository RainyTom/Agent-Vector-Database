# 方案 v9：(质心 × 概念) 分桶——允许混合质心

> 修正 v8 的隐含前提。v8 用"每概念内部 k-means"保证质心纯净；一旦改用全局聚类，质心会横跨多个 owner。解法不是禁止混合，而是**把桶切到 (centroid, concept)**。

## 1. 问题

- item 按 owner 落到概念节点上；
- 质心若全局训练，`μ` 内可能同时含 owner=A、A′、B 的 item；
- 此时"质心合格"与"item 合格"不再等价：`U={A}` 时 `μ` 只有部分成员合格。

若仍按质心整体扫描，低选择率下要扫完整倒排；若按质心整体剪枝，会丢答案。

## 2. 解法：桶 (μ, c)

```text
bucket(μ, c) = [ i : centroid(i) = μ 且 own(i) = c ]
```

- 每个 item 恰好属于一个桶（唯一质心 + 唯一 owner）。
- **桶内所有 item 同 owner ⇒ 桶级剪枝精确。**
- 质心允许混合概念；剪枝精确性不依赖聚类策略。

于是"聚类质量"与"剪枝正确性"解耦：可以放心用全局 k-means 或任何聚类，只要求桶按 owner 切。

## 3. 结构

| 层 | 内容 |
|---|---|
| 质心图 | HNSW，节点 = 质心（FP32）；概念内/跨概念由合并规则决定 |
| 质心表 | 质心 → (FP32, 概念集合描述, 桶目录) |
| 桶目录 | 每质心：按 concept_id 排序的 `(c, offset, count)` |
| 桶数据 | item ID 连续存放；item 编码 `(centroid_id, 2bit/维 残差码)` |
| 概念层 | 闭包位图 `Desc⁺/Anc⁺`、owner 倒排、属性子树计数、Trie |

**概念集合描述**按 `|V|` 选型：

| `V` | 表示 | 字节/质心 |
|---|---|---|
| ≤ 8k | 位图 `V/8` | 1929 概念 → 242 B |
| > 8k | 排序 `concept_id` 数组 + 64 位 Bloom | 4·d_μ + 8 |

`K = n/B`。`V=1929`、`B=64` 时质心概念位图总计约 0.6 MB。

## 4. 构建

```text
1. DAG 划分、闭包位图、owner 倒排、属性子树计数
2. 聚类（自由选择策略）：全局 k-means，或按概念内部 k-means，或两者混合
   得到 item → centroid 映射
3. 分桶：按 (centroid, owner) 聚合 item，桶内按 item ID 排序
   生成桶目录（concept_id 升序）
4. 残差编码：r = x − μ；共享分位点 2bit 标量量化
5. 质心图：按 v7 的合并规则（插入顺序 × 重插/保边，2×2）
6. 质心概念位图或排序数组
```

## 5. 查询

```text
1. D ← ⋂_组 ⋃ Desc⁺；属性子树 0 命中整概念剔除
2. E ← D ∪ Anc(min D)
3. 质心可访问条件：Σ(μ) ∩ E ≠ ∅        # 位图/排序数组与 E 求交
   质心可出结果条件：Σ(μ) ∩ D ≠ ∅
4. 质心图 best-first；展开前 Bloom 否定则跳过邻接
5. 访问 μ：只用"桶级"判据
     for (c, offset, count) in buckets(μ):
         if c ∉ E: continue            # 桶级剪枝，精确，不打开
         扫该桶 item：重建距离打分
         若 c ∈ D 且过属性 → 候选
6. 每桶保留前 k′，全局候选缓冲合并；可选 FP32 refine
7. 结果 top-k；不足 → 回退到 Ant(D)
```

关键：**精确性由桶提供，而不由质心提供**。混合质心只影响"能否跳过整个质心"，不影响"桶内 item 是否合格"。

## 6. 代价

| 项 | 内容 |
|---|---|
| 桶目录 | 每条目 12 B（c 4 + offset 4 + count 4） |
| 桶数 | `Σ_μ #concepts(μ)`；概念纯净时 = `K`，全混合时 ≤ `n` |
| 最坏桶目录开销 | `n × 12 B`（若每桶仅 1 item），此时应改用概念内聚类 |
| 查询扫描量 | `Σ_{admitted buckets}` 的 count，而非整质心 |
| 剪枝粒度 | 从"质心"细化到"桶"，混合质心的损失被限制在桶级 |

## 7. 何时用哪种聚类

| 条件 | 建议 |
|---|---|
| `n_c ≫ B`（大概念） | 概念内 k-means：桶数 ≈ K，剪枝最紧 |
| `n_c ≪ B`（小概念多） | 全局 k-means：桶数 = 桶(μ,c) 对，避免每概念只有半个质心 |
| 混合 | 大概念内部聚类，小概念交给全局质心；**两种都只用桶结构** |

## 8. 12-item（构造混合质心）

设全局 k-means 得 `μ1 = {a1, b1, f1}`，其余按概念各一质心。

| 桶 | 内容 |
|---|---|
| (μ1, A) | a1 |
| (μ1, B) | b1 |
| (μ1, F) | f1 |

查询 `U={A}`：`D={A,C,F}`、`E={R,A,C,F}`。

- `Σ(μ1)={A,B,F} ∩ E ≠ ∅` → 质心可访问；
- 桶级：`(μ1,A)`、`(μ1,F)` 打开（∈D）；**`(μ1,B)` 因 `B∉E` 直接跳过，不扫 b1、不算距离**；
- 若按 v8 的质心整体扫描，b1 会被扫到，只是不能进结果。

## 9. 与 v8 的差别

| 项 | v8 | v9 |
|---|---|---|
| 聚类约束 | 必须概念内（纯净） | 任意策略 |
| 剪枝单位 | 质心 | 桶 (μ,c) |
| 混合质心 | 不允许 | 允许，损失限制在桶级 |
| 额外空间 | — | 桶目录 12 B/桶 + 质心概念位图 |
| 小概念问题 | 质心碎片化 | 可交给全局质心 |

## 10. 待验证

1. 同 `B` 下比较三种聚类（概念内 / 全局 / 混合）的桶数与查询扫描量；
2. 桶目录开销在概念数极大时的上界；
3. 失败判据：全局聚类的桶数接近 `n`（每个桶 1 item）时，桶目录与随机访问成本抵消压缩收益，应退回概念内聚类。
