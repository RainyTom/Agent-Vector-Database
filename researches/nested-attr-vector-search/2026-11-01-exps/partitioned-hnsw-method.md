# 面向动态目录约束的分区 HNSW 检索方法

> 可审阅的方案正文。描述当前已实现的结构，不引入新的方法缩写；未将常规组件组合认证为新颖贡献。依据源码`922281c`及后续结构勘误`eafd563`，主查询配置为DFS装箱＋小候选集精确扫描回退。

## 摘要

研究带目录范围与对象属性过滤的向量top-k检索。每个对象具有独立的逻辑归属目录和物理图分区。元数据侧保存直接目录成员的稀疏位图倒排表及对象属性记录，查询时在线展开目录子树并计算精确候选集。向量侧将按目录DFS顺序排列的完整直接成员组装入若干平坦分区，每个分区维护一张普通HNSW。查询依据候选集大小选择精确扫描，或搜索所有含候选对象的分区并归并结果。逻辑目录移动不强制修改几何图，但会逐渐破坏初始目录共置；插删、局部重建及显式重装箱承担相应维护成本。该结构不提供新的距离下界或跨分区导航，已观察收益主要来自过滤计划、分区组织与posting实现效率。

## 1. 问题定义与系统边界

令目录树为T，目录集合为V，固定对象ID空间为U。对象i保存向量x_i∈R^d、逻辑owner o_i∈V、属性a_i及存活标记live_i。N=|U|，D=|V|。原型中的向量内容不随事件改变，插入/复活只激活U中已有向量，不支持任意新ID扩容或向量替换。

查询q=(z,u,r,φ,k)：z为查询向量，u为anchor目录，r指示是否递归包含后代，φ为属性谓词。定义目录范围

\[
\mathcal D_q=\begin{cases}\{u\},&r=0,\\\operatorname{Desc}(u)\cup\{u\},&r=1,\end{cases}
\]

\[
S_q=\{i\in U\mid live_i\land o_i\in\mathcal D_q\},\qquad
E_q=\{i\in S_q\mid\phi(a_i)\}.
\]

目标是在E_q内按原始FP32 squared-L2距离返回top-k，距离相同按对象ID排序。定义k'=min(k,|E_q|)。精确扫描路径计算精确top-k'；HNSW路径提供近似结果，不能保证固定ef下的Recall或将局部近似结果解释为全局精确top-k。

当前属性包括category等值、numeric闭区间和tags集合测试，支持启用谓词组的AND/OR组合，并非任意嵌套布尔表达式引擎。**层级属于目录树，不属于这些平坦属性。**当前系统为单线程事件重放，不主张并发线性化、事务隔离或崩溃恢复。

## 2. 设计原则

1. **逻辑归属与物理位置解耦。**由o_i判断目录资格，由loc(i)定位向量图；移动owner不必立即搬图。
2. **元数据过滤精确，向量检索可近似。**先确定E_q，随后由候选规模选择向量执行路径；求E_q的成本完整计入查询。
3. **分区是平坦集合。**目录顺序影响初始分组，不额外构建目录层级上的ANN路由。
4. **维护账目不隐藏。**插删可能触发压实或split；恢复初始局部性需显式repack，不能作为免费后台操作。

### 3.1 目录成员倒排表

每个目录v保存其直接成员集合L_v，不物化所有祖先的聚合成员集合：

\[
L_v=\{i\mid live_i\land o_i=v\}.
\]

表示为按word编号排序的稀疏向量P_v=[(w,bits)]。w=⌊i/64⌋，bits的第i mod 64位表示对象i是否属于v。不存在非零bit的word不保存。目录拓扑采用parent/children邻接表示，存活状态另存全局位图。

category/numeric/tags保存在按ID寻址的对象记录中。当前没有为每种属性各建独立倒排表或范围树。`scope`与`eligible`是可复用查询工作位图，不是每目录持久的子树聚合集。

### 3.2 平坦分区与HNSW

物理分区集合记作B_1,…,B_P。每个存活对象恰属于一个分区，loc(i)=b。每分区保存成员ID列表、一张普通HNSW和容量目标t_b。home(v)指定目录v中新激活且无原位置对象的默认落点。

分区图只包含该分区的对象，分区间没有导航边。每张HNSW内部的导航层来自HNSW自身机制，与目录父子层级独立。实现还保留原始向量数组，hnswlib图内有其自己的向量存储，不能把“每对象只属于一个图”写成“进程中向量只有一份物理副本”。

### 3.3 必须维护的不变量

- **目录成员一致性**：倒排表与当前存活owner完全一致。
- **物理覆盖一致性**：每个存活ID有且只有一个有效loc，且其对应分区图可检索该ID；墓碑不视为存活成员。
- **结果资格一致性**：仅E_q内对象可以进入最终结果。

不要求o_i与loc(i)永远保持初始装箱关系。动态split可切开同一目录组；owner移动后，同一目录也可散落多区。该差异影响成本，不应影响过滤正确性。

## 4. 初始构建

1. 建目录邻接关系与直接成员posting。
2. 计算目录DFS次序，以owner的DFS rank及ID顺序分组；对象ID不重编号，原始向量不因该次序重排。
3. 对非空目录组执行next-fit装箱：当前组能放入当前分区则合并，否则开启新分区。
4. 大小达到或超过B的目录组独占分区；因此B是装箱目标，不是分区大小硬上限。
5. 每区构建普通HNSW，记录loc、home和t_b=max(B,|B_b|)。DFS主配置的图容量为2t_b。

DFS只使相邻目录组有机会共置。**分区并不保证恰好对应一棵完整子树，也没有几何紧致性保证。**随机目录次序装箱、每目录单独一图是组织对照，不作为另外两种ANN方法。

分组/次序整理可用计数散射在O(N+D)完成；HNSW构建成本另记为各分区实际构建成本之和，不主张最坏O(N log N)。

## 5. 查询处理

![查询流程](figures/partitioned-hnsw-query-outlined.svg)

### 5.1 精确候选集合

在线枚举D_q，并对P_v执行按位OR，得到scope位图；与live位图相与后逐条读取对象属性，得到E_q及e=|E_q|。这一步不访问向量距离。

这种设计避免了祖先成员物化的更新放大，但每次查询都要付出子树展开、posting合并和属性过滤的代价。当前不能通过目录上的属性摘要直接排除整片子树。

### 5.2 小候选集精确扫描

若e=0，直接返回空结果；若0<e≤τ，枚举E_q，精确计算每个候选到z的距离，以大小k'的堆维护结果。

当前P臂hybrid策略中τ=max(512,k,ef)，固定k=10、ef=20时τ=512。该阈值是既有协议的选择，不是由本轮理论推导出的最优值。扫描发生在**属性过滤后的候选集**，不是扫描整个目录scope。

### 5.3 分区分发与图搜索

当e>τ时，按loc统计

\[
c_b=|E_q\cap B_b|,\qquad \mathcal A_q=\{b\mid c_b>0\}.
\]

对所有b∈A_q执行一次图查询：

\[
k_b=\min(k,c_b),\qquad ef_b=\min(c_b,\max(ef,k_b)).
\]

callback只允许E_q中的ID进入结果候选堆。不合格对象仍可能被HNSW计算距离和用于导航；不能将该执行描述为只遍历合格谓词子图。

当前没有对A_q中的分区作几何优先级排序、距离下界剪枝或提前终止。跳过c_b=0的分区是精确元数据排除，且要在完整候选集求出之后才能执行。

### 5.4 跨分区归并与正确性边界

每区返回至多k_b个近邻候选，统一按(距离,ID)归并，得到至多k'个结果。

**性质1：候选覆盖。**由loc唯一性，E_q被E_q∩B_b按分区无重复地覆盖；任意c_b=0分区不可能包含合法结果，跳过它不会丢失合法top-k。

**性质2：局部精确top-k足以归并。**若每个分区返回其合格集合的精确top-min(k,c_b)，则它们的并集包含全局精确top-k'。理由是全局top-k中的对象在其本分区内的排名不可能大于k；并列距离采用统一ID次序处理。

性质2的前提**不由固定ef的HNSW保证**。当前近似误差来自局部图搜索，可能造成全局漏召回；分区覆盖正确不能当作ANN Recall保证。

### 5.5 算法摘要

```text
Query(z, anchor, recursive, predicate, k):
    S ← union of direct-owner postings in the requested directory scope
    E ← live members of S satisfying predicate
    if |E| = 0: return empty
    if |E| ≤ τ: return ExactTopK(z, E)
    count candidates in each physical partition using loc
    H ← empty global top-k heap
    for every partition b with c_b > 0:
        R_b ← FilteredHNSW(G_b, z, k_b, ef_b, allow=E)
        merge R_b into H using (distance, ID)
    return H in ascending order
```

## 6. 动态维护

| 事件 | 逻辑状态变化 | 对物理图的影响与成本 |
|---|---|---|
| V/T：属性修改 | 写category/numeric或tags；同步元数据副本 | 不修改图，固定宽度字段更新为O(1) |
| M：单对象owner移动 | 从旧目录posting删位、向新目录加位，修改owner | loc不变，不修改图；posting新word的插入/删除可搬移O(W)条目 |
| B：批量移动 | 找出源子树存活对象并逐个移动到目标目录 | 至少Ω(m)，还需取得源范围并维护posting；不搬几何图 |
| R：目录重挂 | 改parent/children并检查环 | 当前重算DFS rank为O(D)，既有物理分区不随之重排 |
| D：删除 | 删除owner位、清live并标记图墓碑 | 还需在分区成员列表线性定位；墓碑占比达1/3或区空时重建该图 |
| I：激活/复活固定ID | 更新owner、属性与live，登记posting | 有旧loc则优先原位，否则home；插图/复活标记；可能压实或分裂 |
| repack：显式重装箱 | 保留逻辑状态，重建loc/home | 丢弃旧分区，按当前owner与DFS次序重新装箱并重建全部图 |

W为相关目录posting的非零word条目数，m为批量移动对象数。有序posting查找为O(log W)；已存在word内改位不需搬移，新增word或删除空word最坏O(W)。不能把这一类更新写成普遍O(log N)或O(1)。

分区的动态增长不是“超过B就分裂”：当新活成员使大小超过2t_b时，按当前owner rank与ID排序后取中点分成两区，分别设置新目标并重建HNSW。中点可以落在同一owner组内部。

repack是恢复局部性的显式操作，不是正确性的必要前提，也没有在当前主查询结果中摊销。原型不声称多版本快照、原子可见性或任意并发更新安全。

## 7. 成本模型

令n_w=ceil(N/64)，d_q=|D_q|，l_q=Σ(v∈D_q)|P_v|，s=|S_q|，e=|E_q|，p为启用的属性谓词组数，P为物理分区数。

元数据求值工作量为

\[
T_{meta}=O(d_q+l_q+n_w+s\,p).
\]

其中n_w来自位图清空及扫描；s·p来自逐对象属性判断。该结构没有将该成本降低为只依赖e的输出敏感复杂度。

精确扫描路径：

\[
T_{small}=T_{meta}+O(ed+e\log(k'+1)).
\]

图路径：

\[
T_{graph}=T_{meta}+O(n_w+e+P)+\sum_{b\in A_q}H_b+O(R\log(k'+1)).
\]

H_b包括实际局部HNSW与局部候选整理成本，R≤k|A_q|为归并候选数上界。显式P项来自分区计数初始化和遍历；没有只访问非空分区的压缩调度索引。H_b取决于过滤密度、图连通性、ef和数据分布，不给出未经证明的对数最坏界。

除向量和HNSW本体外，元数据空间为O(N+D+Σ_v|P_v|+P)，查询位图工作区O(N/64) words、分区计数O(P)。ID散布可能使Σ_v|P_v|较大；连续vector改善访问成本，不改变集合关系或渐近工作量。

## 9. 与已有工作的关系

[TrieHI](https://arxiv.org/pdf/2606.16903v1)在ANN上方以稳定目录节点及inclusive-ID集合解析scope；本方案用直接成员表在线展开，承担不同的查询/更新取舍。[Weaviate Filtering](https://docs.weaviate.io/weaviate/concepts/filtering)已采用allow-list＋HNSW及flat-search cutoff，故不能将这些执行组件单独列为首创。[Curator](https://arxiv.org/pdf/2601.01291v3)利用共享几何层次、标签自适应粒度与路由；本方案没有对应的层级ANN结构。[iRangeGraph](https://arxiv.org/pdf/2409.02571v1)按范围组合邻接，本方案没有按scope改变图边。

更完整版本、章节和命名核对见[当日审查](report.md)。不以组件均有前序为由否定所有组合研究，也不以组合性能好为由直接宣布新颖性。

## 10. 可供调整的设计位置（均未在本文实现）

| 位置 | 当前限制 | 调整需要回答的问题 |
|---|---|---|
| 元数据求值 | 宽scope仍枚举大量posting/对象 | 是否增加属性索引或目录摘要；节省的查询工作能否覆盖更新与空间成本？ |
| 分区组织 | 只按目录次序/容量装箱，无几何或工作负载目标 | 应优化调用数、过滤密度还是几何连通性；如何避免只省调用却增加图遍历？ |
| 跨区搜索 | 所有非空合格分区都搜，无几何剪枝 | 能否给出可维护的排除依据，而不是用启发式漏搜换速度？ |
| 区内过滤 | 不合格节点仍可算距离 | 是否需要新邻接取得/遍历规则；与已有ACORN等究竟差在哪里？ |
| 计划选择 | 固定候选计数阈值τ | 应否考虑d、每区密度、图扇出；额外估计是否比节省的成本更贵？ |
| 动态漂移 | owner移动后物理局部性下降 | 哪些查询指标能刻画退化，且不把全量repack隐藏到测量之外？ |

这六处是审阅接口，不是承诺实施的新机制，也不恢复已停止候选。先确定要改变的结构及其可验证性质，再决定是否值得实验。
