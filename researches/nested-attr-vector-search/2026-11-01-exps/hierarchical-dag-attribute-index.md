# DAG 层级属性约束下的内存向量检索

## 摘要

研究对象是具有 DAG 层级属性的向量集合，向量与全部索引驻留内存。细粒度标签使对象满足全部祖先条件，多路径、多标签按对象 ID 去重。**当前实现属于本项目 NodeANN 的分组粒度变体**：仍是每组普通 HNSW、搜索相关图、合并局部 top-k；区别在于把多个直接标签组并入较粗的图，并配合范围解析与小集合扫描。

倒排、DAG 闭包和可选继承成员物化服务于过滤语义，不构成新的 ANN 搜索机制。这份说明用于界定 NodeANN 类基线及其变体，不作为独立新索引的贡献陈述。研究目标仍是找到 DAG 语义能够支持的额外算法信息，在同质量下减少搜索/距离计算并控制更新；当前分组变体尚未给出这样的增量证明。

### 研究范围与判定标准

- **全驻内存**：不以磁盘块、SSD I/O 或外存页面访问为问题模型。
- **不以访存工程为贡献**：连续排布、结构体布局、缓存局部性、SIMD、预取、压缩及为访问顺序重排对象，不作为本方向的优化机制或论文贡献。不同算法固定相同距离核和实现条件。
- **算法优化须说明减少了什么操作**：哪些概念/posting 无需展开、哪些图无需启动、哪些节点/边无需扩展、哪些向量距离无需计算，以及为何保持过滤语义和目标 Recall。
- **结构变化不等于布局变化**：把对象分配给不同 ANN 图会改变图的节点集、邻接和查询调度；这里只研究这些算法状态，不要求同组向量连续放置。
- **时间与机制分别举证**：完整查询时间、实际 macro/pair Recall 是效率结果；图调用数、节点/边扩展数、距离计算数和元数据枚举量用于机制归因。现有 query20 结果缺少完整操作计数，不能据耗时差证明减少了距离计算，也不能归因为缓存收益。
- **NodeANN 是执行器组件，不是要打败的对手**：按概念分组的局部图作为向量搜索后端，贡献层放在 DAG scope 解析与跨局部图调度上。方法学参照 TrieHI 的分层归因（固定 ANN 执行器、只变元数据层、单列 scope 解析时间）；它与本问题的差异见[定位分析](triehi-baseline-and-dag-positioning.md)。

## 1. 数据模型与查询

属性层级为有根 DAG $G=(V,E)$，边由一般概念指向细化概念。$u\preccurlyeq v$ 表示 $u=v$ 或存在从 $u$ 到 $v$ 的路径。自反可达闭包为

\[
\operatorname{Anc}^{+}(v)=\{u:u\preccurlyeq v\},\qquad
\operatorname{Desc}^{+}(v)=\{w:v\preccurlyeq w\}.
\]

对象 $o_i=(id_i,x_i,L_i,a_i)$ 具有向量 $x_i\in\mathbb R^d$、直接标签集 $L_i\subseteq V$ 与其他属性 $a_i$。继承标签集为

\[
A_i=\bigcup_{c\in L_i}\operatorname{Anc}^{+}(c).
\]

概念条件 $u$ 的 scope 为 $S(u)=\{i:live_i\land u\in A_i\}$。查询 $Q=(q,U,\varphi,k)$ 采用概念条件的并集：

\[
F_Q=\{i:live_i\land A_i\cap U\ne\varnothing\land\varphi(a_i)\}.
\]

$U$ 可删去被祖先条件覆盖的冗余概念，但不能因为已取得足够候选而忽略尚未处理的条件。输出 $F_Q$ 内按原始 FP32 squared-L2、对象 ID 次序取前 $\min(k,|F_Q|)$ 个对象；过滤与去重精确，近似性仅来自 ANN 的近邻选择。

非空查询 Recall 的分母固定为 $\min(k,|F_Q|)$，返回不足不缩小分母。macro Recall 对非空查询等权；pair Recall 为全部命中数除以全部精确答案数。空查询单独计数，不计作 Recall=1。完整查询计时包括工作区建立、范围解析、基数统计、分区定位、搜索与归并；GT、结果核验、日志及构建单列。

### 1.1 DAG 结构的作用

- $u\preccurlyeq v\Rightarrow S(v)\subseteq S(u)$，因此粗粒度条件覆盖细粒度条件。
- 互非祖先的概念也可能共享后代，因而 scope 可以相交。
- 直接标注内部概念，只满足它及其祖先，不能推出属于某个特定后代。
- 概念闭包按可达集合去重；成员并集再按对象 ID 去重。

下文用同一组七概念、八对象贯穿构建、查询与更新；图 1 展示保存的索引，图 2 展示查询工作区和执行过程，图 3 展示标签更新触及的状态。图中的对象 ID、分区名和计算结果与正文一致。

## 2. 索引结构与构建样例

下面按依赖顺序逐项介绍。检索索引分为标签成员索引（直接倒排、可选继承倒排）和向量近邻索引（HNSW）；DAG 闭包、对象到图映射和计数是辅助状态，不另起新索引名称。记 D=|V|、N 为对象 ID 容量、W=⌈N/64⌉。

### 2.1 贯穿全文的八对象例子

概念 ID 固定为 R=0、A=1、B=2、C=3、D=4、E=5、F=6。DAG 的边为 R→A、R→B、R→F、A→C、A→D、B→C、B→E。**C 同时有父概念 A、B**。对象按下表编号；本例每对象只有一个直接标签，全部存活，其他属性谓词为 true。

| 对象 ID | 向量 $x_i$ | 直接标签 | 继承概念集 | 所属局部图 |
|---|---|---|---|---|
| o0 | (0,0) | A | {R,A} | b_A |
| o1 | (1,0) | C | {R,A,B,C} | b_A |
| o2 | (2,0) | D | {R,A,D} | b_A |
| o3 | (0,2) | C | {R,A,B,C} | b_A |
| o4 | (3,0) | B | {R,B} | b_B |
| o5 | (0,3) | E | {R,B,E} | b_B |
| o6 | (4,4) | F | {R,F} | b_F |
| o7 | (5,5) | R | {R} | b_R |

取分组深度 h=1；具有 A、B 祖先的 C 以较小稳定 ID 的 A 为分组键。因此 o1、o3 满足 B 条件，却是局部图 b_A 的节点。查询 B 必须考虑这张图；该归属不约束向量的内存地址或排列次序。

### 2.2 第一项：直接标签倒排 P

**存什么。** 键是概念 ID，值是“直接标注该概念”的对象 ID 集合：

\[
P(c)=\{i:live_i\land c\in L_i\}.
\]

本例有 P(B)=[o4]、P(C)=[o1,o3]、P(E)=[o5]。P(B) 只收直接标签为 B 的 o4，不把 C、E 的对象预先写进来。

**怎么建立。**

1. 为每个概念创建空列表。
2. 遍历存活对象及其直接标签；看到对象 i 直接标注 c，就把 i 加入 P(c)。
3. 将各列表按对象 ID 排序并去重。当前代码使用 `Workload.postings` 的 `vector<uint32_t>`。

**为什么建立。** 查询已知概念后，需要找到相关对象 ID。倒排把“遍历全部对象并检查标签”变为“读取指定概念的成员列表”。它索引的是标签，不计算向量距离。

**查询时怎么用。** P(B) 回答“直接标注 B 的对象有哪些”；本方案查询采用继承匹配，因此还要读取后代概念的列表。要知道后代有哪些，使用下一项 DAG 结构。

**更新什么。** o6 从 F 改为 B 时，只从 P(F) 删除 o6，向 P(B) 加入 o6；其他直接列表不变。排序列表插删仍可能移动 ID，这项成本不能忽略。

对应图 1 的 **②直接倒排**。这是普通标签倒排，不是新型 ANN。

### 2.3 第二项：DAG 邻接与可达闭包表

**存什么。** 这是一项层级辅助结构，处理“概念之间的关系”，不存对象向量：

- `children[c]`、`parents[c]`：直接子概念、直接父概念；
- `Desc⁺[c]`、`Anc⁺[c]`：含自身的全部可达后代、祖先。

本例 `parents[C]=[A,B]`，`children[B]=[C,E]`，`Desc⁺[B]=[B,C,E]`，`Anc⁺[C]=[R,A,B,C]`。这些列表里的元素是概念 ID，不是对象 ID。

**怎么建立。**

1. 读每条父→子边，分别写入 children、parents。
2. 对每个概念沿 children 遍历，得到 Desc⁺；沿 parents 遍历，得到 Anc⁺。
3. 每次遍历使用访问集合，同一概念只收一次。因此 R 即使经 C 的两条父链到达，也只在 Anc⁺(C) 中出现一次。

当前 `Graph` 保存去重后的闭包 ID 列表。完整闭包表是查询/更新的可复用结果；也可以只存邻接、按需遍历，代价是重复计算可达集合。

**为什么建立。** 直接倒排不理解继承。该结构把查询 B 转成直接标签集合 {B,C,E}，也把标签 C 的变化转成可能受影响的祖先 {R,A,B,C}。它解决层级匹配，而非近邻导航。

**查询时怎么用。** 在线计算

\[
S(B)=P(B)\cup P(C)\cup P(E)=\{o1,o3,o4,o5\}.
\]

**更新什么。** 只改对象标签时，概念间可达关系不变，因此不用修改此表；改分类边时才需要维护受影响闭包。

对应图 1 的 **①属性 DAG** 与右侧闭包示例。邻接是输入层级的表示，闭包表是辅助查表结构，不单独包装成一种新向量索引。

### 2.4 第三项：继承成员倒排 M，可选

**存什么。** P 只保存直接成员；M 为选中的概念预先保存继承范围内的全部不同对象：

\[
M(u)=\bigcup_{c\in Desc^+(u)}P(c)=S(u).
\]

在本例中，若选择物化 B，则 M(B)={o1,o3,o4,o5}。当前实现用对象 ID 位图表达集合；图中的 `01011100` 从左到右对应 o0…o7，不按数值二进制串解释。

**怎么建立。**

1. 选一个需要保留派生成员集合的概念 u。
2. 取 Desc⁺(u)，依次读取其中概念的 P。
3. 将所有对象 ID 求并集并去重，存为 M(u)。

**为什么建立。** 如果每次都在线展开 B，就要反复遍历后代概念并合并 P(B)、P(C)、P(E)。M 保存的是这次集合推导的结果，下次可以直接取得同一范围，属于“增加索引状态，减少重复推导”的取舍。它不缓存查询答案，也不包含向量距离。

**查询时怎么用。** 有 M(B) 就读 M(B)，没有就用 P 与 Desc⁺ 在线求并集；两条路径必须得到相同成员，随后使用相同的向量索引。M 是可选项，去掉它仍能正确解析范围。

**更新什么。** 成员资格变化时维护相关已物化集合。例如 o6:F→B 后，在 M(B) 加入 o6。存在多标签或多条路径时，必须按成员资格变化维护，不能重复加减；详见 §4。

**哪些概念物化。** 记对象容量为 N、W=⌈N/64⌉。当前探针以

\[
\widehat E(u)=|Desc^+(u)|+\sum_{c\in Desc^+(u)}|P(c)|
\]

作为展开工作量代理，在预算内优先选择代理值较大且超过 W 的概念。该启发式没有最优性保证。本例显式选 B 只用于展示这条查询分支，不宣称八对象时规则会自动选 B。研究取舍是集合推导操作与维护状态，不是位图连续存储的访存优势。

对应图 1 的 **③物化位图**。它是从 P 派生的继承成员倒排，不是另一张 ANN 图。

### 2.5 第四项：NodeANN 类局部 HNSW，负责向量近邻

**存什么。** 每个非空对象组建立一张普通 HNSW。图中节点是向量对象，边由 HNSW 的近邻构建算法产生，不是属性 DAG 的父子边。

**怎么建立：先确定每张图有哪些对象。** 选择分组深度 h，从根计算概念最短深度，定义

\[
g_h(c)=\begin{cases}
c,&depth(c)<h,\\
\min\{u\in Anc^+(c):depth(u)=h\},&depth(c)\ge h.
\end{cases}
\]

单直接标签 c 的对象加入以 g_h(c) 为键的组；多直接标签方案取各标签分组键的最小值。本例 h=1，C 同时有 A、B 祖先，按较小稳定 ID 选择 A，因此得到：

- b_A 的节点为 {o0,o1,o2,o3}；
- b_B 的节点为 {o4,o5}；
- b_F 的节点为 {o6}；
- b_R 的节点为 {o7}，因为 o7 直接标注根。

**怎么建立：再为组内向量连边。**

1. 为每个非空组创建一个 hnswlib `HierarchicalNSW`，当前参数 M=16、efConstruction=200。
2. 逐个调用 `addPoint(x_i, external_label=i)`。层数采样、近邻候选搜索、邻居选择与连边由既有 HNSW 实现完成；不是按概念父子关系或对象编号直接连边。
3. 保存图入口及节点记录。节点包含局部 ID、全局对象 ID、向量、随机层数和每层的局部邻居 ID。

本例实际构建的 b_A 入口为 local0/o0，max_level=0；local1/o1 的向量是 (1,0)，L0 邻居为 [0,2,3]。四节点在该次 L0 构建中两两相连；这不表示一般 HNSW 是完全图。HNSW 层与属性概念深度互不等同。

**为什么建立。** 前三项只得到合格对象 ID，没有告诉我们哪些向量最近。候选很多时逐个计算距离需要处理全部合格向量，HNSW 提供近似近邻搜索路径；小集合则直接精确扫描。局部图分组用于研究如何选择要搜索的图，不要求同组向量连续存放，也不保证一定比全局图少做计算。

**查询时怎么用。** 查询 B 得到 {o1,o3,o4,o5} 后，搜索 b_A 与 b_B，并以该合格集合过滤返回对象；不能只搜索名字为 B 的图。图中 o0、o2 可以参与导航，但不能成为 B 查询的结果。局部输出最终按距离与全局 ID 合并。

**更新什么。** 标签变化保留对象原来的图成员归属，不重建几何图；代价可能是后续查询搜索更多图。向量变化、插删及图修复是另一类维护，不能按标签改动成本计量。

对应图 1 的 **④局部图表与⑤实际邻接**。这与 NodeANN 属于同一算法范式，没有新增 HNSW 连边或图内遍历规则。

#### 与本项目 NodeANN 的具体关系

这里 NodeANN 指[现有纯图主基线](../../../codes/directory-aware-vector-attr-search/README.md)：每个非空直接概念组建立 HNSW，查询相关组后合并结果。

| 项目 | NodeANN | 当前分组变体 |
|---|---|---|
| 一张图的成员 | 一个直接概念的成员 P(c) | 多个直接概念组的并集 |
| 图内算法 | 普通 HNSW | 普通 HNSW |
| 查询主干 | 查相关局部图，合并 top-k | 查相关局部图，合并 top-k |
| 分组内过滤 | 单概念查询对应的直接组可整体合格 | 合并图内可能混有不合格对象，需要过滤结果 |
| 可选执行策略 | 本项目纯主基线关闭扫描回退 | 当前探针有范围预选和小集合扫描；应单独消融 |

同一八对象例子中，DAG 语义下查询 B：

- NodeANN 对应直接组图 I_B={o4}、I_C={o1,o3}、I_E={o5}，搜索这三张图后合并。
- 当前变体把直接组 A/C/D 并入 b_A，把 B/E 并入 b_B，因此查询 b_A、b_B；其中 o0、o2 不能成为 B 的答案。

两者的精确 top-2 都是 o1、o3。合并组把本例相关图从三张变为两张，但可能增加图内不合格节点和距离计算；这不是总工作量减少的证明。分组变化会改变 HNSW 节点集与邻接，因此也不能保证一般 ANN 结果和 Recall 完全相同。

DAG 的后代去重、直接成员查找、继承集合物化都可以用于 NodeANN，不能只给变体这些能力再把收益归为新 ANN。现有旧 NodeANN runner 的输入是单亲树，公平比较需要对齐 DAG 语义；该适配是正确性要求，不独立构成新搜索算法。

现有 query20 耗时对照是全局过滤 HNSW，尚未证明优于同语义 NodeANN。分组变体保留为基线/消融，不作为独立研究方案的创新证据。

该样例的直接组、合并组、相关图与精确答案推导见[结构核对](data/nodeann-grouping-structure.json)。这是分组关系计算，不是新的 NodeANN 实测，也不证明两种 ANN 在一般数据上的输出等价。

#### 查询准备的区别

在仅有层级条件、每对象单直接标签时，NodeANN 逻辑可以根据 Desc⁺(B) 直接选取 B/C/E 的图，所选图的成员整体合格。当前合并组实现则先求完整 scope 位图，再枚举合格 ID，通过 b(i) 统计每张图的合格数量；这增加了对象级范围解析与调度工作。若再增加其他属性谓词，NodeANN 也可能需要对象级过滤，不能把“整组合格”外推到任意谓词。

两者图内均使用普通 HNSW。合并图内的 callback 限制返回资格，但不排除不合格点参与导航/距离计算。当前局部 ef 按合格数截断、小集合扫描和物化也属于执行条件，需要与分组粒度分别对照；相同名义 ef 不代表相同计算量。

#### 八对象的实际工作量对照

为只观察分组影响，两个配置共用当前 DAG 的 `run_query`/`search_graph`、相同 squared-L2、k=2、ef=20、构建参数与插入次序；关闭物化和扫描（τ=0）。比较的是 NodeANN 式直接组与合并组，不是旧纯 NodeANN CLI 的端到端基准。

| 查询 B 的实际量 | 直接概念组 | 合并组 |
|---|---:|---:|
| 图调用数 | 3 | 2 |
| 距离函数调用数，含重复 | 7 | 7 |
| 被计算距离的不同对象数 | 4 | 6 |
| 对不合格对象的距离调用数 | 0 | 2 |

两者均返回 o1、o3。合并组还对 o0、o2 计算了距离。该例中少一次图调用没有减少总距离调用；不能由此推广其他查询或真实数据的胜负。计数覆盖当前搜索包装器、入口及底层查询的距离调用，构建和 oracle 排除；它不是节点扩展数或时间。[实测数据](data/nodeann-grouping-work.json)、[命令与边界](experiments/dag-worked-example.md)。

#### 标签更新的区别是策略条件

若 NodeANN 始终保持“某图等于当前直接标签组”，o6:F→B 就需要从 F 图移除、向 B 图加入节点。当前设定保留 o6 的图成员归属，仅更新标签范围，随后查询 B 还需调用 b_F。这是维护成本与后续查询 fanout 的交换，未实测完整维护性能。

这项差异不属于 NodeANN 范式不可改变的限制：若给 NodeANN 也采用冻结初始分组、按当前标签过滤的策略，该区别就会消失。分类边变化也不同于对象直接标签变化；直接组不变时，不能笼统认为 NodeANN 必须重建几何图。

### 2.6 关联表、计数和工作区：不再算作独立新索引

**对象到图映射 b。** 为对象决定分组时同时记录 `b(i)=图编号`；创建图实例时把实例加入局部图表。它把前三项输出的 ID 接到第四项。例如 b(o1)=b_A、b(o4)=b_B，因此 B 查询启动两张图。这里记录的是成员归属，不是内存地址。

**基数 C(u)。** 对 S(u) 中不同对象计数即可建立；若长期保存，则成员资格增删时同步维护。C(B)=4、C(A)=4，但并集只有 6，不能把两个计数直接相加当作精确结果。当前更新探针维护 `Strategy.cardinality`，ANN 查询探针使用 `scope.count()`，没有用持久计数代替范围解析。

**查询工作区。** `scope`、属性过滤后的 `eligible`、每图合格数及候选结果属于本次查询的中间状态，不是持久索引。该工作区仍需计入完整查询成本。

### 2.7 图 1：把已经说明的各项接起来

![图1：直接倒排、DAG辅助结构、可选继承倒排与局部HNSW之间的关系](figures/dag-index-layout-outlined.svg)

图中先由 P 与 DAG 闭包求成员，或读取可选 M，再根据 b 选择 HNSW。`b_R0`、`b_A1`、`b_B2`、`b_F3` 的末尾是图编号 0、1、2、3；正文简称 b_R、b_A、b_B、b_F。概念 F 的 ID 为 6，所属图编号为 3，二者不能混用。图的排版不表示向量坐标或内存位置。

### 2.8 一次完整构建的顺序

```text
Build(G, labels, vectors, h, selected_materializations):
    build parents/children from concept edges
    compute unique Anc⁺ and Desc⁺ concept lists
    for object i:
        append i to P(c) for every direct label c of i
        b(i) ← minimum g_h(c) over its direct labels
    sort and deduplicate the direct postings
    create one HNSW for each nonempty object group
    for object i in global-ID order:
        addPoint(HNSW[b(i)], vector=x_i, external_label=i)
    for selected concept u:
        M(u) ← union of P(c) for unique c in Desc⁺(u)
    C(u) ← number of distinct live members in S(u), if counters are maintained
```

P 与 DAG 闭包共同定义过滤范围，M 是可选的派生状态，HNSW 负责距离近邻，b 负责把对象 ID 接到图实例。任何一项都不以访存布局作为优化机制。当前探针实现单直接标签；一般多标签的分组和成员维护属于方案定义，验证范围见 §8。

## 3. 查询算法与逐步样例

### 3.1 通用查询

```text
Search(q, U, predicate, k):
    scope ← empty object bitmap
    for u in U:
        if M(u) exists:
            scope ← scope OR M(u)
        else:
            for c in unique Desc⁺(u):
                add every ID in P(c) to scope
    eligible ← live AND scope AND predicate
    e ← popcount(eligible)
    if e = 0: return empty
    if e ≤ τ: return exact top-k over all eligible IDs
    count[b] ← 0 for every local graph
    for i in eligible:
        count[b(i)] += 1
    candidates ← empty
    for b with count[b] > 0:
        kb ← min(k, count[b])
        efb ← min(count[b], max(efSearch, kb))
        candidates += filtered HNSW(b, q, eligible, kb, efb)
    return top-k of candidates by (squared-L2, object ID)
```

合格集合决定“哪些对象可以返回”，对象到图映射决定“哪些局部图必须搜索”。当前定位仍枚举全部合格 ID，代价为 O(|F_Q|)。跳过不含合格对象的图有精确依据，但 HNSW 仍可能在所选图内经不合格点导航；是否减少总扩展和距离计算需要计数验证。

### 3.2 图 2：查询 B，为何要搜索 b_A

设 q=(1,1)、U={B}、k=2、τ=2、efSearch=20。以下均使用 squared-L2。

![图2：从B条件到跨分区局部近邻与全局归并，并展示小集合扫描分支](figures/dag-query-walkthrough-outlined.svg)

按图中编号读：

1. **范围解析。** B、C、E 的直接成员合并为 {o1,o3,o4,o5}；物化 M(B) 得到相同集合。该步骤仅处理 ID，不计算向量距离。
2. **计划分流。** 合格数量为 4，大于示例阈值 2，走分区图路径。其他属性为 true，因此 scope 与 eligible 相同；有额外属性时必须在这一步前完成其筛选。
3. **按图成员归属分发。** o1、o3 属于 b_A，o4、o5 属于 b_B，因此调用两张图；b_R、b_F 无合格对象，跳过。这里只减少无须执行的图查询，不涉及向量重排或访存方式。
4. **局部图检索。** b_A 返回 (o1,1)、(o3,2)，b_B 返回 (o4,5)、(o5,5)，括号内为对象和距离。b_A 中的 o0、o2 仍是图节点，但不能进入答案；callback 不保证它们不参与导航或距离计算。图中展示局部输出，不虚构 HNSW 的逐边访问顺序。
5. **全局归并。** 对局部候选按 (距离,对象 ID) 排序，得到 o1、o3。两个局部 top-2 不等于各取一个结果，最终答案可以全部来自同一分区。

每个分区只需返回至多 k 个候选：若局部结果精确，全局 top-k 对象在所在分区的局部名次不超过 k。实际 HNSW 可能漏近邻，该覆盖论证不构成一般 ANN Recall 保证。

### 3.3 同一索引的另两种查询

**小集合：U={D}。** 只有 P(D)={o2}，合格数 1≤τ；直接算 d²(q,x₂)=2，返回一个对象 o2，虽然 k=2 也不补入不合格对象。此路径不需要调用任何 HNSW。当前计时探针为了收集结构 fanout 仍统计合格分区，该诊断开销不属于扫描算法的必需步骤。

**交叠并集：U={A,B}。** A、B 各包含 o1、o3，最终并集是 {o0,o1,o2,o3,o4,o5}，不是八个成员。构造 scope 时按对象位或，o1、o3 各置位一次。精确单概念计数只给界

\[
\max_{u\in U}C(u)\le |S(U)|\le\min(N_{live},\sum_{u\in U}C(u)).
\]

本例上下界为 4 和 8，实际并集为 6。计数不能替代候选枚举，也不能在候选“够多”时忽略尚未处理的查询概念。

## 4. 标签更新算法与逐步样例

### 4.1 通用维护规则

直接标签由 L 改为 L′，旧、新继承集合为 A、A′。先计算去重后的成员变化：

\[
\Delta^- = A\setminus A',\qquad\Delta^+=A'\setminus A.
\]

```text
Relabel(i, Lnew):
    Aold ← union of unique Anc⁺(c) for c in Lold
    Anew ← union of unique Anc⁺(c) for c in Lnew
    remove/add i only in direct postings whose labels changed
    for u in Aold minus Anew:
        C(u) -= 1; clear bit i in M(u) if materialized
    for u in Anew minus Aold:
        C(u) += 1; set bit i in M(u) if materialized
    write new direct labels
    keep b(i), vector payload and HNSW adjacency unchanged
```

共有祖先 A∩A′ 保持不变。多条路径与多标签不能重复增减同一成员；例如删除一个直接标签，若另一标签仍支持祖先条件，该祖先成员必须保留。

### 4.2 图 3：o6 从 F 改标为 B，图成员归属保持不变

![图3：维护标签成员关系，保留局部图节点和邻接，后续查询多调用一张图](figures/dag-label-update-outlined.svg)

图 3 延续同一八对象实例，仅将 o6 的直接标签由 F 改为 B：

1. **继承差分。** {R,F}→{R,B}，因此只删除 F 的匹配、增加 B 的匹配，根 R 的基数仍为 8。
2. **直接成员。** 从 P(F) 删除 o6，向 P(B) 插入 o6。概念 DAG、Anc⁺、Desc⁺ 不变。
3. **派生状态。** C(F) 从 1 变为 0，C(B) 从 4 变为 5；已物化 M(B) 置位 o6，展示串 `01011100`→`01011110`。未物化的范围由更新后的直接 posting 在线求得。
4. **图结构。** o6 仍是 b_F 的节点，向量为 (4,4)，各图节点与邻接保持不变；更新不按新标签把它重新加入 b_B。S(F) 可以为空，而图 b_F 仍含 o6，组名只是初始分组键。
5. **后续查询。** B 的合格集合增加 o6，因此需调用 b_A、b_B、b_F 三张图。o6 的距离为 18，结果仍为 o1、o3。fanout 从 2 增至 3，说明保持图结构的更新策略可能增加查询工作。

图中的变化数只描述触及的成员状态，不能当作完整更新时间。排序 vector posting 插删可能搬移 O(|P(c)|) 个 ID。

### 4.3 更新成本与其他事件

单直接标签 c→c′ 需要触及的继承状态数为 O(|Anc⁺(c)∪Anc⁺(c′)|)。已排序闭包可线性归并差分；当前维护探针逐项二分检查对方闭包，还存在对数比较成本。多标签显式重算集合时，闭包枚举为 O(Σ_{c∈L∪L′}|Anc⁺(c)|)，另计去重。若要把多标签对象的单标签变更收紧到该标签祖先数，需要额外每对象祖先支持计数，当前探针不提供。

| 事件 | 触及的状态与限制 |
|---|---|
| 普通属性更新 | 写属性记录；若有独立属性索引，其维护成本另计 |
| 向量修改 | 仅所在分区的向量/图维护，不按元数据更新成本计 |
| 对象插入 | posting、继承成员、一个分区图；ID 容量及位图扩容成本另计 |
| 对象删除 | live/直接与派生成员、图删除标记；压实或图修复不是免费操作 |
| 概念显示名修改 | 稳定 ID 不变时只改名称 |
| 分类边增删 | 检查无环性、维护受影响闭包/基数/位图，保留其他路径的支持 |
| 重分组 / full repack | 重新决定局部图的成员并重建受影响图，代价单列；标签更新不依赖此操作 |

即使在线求概念闭包，分类边变化仍可能使持久基数与物化成员失效。并发快照、崩溃恢复、任意容量扩张未在探针中验证。样例输入、实际执行结果与复现命令见[样例核验](experiments/dag-worked-example.md)；该例验证集合与执行过程，不是性能实验。

## 5. 成本模型

令 $w$ 为在线展开实际访问的 posting ID 数，$d_c$ 为访问的概念数，$e=|F_Q|$，$f$ 为含合格对象的分区数，$C_b\le k$ 为每图返回数。忽略常数时：

\[
T_Q=O(W+d_c+w+T_\varphi+e+P)
+\sum_{b\in touched}T_{ANN}(b,Q)
+O\left((\sum_b C_b)\log(\sum_b C_b)\right).
\]

$P$ 是分区计数数组的初始化/遍历成本。物化可用每张 $W$ 个 word 的读取替代相应后代展开。小集合精确扫描的向量工作为 $O(e\cdot d_{vec})$，仍需承担范围解析成本。HNSW 未提供本设计可用的对数最坏时间或 Recall 保证。

以当前列表闭包、ID posting 与稠密物化位图计，持久空间包括

\[
O(D+|E|+\sum_c|Anc^+(c)|+\sum_c|Desc^+(c)|)
+4\sum_c|P(c)|+8D+8W|\mathcal M|+O(N)+M_{HNSW}.
\]

这些项不含容器常数与查询工作区。多图实现的锁表、入口及访问池开销须实测，不能仅按所有分区总对象数相同推断内存相同。

### 5.1 算法工作量的归因

比较时固定全部驻内存、距离核与质量口径，记录完整查询时间和下列操作量：

| 操作量 | 所回答的问题 |
|---|---|
| 访问的概念、posting ID 数 | 层级索引是否避免了重复的范围推导 |
| 实际启动的局部图数 | 是否安全跳过不含合格对象的图 |
| 扩展节点数、考察邻边数 | 图结构或搜索规则是否减少导航工作 |
| 向量距离计算数 | 相同实际 Recall 下是否少做几何计算 |
| 更新的 posting/计数/派生成员及图操作数 | 查询收益是否依赖不可接受的维护工作 |

八对象结构样例验证集合覆盖，单查询距离计数展示分组取舍，均不提供一般数据上的优势证明。NodeANN 与合并组变体共享“局部 ANN＋全局归并”的主干；范围预选、物化和扫描需与分组粒度分开对照。不能把对全局过滤图的耗时收益解释为优于同语义 NodeANN。
