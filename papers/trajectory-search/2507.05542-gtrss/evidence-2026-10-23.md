# Evidence — GTRSS

Version: arXiv:2507.05542v1. Checked: 2026-10-23 via local PDF and alphaXiv page extraction.

- PDF §III, Definitions 2–4: a subtrajectory is a continuous portion of a data trajectory. For each data trajectory, its representative subtrajectory is the segment most similar to the query trajectory. The query returns the top-k representatives across different data trajectories.
- This output semantics already enforces one best segment per trajectory before global top-k selection—the same trajectory-level deduplication shape used by the current episode problem.
- PDF §III–IV: evaluated similarity functions are DTW, EDR, and ERP over spatial trajectory points; timestamps are present in the point model but often omitted from notation.
- The query has no absolute time window, duration tolerance, POI/text semantic score, or semantic embedding sequence.
- Method: approximate dual-layer graph retrieval; R-tree/grid filtering assists index construction.
- PDF §I–II on TRSSQ: the problem "is named as TRSSQ, which is proposed by Wang et al [14]"; “representative subtrajectory refers to the subtrajectory most similar to the query T^q within each trajectory”; Wang et al. use RSSE (GRU point-level matching, trajectory encoding/aligning, local similarity) in a filter-validate paradigm, and are "the only approach directly targeting the TRSSQ problem".

Classification: the closest prior by **output semantics**. Episode localization and one-result-per-trajectory are not new; the remaining candidate delta is semantic scoring plus hard time/space/duration feasibility.
