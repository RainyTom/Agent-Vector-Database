# Evidence — TRSSQ (ICDE 2024)

Version: IEEE ICDE 2024, pp. 4396–4408, DOI 10.1109/ICDE60146.2024.00335. 13-page正式版 PDF（本地 `paper.pdf`，sha256 `99e38b36…`）。Checked: 2026-10-23.

- PDF §II-A, Definitions 1–4: trajectory `(t_i, lon_i, lat_i)`；subtrajectory 为连续片段；每条数据轨迹的 representative similar subtrajectory 是使 Θ 最大的片段；TRSSQ 在**不同数据轨迹之间**取 top-k，满足 `|R'| = k`。§I 明确：保留每轨一个代表片段是为了避免“只差一个点”的冗余结果。
- PDF §II-A 末：`For ease of representation, we usually omit the time dimension t_i`。时间戳只是点字段，**没有**绝对时间窗、持续时间或空间范围约束；没有 POI/text 语义或 embedding 序列。
- PDF §II-B: 评测四种度量 Θ — DTW、EDR、ERP、LCSS（LCSS 用其距离形式 Eq.5）。这与 GTRSS 只用 DTW/EDR/ERP 不同。
- PDF §III: RSSE = Bi-GRU 编码 + 点级 attention 匹配 + embedding interaction（加/减/BN）+ max/mean pooling + 3 层全连接；Siamese 训练，损失 `L_regression(MSE) + L_ranking`；层次化采样率 `r`。
- PDF §I / Fig.2: filter-validate 框架。RSSE 对全库轨迹打分，取 top-`M` 候选（`M > k`），再用 ExactS（或 PSS/RLS 启发式）在候选内求精确代表片段与 top-k。因此**端到端不保证精确**：候选集外的高分轨迹会被丢弃。
- PDF §IV-A: 三城真实数据 Xi'an 85,802 / Chengdu 221,781 / Porto 1,252,547 条轨迹；随机 30,000 条作数据、2,000 条作查询；查询长度 30–90，数据轨迹 90–300（强制 `m > n`）；网格 50m。
- PDF §IV-B Table II: RSSE 在三种数据集、四种度量上均优于 SRN、T3S、TMN（例：Porto DTW NDCG@50 0.7908 vs TMN 0.5372；Xi'an DTW 0.7568 vs 0.6258）。作者自述相对 TMN 平均 R10@50 约翻倍、NDCG@50 +0.23、HR50 +0.37。
- PDF §IV-C Fig.10–13: LBF（RSSE 过滤）在 ExactS 验证下 RR 多数最优；OSF 的查询时间平均比 LBF 多 11,602 s（Porto），Grid 过滤比 LBF 慢约两个数量级；LBF 随数据规模增长最慢。
- PDF §IV-B/Table III: 消融去掉点级匹配、interaction、排序损失+采样都会显著掉点。
- PDF §V: 直接前序为 SimSub 系列（ExactS 复杂度 $O(nm^2)$，PSS/RLS $O(nm)$）与路网 OSF；作者在 §I 声明“we are the first to propose this problem”。

Classification: **TRSSQ 是问题定义来源**，GTRSS 是其图索引后继。它已覆盖：连续子轨迹定位、每轨一个代表片段、全局 top-k、学习型相似度估计与候选过滤。未覆盖：语义（POI/text embedding）、绝对时间窗、持续时间、空间范围可行性。

Remaining delta for the current direction: semantic sequence distance + hard temporal/spatial feasibility, plus an execution path that beats `hard filter → RSSE + ExactS`.
